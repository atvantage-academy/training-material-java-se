    Räume mit Lambdas, Streams und Optional suchen

    User Story

    Als Entwickler:in der Raumbuchung möchte ich bestehende Suchen als Pipelines formulieren, damit im Code steht, was ich wissen will, und nicht, wie die Schleife läuft.

    Lernziele
    • Du baust Schleifen zu Stream-Pipelines um, ohne dass sich ihr Ergebnis ändert – die Tests bleiben grün.
    • Du schreibst Bedingungen als Lambdas und Abbildungen als Methodenreferenzen.
    • Du ersetzt eine Rückgabe, die null sein kann, durch Optional und rechnest im Test damit weiter.
    • Du verwendest assertAll und assertThrows aus JUnit und begründest, warum sie Lambdas brauchen.
    Definition of Done
    • RoomManager enthält keine Schleife und kein null mehr; findFreeRoom und findByNumber liefern ein Optional<Room>.
    • RoomManagerTest enthält keine Schleife, kein assertNull und kein get(); alle Tests sind grün.
    • secondBookingOfTheSameDayIsRejected erwartet die Exception mit assertThrows, ohne try-catch und fail, und prüft Raum und Tag mit assertAll – der Test ist grün.
    • Der Maven-Build läuft ohne Fehler durch.
    • Du hast die Kontrollfragen beantwortet

    Die Raumbuchung verwaltet ihre Räume in einem RoomManager. Er kann schon suchen: einen freien Raum für eine Anzahl Personen an einem Tag, alle an einem Tag gebuchten Räume und einen Raum nach seiner Nummer. Die Suchen funktionieren – geschrieben mit Schleifen und einem null für „nicht gefunden“. Du baust sie auf Lambdas, Streams und Optional um. Die Tests sind von Anfang an grün und müssen es nach jedem Schritt bleiben.

    Arbeitsschritte

    Lege das Paket an und kopiere den Code

    Im Ordner src/main/java und im Ordner src/test/java Deines Projekts java-aufbau lege je das Package aufbau.lambdas an. Die Räume sind der Room aus Den Raum mit JUnit testen im Package aufbau.junit – mit der RoomAlreadyBookedException aus Exceptions: früh scheitern, nicht spät. Du kopierst ihn nicht, sondern importierst ihn. Kopiere die folgende Klasse ins Package aufbau.lambdas unter src/main/java.

    RoomManager.java – die Suchen, die Du umbaust:

    package aufbau.lambdas;

import aufbau.junit.Room;
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;

public class RoomManager {

    private final List<Room> rooms;

    public RoomManager(List<Room> rooms) {
        this.rooms = List.copyOf(rooms);
    }

    // the first room that can host the persons and is not booked on the day, or null if there is none
    public Room findFreeRoom(LocalDate day, int persons) {
        for (Room room : rooms) {
            if (room.canHost(persons) && !room.isBooked(day)) {
                return room;
            }
        }
        return null;
    }

    // all rooms that are booked on the day
    public List<Room> findBookedRooms(LocalDate day) {
        List<Room> booked = new ArrayList<>();
        for (Room room : rooms) {
            if (room.isBooked(day)) {
                booked.add(room);
            }
        }
        return booked;
    }

    // the room with the number, or null if there is none
    public Room findByNumber(String number) {
        for (Room room : rooms) {
            if (room.getNumber().equals(number)) {
                return room;
            }
        }
        return null;
    }
}

    Kopiere den Test ins Package aufbau.lambdas unter src/test/java.

    RoomManagerTest.java:

    package aufbau.lambdas;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertNull;

import aufbau.junit.Room;
import aufbau.junit.RoomAlreadyBookedException;
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

class RoomManagerTest {

    static final LocalDate MONDAY = LocalDate.of(2026, 12, 7);
    static final LocalDate TUESDAY = LocalDate.of(2026, 12, 8);

    RoomManager manager;

    @BeforeEach
    void setUp() throws RoomAlreadyBookedException {
        Room berlin = new Room("R101", "Berlin", 6);
        Room hamburg = new Room("R102", "Hamburg", 10);
        Room munich = new Room("R103", "Munich", 16);
        Room cologne = new Room("R201", "Cologne", 12);
        Room dresden = new Room("R202", "Dresden", 4);
        Room leipzig = new Room("R203", "Leipzig", 2);
        Room bremen = new Room("R301", "Bremen", 24);
        Room kiel = new Room("R302", "Kiel", 8);
        hamburg.book(MONDAY);
        munich.book(MONDAY);
        dresden.book(MONDAY);
        berlin.book(TUESDAY);
        manager = new RoomManager(
                List.of(berlin, hamburg, munich, cologne, dresden, leipzig, bremen, kiel)
        );
    }

    @Test
    void findsTheFirstFreeRoomThatIsLargeEnough() {
        assertEquals("Cologne", manager.findFreeRoom(MONDAY, 10).getName());
    }

    @Test
    void findsNoFreeRoomForTooManyPersons() {
        assertNull(manager.findFreeRoom(MONDAY, 30));
    }

    @Test
    void findsTheBookedRoomsOfADay() {
        List<String> names = new ArrayList<>();
        for (Room room : manager.findBookedRooms(MONDAY)) {
            names.add(room.getName());
        }

        assertEquals(List.of("Hamburg", "Munich", "Dresden"), names);
    }

    @Test
    void findsTheRoomByItsNumber() {
        assertEquals("Cologne", manager.findByNumber("R201").getName());
    }

    @Test
    void findsNoRoomForAnUnknownNumber() {
        assertNull(manager.findByNumber("R999"));
    }
}

    Starte die Tests in der IDE: Alle fünf sind grün.

    Bau die Schleifen zu Pipelines um

    Bau findBookedRooms zu einer Stream-Pipeline um: Räume filtern und den Stream zurückgeben – der Rückgabetyp wird Stream<Room>. Das Bild dazu – ein Fließband mit Maschinen und einem Eimer am Ende – zeigt die Visualisierung Lambdas, Streams und Optional.

    Bau danach im Test findsTheBookedRoomsOfADay die Schleife ebenso um: Die Räume werden auf ihre Namen abgebildet.

    Hinweis: Eine Bedingung schreibst Du als Lambda, room -> room.isBooked(day); ein Lambda, das nur eine Methode aufruft, als Methodenreferenz, Room::getName. Die Liste liefert toList() am Ende der Pipeline.

    Lösung: findBookedRooms

    Der Import java.util.ArrayList entfällt, dazu kommt java.util.stream.Stream.

    public Stream<Room> findBookedRooms(LocalDate day) {
    return rooms
            .stream()
            .filter(room -> room.isBooked(day));
}
    Lösung: Test

    Auch im Test entfällt der Import java.util.ArrayList.

    @Test
void findsTheBookedRoomsOfADay() {
    List<String> names = manager
            .findBookedRooms(MONDAY)
            .map(Room::getName)
            .toList();

    assertEquals(List.of("Hamburg", "Munich", "Dresden"), names);
}

    Ersetz null durch Optional

    findFreeRoom und findByNumber liefern null, wenn es keinen passenden Raum gibt.

    1. Ändere bei beiden den Rückgabetyp auf Optional<Room> und bau sie zu Pipelines um.
    2. Der Compiler meldet jetzt die Tests, die mit null gerechnet haben. Pass sie an: statt getName() und assertNull jetzt map, orElse und isEmpty – ohne isPresent und get.

    Hinweis: Den ersten Treffer einer Pipeline liefert findFirst() – schon als Optional. Optional ist ein Rückgabetyp: Als Feld oder Parameter macht es den Code nicht sicherer, nur länger.

    Lösung: findFreeRoom und findByNumber

    Dazu der Import java.util.Optional.

    public Optional<Room> findFreeRoom(LocalDate day, int persons) {
    return rooms
            .stream()
            .filter(room -> room.canHost(persons))
            .filter(room -> !room.isBooked(day))
            .findFirst();
}

public Optional<Room> findByNumber(String number) {
    return rooms
            .stream()
            .filter(room -> room.getNumber().equals(number))
            .findFirst();
}
    Lösung: Tests

    Statt Assertions.assertNull jetzt statisch Assertions.assertTrue importieren.

    @Test
void findsTheFirstFreeRoomThatIsLargeEnough() {
    assertEquals(
            "Cologne",
            manager
                    .findFreeRoom(MONDAY, 10)
                    .map(Room::getName)
                    .orElse("none")
    );
}

@Test
void findsNoFreeRoomForTooManyPersons() {
    assertTrue(
            manager
                    .findFreeRoom(MONDAY, 30)
                    .isEmpty()
    );
}

@Test
void findsTheRoomByItsNumber() {
    assertEquals(
            "Cologne",
            manager
                    .findByNumber("R201")
                    .map(Room::getName)
                    .orElse("none")
    );
}

@Test
void findsNoRoomForAnUnknownNumber() {
    assertTrue(
            manager
                    .findByNumber("R999")
                    .isEmpty()
    );
}

    Teste mit Lambdas: assertAll und assertThrows

    JUnit nimmt an zwei Stellen Lambdas entgegen: Assertions.assertAll und Assertions.assertThrows. Sieh Dir beide Methoden in der Javadoc oder im JUnit User Guide an und bau damit den Test secondBookingOfTheSameDayIsRejected in RoomTest (Package aufbau.junit) um:

    • Er erwartet die RoomAlreadyBookedException der zweiten Buchung mit assertThrows – ohne try-catch und fail.
    • Er prüft weiter, dass sie diesen Raum und diesen Tag nennt – mit assertAll, sodass beide Prüfungen laufen, auch wenn die erste scheitert.

    Hinweis: assertThrows liefert die gefangene Exception zurück; an ihr prüfst Du Raum und Tag wie bisher im catch-Block.

    Lösung: secondBookingOfTheSameDayIsRejected

    Statt Assertions.fail jetzt statisch Assertions.assertThrows und Assertions.assertAll importieren. Die erste Buchung steht weiter außerhalb des Lambdas – deshalb bleibt das throws am Test.

    @Test
void secondBookingOfTheSameDayIsRejected() throws RoomAlreadyBookedException {
    room.book(MONDAY);

    RoomAlreadyBookedException exception = assertThrows(
            RoomAlreadyBookedException.class,
            () -> room.book(MONDAY)
    );

    assertAll(
            () -> assertSame(room, exception.getRoom()),
            () -> assertEquals(MONDAY, exception.getDay())
    );
}

    Starte den Test danach in der IDE; er muss grün bleiben. Ändere zur Probe beide Erwartungen im assertAll – wie viele Fehlschläge meldet JUnit? Nimm die Änderung danach zurück.

    Für Schnelle

    • Ergänze im RoomManager eine Methode, die den kleinsten freien Raum für eine Anzahl Personen an einem Tag liefert, und einen Test dazu. Welche Endoperation ersetzt findFirst?
    • Schreib eine Methode, die die Namen aller an einem Tag gebuchten Räume als "Hamburg, Munich, Dresden" liefert – mit welchem Collector?
    Lösung: der kleinste freie Raum

    min mit einem Comparator ersetzt findFirst; im RoomManager dazu der Import java.util.Comparator. Für 2 Personen findet findFirst Berlin, min Leipzig.

    public Optional<Room> findSmallestFreeRoom(LocalDate day, int persons) {
    return rooms
            .stream()
            .filter(room -> room.canHost(persons))
            .filter(room -> !room.isBooked(day))
            .min(Comparator.comparingInt(Room::getCapacity));
}

@Test
void findsTheSmallestFreeRoomThatIsLargeEnough() {
    assertEquals(
            "Leipzig",
            manager
                    .findSmallestFreeRoom(MONDAY, 2)
                    .map(Room::getName)
                    .orElse("none")
    );
}
    Lösung: die Namen der gebuchten Räume

    Collectors.joining mit Trennzeichen; dazu der Import java.util.stream.Collectors.

    public String findBookedRoomNames(LocalDate day) {
    return findBookedRooms(day)
            .map(Room::getName)
            .collect(Collectors.joining(", "));
}

@Test
void joinsTheNamesOfTheBookedRooms() {
    assertEquals(
            "Hamburg, Munich, Dresden",
            manager.findBookedRoomNames(MONDAY)
    );
}
