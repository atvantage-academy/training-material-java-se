    Parameterized Tests: einen Raum mit vielen Fällen prüfen

    User Story

    Als Java-Entwickler:in möchte ich viele Fälle mit einem Test abdecken, ohne ihn zu kopieren, damit Testdaten und Prüfung getrennt bleiben und ein gescheiterter Fall sofort erkennbar ist.

    Lernziele
    • Du schreibst parametrisierte Tests mit @ValueSource und @CsvSource.
    • Du gibst den Durchläufen eines parametrisierten Tests mit name lesbare Namen.
    • Du lieferst Argumente aus einer Methode (@MethodSource) und aus einer Datei (@CsvFileSource).
    • Du schreibst mehrzeilige Testfälle als Text-Block in @CsvSource.
    Definition of Done
    • RoomParameterizedTest enthält die Tests canHost, rejectsCapacityBelowOne, hostsExactlyItsCapacity und canHostFromFile, und alle Durchläufe sind grün.
    • Die Durchläufe von canHost tragen in der IDE Namen wie 13 persons in a room for 12: false.
    • src/test/resources/rooms.csv liegt im Projekt, und canHostFromFile liest sie.
    • Du hast die Kontrollfragen beantwortet

    Bisher hat jeder Test genau einen Fall geprüft. Ein parametrisierter Test läuft für viele Eingaben: Werte aus @ValueSource, Zeilen aus @CsvSource, Räume aus einer Methode und Testfälle aus einer Datei – jeder Durchlauf mit einem lesbaren Namen. Du arbeitest im Package aufbau.junit mit dem Room aus JUnit.

    Arbeitsschritte

    Leg die Testklasse an

    Leg im Package aufbau.junit unter src/test/java die Datei RoomParameterizedTest.java an. Die Fälle stehen als Text-Block – eine Zeile je Durchlauf:

    package aufbau.junit;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;

class RoomParameterizedTest {

    @ParameterizedTest
    @CsvSource(textBlock = """
            0,  false
            1,  true
            12, true
            13, false
            """)
    void canHost(int persons, boolean expected) {
        assertEquals(expected, new Room("R101", "Seminar 1", 12).canHost(persons));
    }
}

    Starte den Test in Deiner IDE und sieh Dir an, wie die vier Durchläufe heißen.

    Prüf mehrere Werte mit einem Test

    Ein Raum mit Kapazität 0 oder -1 lässt sich nicht anlegen. Statt zwei fast gleicher Tests schreibst Du einen parametrisierten Test rejectsCapacityBelowOne(int capacity): @ParameterizedTest statt @Test, die Werte kommen aus @ValueSource.

    Lösung

    Dazu die Importe org.junit.jupiter.params.provider.ValueSource und statisch Assertions.assertThrows.

    @ParameterizedTest
@ValueSource(ints = { 0, -1 })
void rejectsCapacityBelowOne(int capacity) {
    assertThrows(IllegalArgumentException.class, () -> new Room("R101", "Seminar 1", capacity));
}

    Gib den Durchläufen Namen

    Gib dem Test über das Attribut name von @ParameterizedTest Namen wie 13 persons in a room for 12: false. Die Platzhalter {0}, {1} … stehen für die Argumente. Starte den Test noch einmal in der IDE.

    Lösung 
    @ParameterizedTest(name = "{0} persons in a room for 12: {1}")

    Liefere Räume aus einer Methode

    Jeder Raum soll genau so viele Personen aufnehmen, wie er Plätze hat – und keine mehr. Prüf das für ein Büro mit 1 Platz, das Seminar mit 12 und einen Saal mit 200 Plätzen in einem Test hostsExactlyItsCapacity(Room room). Die drei Räume liefert eine statische Methode, die einen Stream<Room> zurückgibt; der Test nennt sie mit @MethodSource.

    Lösung

    Dazu die Importe java.util.stream.Stream, org.junit.jupiter.params.provider.MethodSource und statisch assertTrue, assertFalse.

    static Stream<Room> roomsOfDifferentSize() {
    return Stream.of(new Room("R001", "Office", 1), new Room("R101", "Seminar 1", 12), new Room("R301", "Hall", 200));
}

@ParameterizedTest
@MethodSource("roomsOfDifferentSize")
void hostsExactlyItsCapacity(Room room) {
    assertTrue(room.canHost(room.getCapacity()));
    assertFalse(room.canHost(room.getCapacity() + 1));
}

    Wie heißen die Durchläufe jetzt? Gib dem Test einen Namen, der den Raum nennt.

    Lies die Fälle aus einer Datei

    Leg den Ordner src/test/resources an und darin rooms.csv:

    number,name,capacity,persons,expected
R001,Office,1,1,true
R001,Office,1,2,false
R101,Seminar 1,12,12,true
R301,Hall,200,150,true

    Schreib einen Test canHostFromFile(String number, String name, int capacity, int persons, boolean expected), der die Datei mit @CsvFileSource liest. Die erste Zeile ist eine Überschrift und muss übersprungen werden. Ergänze danach eine Zeile in der Datei und starte den Test noch einmal.

    Lösung

    Dazu der Import org.junit.jupiter.params.provider.CsvFileSource.

    @ParameterizedTest(name = "{1} ({2} seats) for {3} persons: {4}")
@CsvFileSource(resources = "/rooms.csv", numLinesToSkip = 1)
void canHostFromFile(String number, String name, int capacity, int persons, boolean expected) {
    assertEquals(expected, new Room(number, name, capacity).canHost(persons));
}

    Für Schnelle: Text in einen Raum umwandeln

    Schreib einen Test, der Räume als Text bekommt, etwa @ValueSource(strings = { "R101:Seminar 1:12", "R001:Office:1" }), und als Parameter einen Room erwartet. Die Umwandlung übernimmt eine eigene Klasse, die von SimpleArgumentConverter erbt; am Parameter steht @ConvertWith(…). Was meldet JUnit, wenn ein Text keinen Doppelpunkt enthält?

    Reflexionsfragen

    • Was gewinnst Du mit einem Namen wie 13 persons in a room for 12: false gegenüber [4]?
    • Wann nimmst Du @CsvSource, wann @MethodSource, wann @CsvFileSource?
    • Warum steht rooms.csv unter src/test/resources und nicht unter src/test/java?
