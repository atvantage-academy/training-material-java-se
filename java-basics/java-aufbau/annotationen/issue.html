    Eigene Annotation: @Logged schreiben und per Reflection auslesen

    User Story

    Als Entwickler:in der Raumbuchung möchte ich Methoden mit einer eigenen Annotation markieren und die Markierung zur Laufzeit auslesen, damit ich verstehe, wie Frameworks mit @Test, @Transactional & Co. arbeiten.

    Lernziele
    • Du schreibst eine Annotation mit value, einem weiteren Attribut und einem Default-Wert.
    • Du legst mit @Retention und @Target fest, wo die Annotation stehen darf und ob sie zur Laufzeit erhalten bleibt.
    • Du verwendest die Kurzschreibweise für value und die Schreibweise mit Attributnamen.
    • Du liest Annotationen mit getAnnotation aus und rufst ihre Attribute ab.
    Definition of Done
    • @Logged hat die Attribute value und withArguments (Default false), bleibt zur Laufzeit erhalten und ist nur an Methoden erlaubt.
    • add und find in RoomCatalog tragen @Logged, size nicht.
    • LoggedMethodsTest trägt kein @Disabled mehr und ist grün; die Vorhersage zur Implementierung hast Du notiert, geprüft und die Assertion korrigiert.
    • Du hast die Kontrollfragen beantwortet

    Der Raumkatalog soll später protokollieren, wer welche Methode aufruft – aber nicht jede: Welche Methoden ins Protokoll gehören und mit welcher Beschreibung, soll an der Methode selbst stehen. Dafür schreibst Du eine eigene Annotation und liest sie per Reflection aus. Wie eine Annotation aufgebaut ist, zeigt die Visualisierung Eigene Annotationen.

    Arbeitsschritte

    Lege das Paket an und kopiere den Code

    Im Ordner src/main/java und im Ordner src/test/java Deines Projekts java-aufbau lege je das Package aufbau.annotations an. Kopiere die folgenden Typen ins Package unter src/main/java.

    Room.java:

    package aufbau.annotations;

public record Room(String id, String name, int seats) {
}

    RoomCatalog.java:

    package aufbau.annotations;

import java.util.Optional;

public interface RoomCatalog {

    void add(Room room);

    Optional<Room> find(String id);

    int size();
}

    InMemoryRoomCatalog.java:

    package aufbau.annotations;

import java.util.HashMap;
import java.util.Map;
import java.util.Optional;

public class InMemoryRoomCatalog implements RoomCatalog {

    private final Map<String, Room> rooms = new HashMap<>();

    @Override
    public void add(Room room) {
        if (rooms.putIfAbsent(room.id(), room) != null) {
            throw new IllegalStateException(room.id() + " already exists");
        }
    }

    @Override
    public Optional<Room> find(String id) {
        return Optional.ofNullable(rooms.get(id));
    }

    @Override
    public int size() {
        return rooms.size();
    }
}

    LoggedMethods.java:

    package aufbau.annotations;

import java.util.List;

public final class LoggedMethods {

    // "name: description" of every public method marked with @Logged, sorted alphabetically;
    // " (with arguments)" is appended if the arguments are logged as well
    public static List<String> describe(Class<?> type) {
        throw new UnsupportedOperationException("TODO");
    }

    private LoggedMethods() {
    }
}

    Kopiere den Test ins Package aufbau.annotations unter src/test/java.

    LoggedMethodsTest.java:

    package aufbau.annotations;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.List;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class LoggedMethodsTest {

    @Test
    @Disabled("Remove @Disabled once you have implemented describe")
    void describesTheLoggedMethodsOfTheCatalog() {
        assertEquals(List.of("add: add a room", "find: look up a room (with arguments)"),
                LoggedMethods.describe(RoomCatalog.class));
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void describesTheLoggedMethodsOfTheImplementation() {
        assertEquals(List.of("add: add a room", "find: look up a room (with arguments)"),
                LoggedMethods.describe(InMemoryRoomCatalog.class));
    }
}

    Schreib die Annotation @Logged

    Schreib im Package aufbau.annotations unter src/main/java die Annotation Logged mit zwei Attributen:

    • value – eine Beschreibung des Aufrufs als String, ohne Default-Wert,
    • withArguments – ob auch die Argumente ins Protokoll gehören, als boolean mit dem Default-Wert false.

    Die Annotation soll nur an Methoden stehen dürfen und zur Laufzeit erhalten bleiben.

    Markiere die Methoden des Katalogs

    Setz @Logged in RoomCatalog:

    • an add mit der Beschreibung add a room – in der Kurzschreibweise, ohne Attributnamen,
    • an find mit der Beschreibung look up a room und mit Argumenten.

    size bleibt ohne Annotation. Probier aus, was der Compiler sagt, wenn Du @Logged ohne Beschreibung oder an ein Feld schreibst.

    Lies die Annotation per Reflection aus

    Implementier LoggedMethods.describe, entferne am ersten Test @Disabled und mach ihn grün.

    Hinweis: Alle öffentlichen Methoden eines Typs liefert getMethods(). An einer Method gibt getAnnotation(Logged.class) die Annotation zurück – oder null. Ihre Attribute rufst Du wie Methoden auf: logged.value().

    Sag die Implementierung vorher

    Der zweite Test fragt dasselbe an InMemoryRoomCatalog statt am Interface.

    1. Notier Deine Erwartung: Findet describe dort dieselben Methoden?
    2. Entferne @Disabled und starte den Test.
    3. Erklär das Ergebnis.
    4. Korrigier die Assertion auf das tatsächliche Verhalten, bis der Test grün ist.

    Nimm danach testweise @Retention aus Logged heraus, starte die Tests und setz die Zeile wieder ein.

    Für Schnelle

    Schreib einen Mini-Testrunner: eine Annotation @MyTest für Methoden und eine Klasse mit main, die alle @MyTest-Methoden einer Klasse aufruft und je Methode passed oder failed ausgibt. Was muss der Runner tun, um die Klasse zu instanziieren?

    Reflexionsfragen

    • Was passiert, wenn Du an @Logged die Zeile @Retention(RetentionPolicy.RUNTIME) weglässt – und warum?
    • Warum findet describe an InMemoryRoomCatalog keine markierte Methode, obwohl die Klasse RoomCatalog umsetzt?
    • Warum darfst Du bei @Logged("add a room") den Namen value weglassen, bei find aber nicht?
