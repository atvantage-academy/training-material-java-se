    Eigene Annotation: die protokollierten Methoden eines Raums markieren

    User Story

    Als Entwickler:in der Raumbuchung möchte ich Methoden mit einer eigenen Annotation markieren und die Markierung zur Laufzeit auslesen, damit ich verstehe, wie Frameworks mit @Test, @Transactional & Co. arbeiten.

    Lernziele
    • Du schreibst eine Annotation ohne Attribute, eine reine Markierung.
    • Du legst mit @Retention und @Target fest, wo die Annotation stehen darf und ob sie zur Laufzeit erhalten bleibt.
    • Du prüfst per Reflection, welche Methoden eines Objekts die Annotation tragen.
    Definition of Done
    • @Logged bleibt zur Laufzeit erhalten und ist nur an Methoden erlaubt.
    • book und cancel in MeetingRoom tragen @Logged, name und isFree nicht.
    • LoggedMethods.print gibt für einen MeetingRoom genau book und cancel aus.
    • Du hast die Kontrollfragen beantwortet

    Logging heißt: Ein Programm schreibt mit, was es tut – wann welche Methode aufgerufen wurde, wie lange sie lief, ob sie scheiterte. Ein Raum der Raumbuchung soll das später für ausgewählte Methoden tun. Welche das sind, soll an der Methode selbst stehen: als eigene Annotation @Logged, „wird protokolliert“. In dieser Übung schreibst Du die Annotation und liest sie per Reflection aus; protokolliert wird in der nächsten Übung. Wie eine Annotation aufgebaut ist, zeigt die Visualisierung Eigene Annotationen.

    Arbeitsschritte

    Lege das Paket an und kopiere den Code

    Lege im Ordner src/main/java Deines Projekts java-aufbau das Package aufbau.annotations an und kopiere die folgenden Typen hinein.

    Room.java:

    package aufbau.annotations;

public interface Room {

    String name();

    boolean isFree();

    void book(String person);

    void cancel();
}

    MeetingRoom.java:

    package aufbau.annotations;

public class MeetingRoom implements Room {

    private final String name;
    private String bookedBy;

    public MeetingRoom(String name) {
        this.name = name;
    }

    @Override
    public String name() {
        return name;
    }

    @Override
    public boolean isFree() {
        return bookedBy == null;
    }

    @Override
    public void book(String person) {
        if (bookedBy != null) {
            throw new IllegalStateException(name + " is already booked by " + bookedBy);
        }
        bookedBy = person;
    }

    @Override
    public void cancel() {
        bookedBy = null;
    }
}

    Schreib die Annotation @Logged

    Schreib im Package aufbau.annotations die Annotation Logged – ohne Attribute, als reine Markierung. Sie soll nur an Methoden stehen dürfen und zur Laufzeit erhalten bleiben.

    Markiere die Methoden des Raums

    Setz @Logged in MeetingRoom an book und cancel. name und isFree bleiben ohne Annotation. Probier aus, was der Compiler sagt, wenn Du @Logged an das Feld name schreibst.

    Gib die markierten Methoden aus

    Schreib eine Klasse LoggedMethods mit einer Hilfsmethode public static void print(Object room), die die Namen aller öffentlichen Methoden von room ausgibt, die @Logged tragen. Ruf sie in einer main-Methode mit einem MeetingRoom auf.

    Hinweis: Die Klasse eines Objekts liefert getClass(), ihre öffentlichen Methoden getMethods(). Ob eine Method die Annotation trägt, sagt isAnnotationPresent(Logged.class).

    Die Ausgabe enthält book und cancel, in beliebiger Reihenfolge:

    book
cancel

    Nimm danach testweise @Retention aus Logged heraus, starte main noch einmal und setz die Zeile wieder ein.

    Für Schnelle

    Verschieb @Logged von book in MeetingRoom an book im Interface Room. Was gibt print jetzt aus – und warum? Setz die Annotation danach wieder an MeetingRoom; die nächste Übung sucht sie dort.

    Reflexionsfragen

    • Was passiert, wenn Du an @Logged die Zeile @Retention(RetentionPolicy.RUNTIME) weglässt – und warum?
    • @Logged an einer Methode ändert nichts daran, was die Methode tut. Wer gibt der Annotation ihre Bedeutung?
