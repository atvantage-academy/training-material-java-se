    Die Oberklasse Object: Ist ein Whiteboard ein Beamer?

    User Story

    Als Java-Entwickler:in möchte ich wissen, was meine Klassen von Object erben und wann ich es überschreiben muss, damit sich meine Objekte in Ausgaben, Vergleichen und Collections so verhalten, wie ich es erwarte.

    Lernziele
    • Du überschreibst toString in einer Oberklasse so, dass es für alle Unterklassen passt.
    • Du erkennst ein equals, das die Symmetrie bricht, und korrigierst es.
    • Du ergänzt ein hashCode, das zu equals passt, und begründest den Zusammenhang.
    Definition of Done
    • Das Package aufbau.object enthält RoomInventory, Projector und Whiteboard und die drei Testklassen dieser Übung, keine trägt mehr @Disabled.
    • toString, equals und hashCode stehen nur in RoomInventory; Projector und Whiteboard hast Du dafür nicht geändert.
    • Alle Tests sind grün, ohne dass Du eine Assertion geändert hast, und der Maven-Build läuft durch.
    • Du hast die Kontrollfragen beantwortet

    Zum Inventar eines Raums gehören Beamer und Whiteboards, jedes Stück mit einer Inventarnummer. Die Klassen dafür gibt es schon – und sie erben, ohne dass es dasteht, von Object. Die folgenden Tests zeigen, was dabei herauskommt. Jeder kompiliert, ist aber mit @Disabled abgeschaltet.

    Hinweis: Ein Test bricht an der ersten Assertion ab, die nicht stimmt – die Assertions danach laufen gar nicht erst. Deshalb prüfen die Tests hier je nur eine Sache.

    Arbeitsschritte

    Leg das Package an und übernimm das Inventar

    Im Ordner src/main/java lege das Package aufbau.object an und kopiere die drei Klassen hinein.

    RoomInventory.java:

    package aufbau.object;

public abstract class RoomInventory {

    private final String inventoryNumber;

    protected RoomInventory(String inventoryNumber) {
        this.inventoryNumber = inventoryNumber;
    }

    public String getInventoryNumber() {
        return inventoryNumber;
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof RoomInventory other
                && inventoryNumber.equals(other.inventoryNumber);
    }
}

    Projector.java:

    package aufbau.object;

public class Projector extends RoomInventory {

    private final int lumens;
    private boolean lampOn;

    public Projector(String inventoryNumber, int lumens) {
        super(inventoryNumber);
        this.lumens = lumens;
    }

    public int getLumens() {
        return lumens;
    }

    public void switchOn() {
        lampOn = true;
    }

    public void switchOff() {
        lampOn = false;
    }

    public boolean isLampOn() {
        return lampOn;
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof Projector other
                && super.equals(other)
                && lumens == other.lumens;
    }
}

    Whiteboard.java:

    package aufbau.object;

public class Whiteboard extends RoomInventory {

    private final int widthInCm;

    public Whiteboard(String inventoryNumber, int widthInCm) {
        super(inventoryNumber);
        this.widthInCm = widthInCm;
    }

    public int getWidthInCm() {
        return widthInCm;
    }
}

    Lege das Package aufbau.object auch unter src/test/java an – dorthin gehören die Tests.

    Lass das Inventar sich vorstellen

    Speichere den Test als InventoryToStringTest.java:

    package aufbau.object;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class InventoryToStringTest {

    @Test
    void projectorNamesItself() {
        Projector projector = new Projector("INV-17", 3000);
        assertEquals("Projector INV-17", projector.toString());
    }

    @Test
    void whiteboardNamesItself() {
        Whiteboard whiteboard = new Whiteboard("INV-42", 180);
        assertEquals("Whiteboard INV-42", whiteboard.toString());
    }
}

    Was liefert toString(), solange es niemand überschreibt? Notier Deine Erwartung, entferne @Disabled und starte den Test in der IDE.

    Überschreibe toString danach einmal, in RoomInventory, sodass beide Tests grün werden. Projector und Whiteboard fasst Du dafür nicht an.

    Lösung

    getClass() liefert die Klasse, mit der das Objekt erzeugt wurde – also die Unterklasse.

    @Override
public String toString() {
    return getClass().getSimpleName() + " " + inventoryNumber;
}

    Prüfe, ob ein Whiteboard ein Beamer ist

    Speichere den Test als InventoryEqualsTest.java:

    package aufbau.object;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class InventoryEqualsTest {

    private final RoomInventory whiteboard = new Whiteboard("INV-17", 180);
    private final RoomInventory projector = new Projector("INV-17", 3000);

    @Test
    void whiteboardIsNoProjector() {
        assertEquals(false, whiteboard.equals(projector));
    }

    @Test
    void projectorIsNoWhiteboard() {
        assertEquals(false, projector.equals(whiteboard));
    }

    @Test
    void sameProjectorIsEqual() {
        assertEquals(true, projector.equals(new Projector("INV-17", 3000)));
    }
}

    Beide Stücke tragen dieselbe Inventarnummer. Was liefert equals in jedem der drei Tests? Notier Deine Erwartung, entferne @Disabled und starte den Test in der IDE.

    Korrigiere danach equals in RoomInventory so, dass alle drei Tests grün werden. Projector bleibt, wie er ist.

    Lösung

    getClass() statt instanceof: Gleich sein können nur Objekte derselben Klasse.

    @Override
public boolean equals(Object o) {
    if (o == null || getClass() != o.getClass()) {
        return false;
    }
    RoomInventory other = (RoomInventory) o;
    return inventoryNumber.equals(other.inventoryNumber);
}

    Finde den Beamer im Set wieder

    Speichere den Test als InventorySetTest.java:

    package aufbau.object;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;

import java.util.HashSet;
import java.util.Set;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class InventorySetTest {

    @Test
    void sameProjectorIsStoredOnce() {
        Set<RoomInventory> inventory = new HashSet<>();
        inventory.add(new Projector("INV-17", 3000));
        inventory.add(new Projector("INV-17", 3000));

        assertEquals(1, inventory.size());
    }

    @Test
    void setFindsAnEqualProjector() {
        Set<RoomInventory> inventory = new HashSet<>();
        inventory.add(new Projector("INV-17", 3000));

        assertTrue(inventory.contains(new Projector("INV-17", 3000)));
    }
}

    Die beiden Beamer sind nach equals jetzt gleich. Wie viele liegen im Set, und findet es den zweiten? Notier Deine Erwartung, entferne @Disabled und starte den Test in der IDE.

    Ergänze danach in RoomInventory ein hashCode, das zu equals passt. Was „passt“ heißt, zeigt die Visualisierung Die Oberklasse Object. Baue zum Schluss erneut mit Maven.

    Lösung

    Dasselbe Feld wie in equals – gleiche Stücke haben dann denselben Hashwert. Objects.hash(inventoryNumber) geht ebenso.

    @Override
public int hashCode() {
    return inventoryNumber.hashCode();
}

    Für Schnelle: Schalte die Lampe zuverlässig aus

    Nach der Präsentation soll die Lampe des Beamers aus sein, auch wenn zwischendurch etwas schiefgeht. finalize() aus Object wäre dafür der falsche Ort: Der Garbage Collector ruft es auf, wann er will – oder nie.

    Lass Projector stattdessen AutoCloseable implementieren; close() schaltet die Lampe aus. Speichere danach den Test als ProjectorLampTest.java – er kompiliert erst, wenn Projector ein AutoCloseable ist:

    package aufbau.object;

import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertTrue;

import org.junit.jupiter.api.Test;

class ProjectorLampTest {

    @Test
    void lampIsOffAfterThePresentation() {
        Projector projector = new Projector("INV-17", 3000);
        try (projector) {
            projector.switchOn();
            assertTrue(projector.isLampOn());
        }
        assertFalse(projector.isLampOn());
    }
}
    Lösung

    Ohne throws an close() braucht auch der Test kein throws.

    public class Projector extends RoomInventory implements AutoCloseable {

    // … wie bisher …

    @Override
    public void close() {
        switchOff();
    }
}

    Reflexionsfragen

    • Was gibt toString() aus, solange es niemand überschreibt – und woher kennt toString in RoomInventory den Namen der Unterklasse?
    • Object ist nicht abstrakt – new Object() ist erlaubt. Wofür könnte man ein Objekt brauchen, das nichts kann als Object?
    • Warum hielt sich das Whiteboard für gleich mit dem Beamer, der Beamer aber nicht für gleich mit dem Whiteboard?
    • Warum fand das HashSet den zweiten Beamer nicht, obwohl equals schon stimmte?
