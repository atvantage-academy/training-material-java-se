    Effective Java: fünf Rätsel als Tests

    User Story

    Als Java-Entwickler:in möchte ich Code, der harmlos aussieht, an seinem tatsächlichen Verhalten messen, damit ich dieselben Fallen im eigenen Projekt erkenne.

    Lernziele
    • Du notierst eine Vorhersage, bevor Du einen Test mit @Disabled freischaltest.
    • Du erklärst eine Abweichung zwischen Vorhersage und Ergebnis mit den Regeln der Sprache.
    • Du korrigierst eine Assertion so, dass sie das tatsächliche Verhalten beschreibt.
    • Du schätzt einen Laufzeitunterschied vorher ab und vergleichst ihn mit der Messung.
    Definition of Done
    • Im Package aufbau.puzzlers unter src/test/java liegen die Testklassen der Rätsel, die Du bearbeitet hast – mindestens drei.
    • Zu jedem bearbeiteten Rätsel hast Du Deine Vorhersage notiert, bevor Du @Disabled entfernt hast.
    • Jede Assertion beschreibt das tatsächliche Verhalten, und der Maven-Build endet mit BUILD SUCCESS.
    • Zu jedem Rätsel hast Du eine Erklärung notiert – oder eine Frage für die Nachbesprechung.
    • Du hast die Kontrollfragen beantwortet

    Jedes Rätsel ist ein Test mit @Disabled und der naheliegenden Erwartung als Assertion. Die Reihenfolge der Rätsel ist frei; nimm Dir mindestens drei vor.

    Im Ordner src/test/java Deines Projekts java-aufbau lege das Package aufbau.puzzlers an; alle Testklassen kommen dort hinein. Einen einzelnen Test startest Du in der IDE.

    Arbeitsschritte

    Elvis und sein Gürtel

    Leg StaticInitializationTest.java an:

    package aufbau.puzzlers;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.time.LocalDate;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class StaticInitializationTest {

    static class Elvis {

        static final Elvis INSTANCE = new Elvis();
        static final int CURRENT_YEAR = LocalDate.now().getYear();

        private final int beltSize;

        private Elvis() {
            beltSize = CURRENT_YEAR - 1930;
        }

        int beltSize() {
            return beltSize;
        }
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void elvisKnowsTheCurrentYear() {
        assertEquals(LocalDate.now().getYear(), Elvis.CURRENT_YEAR);
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void elvisWearsABeltThatFits() {
        int expectedBeltSize = LocalDate.now().getYear() - 1930;
        assertEquals(expectedBeltSize, Elvis.INSTANCE.beltSize());
    }
}

    Notier für beide Tests, ob sie grün werden. Entferne dann beide @Disabled und starte die Testklasse in der IDE.

    Korrigiere die Assertion, die scheitert. Ändere danach die Klasse Elvis so, dass der Gürtel passt, und stell die ursprüngliche Assertion wieder her.

    Strings in der Schleife

    Leg StringConcatenationTest.java an:

    package aufbau.puzzlers;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class StringConcatenationTest {

    // Adjust to your machine: smaller if the test runs too long, larger if the times are too short to compare.
    private static final int COUNT = 100_000;

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void compareConcatenationWithStringBuilder() {
        long start = System.nanoTime();
        String text = "";
        for (int i = 0; i < COUNT; i++) {
            text += 'a';
        }
        long concatenationMillis = (System.nanoTime() - start) / 1_000_000;

        start = System.nanoTime();
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < COUNT; i++) {
            builder.append('a');
        }
        String builtText = builder.toString();
        long builderMillis = (System.nanoTime() - start) / 1_000_000;

        System.out.println("String +=      : " + concatenationMillis + " ms");
        System.out.println("StringBuilder  : " + builderMillis + " ms");
        assertEquals(text, builtText);
    }
}

    Beide Schleifen bauen denselben Text. Schätz vorher: Wie viel schneller ist die zweite – gleich schnell, doppelt, zehnfach, hundertfach? Entferne dann @Disabled und starte den Test in der IDE.

    Vergleich die beiden Zeilen in der Ausgabe mit Deiner Schätzung.

    Ein Raum je Durchlauf

    Leg ObjectCreationTest.java an. Der Raum hier hat 1000 Plätze, jeder als Eintrag in einem Array:

    package aufbau.puzzlers;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class ObjectCreationTest {

    // Adjust to your machine: smaller if the test runs too long, larger if the times are too short to compare.
    private static final int COUNT = 1_000_000;
    private static final int SEATS = 1_000;

    static class Room {

        private final int[] seats;
        private String number;

        Room(int seatCount) {
            seats = new int[seatCount];
        }

        void setNumber(String number) {
            this.number = number;
        }

        @Override
        public String toString() {
            return "Room " + number + " with " + seats.length + " seats";
        }
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void compareNewObjectPerLoopWithReusedObject() {
        long start = System.nanoTime();
        StringBuilder newRooms = new StringBuilder();
        for (int i = 0; i < COUNT; i++) {
            Room room = new Room(SEATS);
            room.setNumber(Integer.toString(i));
            newRooms.append(room).append('\n');
        }
        long newRoomsMillis = (System.nanoTime() - start) / 1_000_000;

        start = System.nanoTime();
        StringBuilder reusedRoom = new StringBuilder();
        Room room = new Room(SEATS);
        for (int i = 0; i < COUNT; i++) {
            room.setNumber(Integer.toString(i));
            reusedRoom.append(room).append('\n');
        }
        long reusedRoomMillis = (System.nanoTime() - start) / 1_000_000;

        System.out.println("New room per loop : " + newRoomsMillis + " ms");
        System.out.println("One reused room   : " + reusedRoomMillis + " ms");
        assertEquals(newRooms.toString(), reusedRoom.toString());
    }
}

    Schätz vorher, wie groß der Unterschied ist. Entferne dann @Disabled und starte den Test in der IDE.

    Setz danach SEATS auf 1 und miss noch einmal. Was sagt Dir der Unterschied?

    Kleinbuchstaben, aber welche?

    Leg LowerCaseTest.java an. Ì ist das große Ì (I mit Gravis):

    package aufbau.puzzlers;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.Locale;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class LowerCaseTest {

    private static final String ROOM_CODE = "Ì"; // Ì, capital I with grave accent

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void lowerCaseKeepsTheLength() {
        String lowerCase = ROOM_CODE.toLowerCase(Locale.ROOT);
        assertEquals(ROOM_CODE.length(), lowerCase.length());
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void lowerCaseKeepsTheLengthInLithuanian() {
        String lowerCase = ROOM_CODE.toLowerCase(Locale.forLanguageTag("lt"));
        assertEquals(ROOM_CODE.length(), lowerCase.length());
    }
}

    Notier für beide Tests, ob sie grün werden. Entferne dann beide @Disabled und starte die Testklasse in der IDE.

    Korrigiere die Assertion, die scheitert. Was liefert ROOM_CODE.toLowerCase() ohne Argument – und auf welchem Rechner?

    Ein auskommentierter Zähler

    Leg UnicodeCommentTest.java an:

    package aufbau.puzzlers;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class UnicodeCommentTest {

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void commentedOutBookingIsNotCounted() {
        int bookings = 0;
        // \u000a bookings++;
        assertEquals(0, bookings);
    }
}

    Notier, ob der Test grün wird. Entferne dann @Disabled und starte ihn in der IDE.

    Korrigiere die Assertion. Dann die Gegenfrage: Füg in den Test die Zeile // \u000a is a line break ein und sag voraus, ob das Projekt noch übersetzt. Prüf es, indem Du erneut mit Maven baust.

    Entferne die Zeile danach wieder, damit das Projekt baut.

    Reflexionsfragen

    • Warum trägt Elvis einen Gürtel der Größe -1930 – und warum wäre das bei static final int CURRENT_YEAR = 2026; nicht passiert?
    • Warum ist die Schleife mit += so viel langsamer als die mit StringBuilder?
    • Was macht in ObjectCreationTest die erste Variante langsamer – das neue Objekt oder etwas anderes? Und ist die zweite Variante deshalb besser?
    • Warum ist toLowerCase() ohne Argument für einen Raumcode keine gute Idee?
    • Wie kann eine Zeile, die mit // beginnt, eine Buchung zählen?
    • Welches der Rätsel könnte Dir im eigenen Projekt tatsächlich begegnen – und woran würdest Du es dort erkennen?
