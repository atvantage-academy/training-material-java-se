    Drei Vorhersagen zu Literalen, Verkettung und statischen Methoden

    User Story

    Als Java-Entwickler:in möchte ich prüfen, ob meine Erwartung an eine Zeile Code stimmt, damit ich merke, wo mein Bild von Java Lücken hat.

    Lernziele
    • Du notierst die erwartete Ausgabe eines Programms, bevor Du es startest.
    • Du erklärst eine Abweichung zwischen Erwartung und Ausgabe mit den Regeln der Sprache.
    • Du unterscheidest statisch und dynamisch gebundene Methodenaufrufe.
    Definition of Done
    • In Deiner IDE gibt es ein Java-Projekt einstieg mit den drei Klassen.
    • Hinter jeder Ausgabezeile der drei Programme steht Deine Erwartung als Kommentar – notiert vor dem Start.
    • Alle drei Programme sind gestartet, und Du hast jede Ausgabe mit Deiner Erwartung verglichen.
    • Für jede Abweichung hast Du eine Erklärung notiert – oder eine Frage für die Nachbesprechung.
    • Du hast die Kontrollfragen beantwortet

    Drei kurze Programme, jedes mit einer main-Methode. Du legst sie in einem Java-Projekt Deiner IDE ab und startest sie dort. Die Spielregel: Erst die Erwartung aufschreiben, dann starten. Wer danebenliegt, hat gefunden, worum es geht.

    Arbeitsschritte

    Ein Projekt anlegen

    Leg in Deiner IDE ein Java-Projekt einstieg an, mit Java 17 oder höher.

    Die Addition vorhersagen und starten

    Leg die Klasse CafeBabe an und kopiere dieses Programm hinein. Es soll die Addition aus dem Kommentar ausrechnen:

    public class CafeBabe {

    // Wanted: this addition
    //       CAFE BABE
    //   + 1 0000 0000
    //   =============
    //     1 CAFE BABE
    public static void main(String[] args) {
        long l1 = 0x0_cafe_babe;
        long l2 = 0x1_0000_0000L;
        System.out.println(Long.toHexString(l1 + l2));
    }
}

    Schreib Deine Erwartung als Kommentar hinter die Zeile mit println, etwa // expected: …. Erst dann starte das Programm.

    Die Verkettungen vorhersagen und starten

    Leg die Klasse Concatenation an:

    public class Concatenation {

    public static void main(String[] args) {
        System.out.println(String.format("%s%s%d", "H", "a", 124 + 56)); // 1
        System.out.println("H" + "a" + 124 + 56);                        // 2
        System.out.println("H" + "a" + (124 + 56));                      // 3
        System.out.println(124 + 56 + "H" + "a");                        // 4
        System.out.println('H' + 'a');                                   // 5
        System.out.println((char) ('H' + 'a'));                          // 6
    }
}

    Notier hinter jeder der sechs Zeilen, was sie ausgibt. Dann starte das Programm.

    Die bellenden Hunde vorhersagen und starten

    Leg die Klasse Bark an:

    public class Bark {

    static class Dog {
        static void bark() {
            System.out.println("woof");
        }
    }

    static class Basenji extends Dog {
        static void bark() {
            System.out.println("wow");
        }
    }

    public static void main(String[] args) {
        Dog woofer = new Dog();
        Dog nipper = new Basenji();
        woofer.bark();
        nipper.bark();
    }
}

    Notier hinter den beiden bark()-Aufrufen, was sie ausgeben. Dann starte das Programm.

    Die Abweichungen erklären

    Geh die drei Programme durch und markiere jede Zeile, bei der Ausgabe und Erwartung nicht übereinstimmen. Notier zu jeder eine Erklärung – oder, wenn Du keine findest, die Frage, die Du in der Nachbesprechung stellen willst.

    Reflexionsfragen

    • Warum gibt CafeBabe nicht 1cafebabe aus – und was musst Du ändern, damit es das tut?
    • Warum ergibt Ausgabe 2 von Concatenation Ha12456, Ausgabe 4 aber 180Ha – und warum ist Ausgabe 5 eine Zahl?
    • Warum sagt in Bark auch der Basenji woof?
    • Was bedeutet „statische Bindung“, was „dynamische Bindung“? Welche Methoden sind in Java statisch, welche dynamisch gebunden?
