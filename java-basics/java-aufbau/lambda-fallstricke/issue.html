    Fallstricke mit Lambdas und Streams vorhersagen

    User Story

    Als Java-Entwickler:in möchte ich die typischen Fallen bei Lambdas und Streams kennen, bevor sie mir im Projekt begegnen, damit ich Fehler und Langsamkeit dort erkenne, wo sie herkommen.

    Lernziele
    • Du erkennst Autoboxing hinter generischen funktionalen Interfaces und ersetzt sie durch ihre Ableitungen für primitive Typen.
    • Du erklärst, wann eine Methodenreferenz ihr Ziel auswertet und wann ein Lambda.
    • Du unterscheidest, worauf this in einem Lambda und in einer anonymen Klasse zeigt.
    • Du sagst das Verhalten von Streams, toList, toMap und Optional.orElse vorher.
    Definition of Done
    • BoxingInLambdasTest enthält beide Varianten, mit Function<Long, Long> und mit LongUnaryOperator; Du hast die Laufzeiten verglichen.
    • In LambdaPitfallsTest trägt kein Test mehr @Disabled; jede Vorhersage hast Du notiert, geprüft und die Assertion auf das tatsächliche Verhalten korrigiert.
    • Der Maven-Build läuft ohne Fehler und ohne übersprungene Tests durch.
    • Du hast die Kontrollfragen beantwortet

    Lambdas und Streams machen Code kürzer – und verstecken dabei manches, was eine Schleife offen zeigt: ein Autoboxing, einen Auswertungszeitpunkt, einen Zustand. Neun kurze Tests tragen je eine naheliegende Erwartung.

    Du arbeitest im Package aufbau.lambdas mit Room, Booking und SampleData aus Raumbuchungen mit Lambdas und Streams auswerten.

    Arbeitsschritte

    Kopiere die Tests

    Kopiere beide Klassen ins Package aufbau.lambdas unter src/test/java.

    BoxingInLambdasTest.java:

    package aufbau.lambdas;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.function.Function;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class BoxingInLambdasTest {

    // Adjust to your machine: smaller if the test runs too long, larger if the times are too short to compare.
    static final int LIMIT = Integer.MAX_VALUE;
    static final long EXPECTED_SUM = (long) LIMIT * (LIMIT - 1) / 2;

    @Test
    @Disabled("Predict the duration first, then remove @Disabled")
    void sumWithFunctionOfLong() {
        Function<Long, Long> addUpTo = sum -> {
            for (int i = 0; i < LIMIT; i++) {
                sum += i;
            }
            return sum;
        };

        long start = System.nanoTime();
        long result = addUpTo.apply(0L);
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Function<Long, Long>: " + millis + " ms");

        assertEquals(EXPECTED_SUM, result);
    }
}

    LambdaPitfallsTest.java:

    package aufbau.lambdas;

import static aufbau.lambdas.SampleData.BOOKINGS;
import static aufbau.lambdas.SampleData.ROOMS;
import static org.junit.jupiter.api.Assertions.assertDoesNotThrow;
import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;
import java.util.concurrent.atomic.AtomicInteger;
import java.util.function.Supplier;
import java.util.stream.Collectors;
import java.util.stream.Stream;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class LambdaPitfallsTest {

    // --- core

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void methodReferenceOnNull() {
        Room room = null;

        assertDoesNotThrow(() -> {
            Supplier<String> name = room::name;
        });
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void thisInLambdaAndAnonymousClass() {
        Greeter greeter = new Greeter();

        assertEquals(greeter.byLambda().get(), greeter.byAnonymousClass().get());
    }

    static class Greeter {

        Supplier<String> byLambda() {
            return () -> this.toString();
        }

        Supplier<String> byAnonymousClass() {
            return new Supplier<>() {
                @Override
                public String get() {
                    return this.toString();
                }
            };
        }

        @Override
        public String toString() {
            return "Greeter";
        }
    }

    // --- quick predictions

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void howManyRoomsAreChecked() {
        List<String> checked = new ArrayList<>();

        Optional<Room> firstLargeRoom = ROOMS.stream()
                .filter(room -> {
                    checked.add(room.id());
                    return room.seats() > 10;
                })
                .findFirst();

        assertEquals("Munich", firstLargeRoom.orElseThrow().name());
        assertEquals(8, checked.size());
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void howOftenIsTheFallbackCreated() {
        AtomicInteger calls = new AtomicInteger();

        String name = Optional.of("Berlin").orElse(fallbackName(calls));

        assertEquals("Berlin", name);
        assertEquals(0, calls.get());
    }

    private static String fallbackName(AtomicInteger calls) {
        calls.incrementAndGet();
        return "unknown";
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void useAStreamTwice() {
        Stream<Room> rooms = ROOMS.stream();
        long large = rooms.filter(room -> room.seats() > 10).count();

        assertEquals(3, large);
        assertDoesNotThrow(() -> rooms.filter(room -> room.seats() <= 10).count());
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void addToTheResultOfToList() {
        List<String> names = ROOMS.stream().map(Room::name).toList();

        assertDoesNotThrow(() -> names.add("Bonn"));
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void hoursPerPersonWithToMap() {
        assertDoesNotThrow(() -> BOOKINGS.stream()
                .collect(Collectors.toMap(Booking::bookedBy, Booking::hours)));
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void streamOfAnIntArray() {
        int[] seats = { 6, 10, 16 };

        assertEquals(3, Stream.of(seats).count());
    }
}

    Sag die Kosten des Autoboxings vorher

    Schätz, wie lange sumWithFunctionOfLong läuft, und notier die Zahl. Entferne @Disabled und starte die Testklasse in der IDE.

    Schreib danach einen zweiten Test sumWithLongUnaryOperator, der dasselbe mit einem LongUnaryOperator rechnet, und vergleich die Laufzeiten. Welche Ableitungen für primitive Typen es gibt, zeigt die Visualisierung Lambdas, Streams und Optional.

    Hinweis: Der Test läuft einige Sekunden – er addiert rund zwei Milliarden Zahlen.

    Sag die beiden Kernfälle vorher

    Nimm Dir in LambdaPitfallsTest die beiden Tests unter // --- core vor, methodReferenceOnNull und thisInLambdaAndAnonymousClass. Was passiert jeweils? Notier Deine Erwartung, entferne @Disabled und starte den Test in der IDE. Erklär das Ergebnis und korrigier die Assertion auf das tatsächliche Verhalten.

    Schreib danach in methodReferenceOnNull zum Vergleich ein Lambda daneben: Supplier<String> byLambda = () -> room.name(); – was passiert damit?

    Sag die schnellen Fälle vorher

    Die übrigen sechs Tests unter // --- quick predictions sind schneller entschieden. Geh sie nacheinander durch – Erwartung notieren, starten, erklären, korrigieren. Bei hoursPerPersonWithToMap gibt es außer dem Korrigieren der Assertion einen zweiten Weg: Welches dritte Argument von toMap macht daraus eine Summe je Person?

    Für Schnelle

    • Effectively final: Zähl in einer Schleife mit int count = 0; und ROOMS.forEach(room -> count++);. Was sagt der Compiler? Warum ist der Ausweg über int[] count oder AtomicInteger meist der eigentliche Fehler – und was wäre richtig?
    • Seiteneffekte im parallelen Stream: Sammle mit IntStream.range(0, 100_000).parallel().forEach(list::add) in eine ArrayList. Wie viele Elemente landen darin? Was sagt collect dazu?
    • Comparator mit Subtraktion: Sortier Integer.MAX_VALUE, -1 und 1 mit (a, b) -> a - b und mit Integer::compare. Was geht schief?

    Reflexionsfragen

    • Warum ist Function<Long, Long> hier langsamer als LongUnaryOperator, obwohl beide dasselbe rechnen?
    • Warum wirft room::name sofort, () -> room.name() aber erst beim Aufruf?
    • Warum prüft der Stream in howManyRoomsAreChecked nur drei Räume und nicht alle acht?
    • Wann ist orElseGet besser als orElse?
