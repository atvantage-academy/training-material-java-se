    Lombok: Boilerplate vom Compiler erzeugen lassen

    User Story

    Als Entwickler:in der Raumbuchung möchte ich Getter, equals, hashCode und toString nicht von Hand schreiben, damit Wertklassen kurz bleiben und beim nächsten neuen Feld nichts vergessen wird.

    Lernziele
    • Du bindest Lombok als Abhängigkeit im Scope provided und als Annotation Processor im maven-compiler-plugin ein.
    • Du ersetzt handgeschriebene Getter, equals, hashCode und toString durch @Value und ergänzt einen Builder mit @Builder.
    • Du erklärst, dass Lombok zur Übersetzungszeit arbeitet und seine Annotationen zur Laufzeit nicht mehr da sind.
    • Du erkennst die Falle von @Data an veränderlichen Objekten in einem HashSet.
    • Du kennzeichnest erzeugten Code mit @Generated, damit die Testabdeckung ihn nicht mitzählt.
    Definition of Done
    • Lombok steht mit der Version als Property lombok.version im POM, als Abhängigkeit im Scope provided und als Annotation Processor in der Konfiguration des maven-compiler-plugin unter pluginManagement.
    • Booking besteht nur noch aus Feldern, @Value und @Builder; BookingTest ist unverändert grün, und der Builder-Test läuft.
    • Die Vorhersagen in LombokPredictionsTest hast Du notiert, geprüft und die Assertions auf das tatsächliche Verhalten korrigiert.
    • Die lombok.config neben der pom.xml setzt lombok.addLombokGeneratedAnnotation = true; equals und hashCode von Room erzeugt Lombok aus der Raumnummer, und der JaCoCo-Bericht zählt sie nicht mit.
    • Der Maven-Build läuft ohne Fehler und ohne übersprungene Tests durch.
    • Du hast die Kontrollfragen beantwortet

    Eine Buchung hat vier Felder – und rund 60 Zeilen Code: Konstruktor, Getter, equals, hashCode, toString. Lombok erzeugt das beim Übersetzen aus wenigen Annotationen. Du baust die Buchung damit um; die vorhandenen Tests müssen dabei grün bleiben.

    Hinweis zur IDE: Lombok verändert den Code beim Übersetzen. Damit die IDE die erzeugten Methoden kennt, braucht sie Unterstützung: IntelliJ IDEA bringt sie mit, Eclipse braucht eine eigene Installation von Lombok (siehe die Links oben). Deshalb ist diese Übung optional. Maven baut in jedem Fall.

    Arbeitsschritte

    Binde Lombok ein

    Schlag auf Maven Central die neueste stabile Version von org.projectlombok:lombok und von org.apache.maven.plugins:maven-compiler-plugin nach und leg beide als Property an – in <properties>, VERSION jeweils ersetzt:

    <lombok.version>VERSION</lombok.version>
<maven-compiler-plugin.version>VERSION</maven-compiler-plugin.version>

    Ergänze in den dependencies die Abhängigkeit – nur zum Übersetzen, deshalb provided:

    <dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <version>${lombok.version}</version>
    <scope>provided</scope>
</dependency>

    Leg in pluginManagement den Compiler fest und nenn ihm Lombok als Annotation Processor:

    <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>${maven-compiler-plugin.version}</version>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
                <version>${lombok.version}</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>

    Kopiere die Buchung und ihren Test

    Im Ordner src/main/java lege das Package aufbau.lombok an und darin Booking.java:

    package aufbau.lombok;

import java.time.LocalDate;
import java.util.Objects;

public final class Booking {

    private final String roomId;
    private final String bookedBy;
    private final LocalDate date;
    private final int hours;

    public Booking(String roomId, String bookedBy, LocalDate date, int hours) {
        this.roomId = roomId;
        this.bookedBy = bookedBy;
        this.date = date;
        this.hours = hours;
    }

    public String getRoomId() {
        return roomId;
    }

    public String getBookedBy() {
        return bookedBy;
    }

    public LocalDate getDate() {
        return date;
    }

    public int getHours() {
        return hours;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) {
            return true;
        }
        if (!(o instanceof Booking)) {
            return false;
        }
        Booking other = (Booking) o;
        return hours == other.hours
                && Objects.equals(roomId, other.roomId)
                && Objects.equals(bookedBy, other.bookedBy)
                && Objects.equals(date, other.date);
    }

    @Override
    public int hashCode() {
        return Objects.hash(roomId, bookedBy, date, hours);
    }

    @Override
    public String toString() {
        return "Booking(roomId=" + roomId + ", bookedBy=" + bookedBy + ", date=" + date + ", hours=" + hours + ")";
    }
}

    Baue erneut mit Maven: Die drei Tests sind grün, der Builder-Test wartet.

    Lass Lombok die Buchung schreiben

    Ersetze in Booking Konstruktor, Getter, equals, hashCode und toString durch eine Annotation: @Value. Die Felder bleiben – ohne private final, das ergänzt @Value selbst. Baue erneut mit Maven: BookingTest bleibt grün, auch describesItself mit seinem genauen Text.

    Ergänze danach @Builder, entferne im Test buildsABookingStepByStep das @Disabled und die Kommentarzeichen und starte die Testklasse in der IDE.

    Hinweis: Was eine Annotation genau erzeugt, steht auf der Seite Features von Lombok. In IntelliJ IDEA zeigt die Strukturansicht der Klasse die erzeugten Methoden.

    Lass Lombok equals und hashCode des Raums erzeugen

    Im Room aus Den Raum mit JUnit testen stehen equals und hashCode, die Deine IDE in Zauberei mit Collections erzeugt hat. Das kann Lombok ebenso – und dabei die erzeugten Methoden so kennzeichnen, dass JaCoCo sie nicht mitmisst.

    1. Leg im Projektordner, neben der pom.xml, die Datei lombok.config an:

      config.stopBubbling = true
lombok.addLombokGeneratedAnnotation = true

      Die zweite Zeile hängt an jede von Lombok erzeugte Methode die Annotation @lombok.Generated.

    2. Ersetz in Room die Methoden equals und hashCode durch Annotationen: Lombok soll sie nur aus der Raumnummer erzeugen.

    3. Baue erneut mit Maven: Die Tests aus Zauberei mit Collections bleiben grün. Sieh im JaCoCo-Bericht nach, welche Methoden von Room dort noch auftauchen.

    Lösung

    Dazu der Import lombok.EqualsAndHashCode; die alten Methoden und der Import java.util.Objects fallen weg.

    @EqualsAndHashCode(onlyExplicitlyIncluded = true)
public class Room {

    @EqualsAndHashCode.Include
    private final String number;

    // …
}

    Was passiert, wenn Du in der lombok.config testweise false statt true einträgst? Notier Deine Erwartung, baue erneut mit Maven und stell danach true wieder her.

    Sag vorher, was von Lombok übrig bleibt

    Kopiere die folgenden Klassen. Room kommt ins Package aufbau.lombok unter src/main/java:

    package aufbau.lombok;

import lombok.AllArgsConstructor;
import lombok.Data;

@Data
@AllArgsConstructor
public class Room {

    private String name;
    private int capacity;
}

    LombokPredictionsTest kommt ins Package aufbau.lombok unter src/test/java:

    package aufbau.lombok;

import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;

import java.util.HashSet;
import java.util.Set;
import lombok.Value;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class LombokPredictionsTest {

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void annotationAtRuntime() {
        assertNotNull(Booking.class.getAnnotation(Value.class));
    }

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void changedRoomInHashSet() {
        Room room = new Room("Seminar 1", 12);
        Set<Room> rooms = new HashSet<>();
        rooms.add(room);

        room.setCapacity(16);

        assertTrue(rooms.contains(room));
    }
}

    Geh für jeden Test so vor:

    1. Notier Deine Erwartung.
    2. Entferne @Disabled und starte den Test in der IDE.
    3. Erklär das Ergebnis.
    4. Korrigier die Assertion auf das tatsächliche Verhalten, bis der Test grün ist.

    Für Schnelle

    Schreib Booking testweise als Record. Welche Tests in BookingTest brechen – und warum? Nimm die Änderung danach zurück.

    Reflexionsfragen

    • Warum steht Lombok im Scope provided?
    • Warum findet Booking.class.getAnnotation(Value.class) nichts – und was unterscheidet Lombok damit von JUnit oder einem Dynamic Proxy?
    • Warum findet das HashSet den Raum nicht mehr, nachdem Du seine Kapazität geändert hast?
    • Warum zählt JaCoCo die von Lombok erzeugten Methoden nicht mit – und was passiert ohne @Generated?
    • Seit Java 16 gibt es Records. Wann nimmst Du noch @Value?
