    SPI: Benachrichtigungskanäle per ServiceLoader

    User Story

    Als Entwickler:in möchte ich neue Benachrichtigungskanäle hinzufügen, ohne den Buchungsservice zu ändern, damit ein Kanal als eigenes JAR dazukommen kann.

    Lernziele
    • Du definierst ein Interface als Service und meldest Implementierungen in einer Datei unter META-INF/services an.
    • Du lädst alle angemeldeten Implementierungen mit ServiceLoader.load und verwendest sie, ohne ihre Klassen zu kennen.
    • Du sagst voraus, wann der ServiceLoader Klassen lädt und wann ein Fehler in der Anmeldung auffällt.
    • Du prüfst in einem Test, welche Implementierungen gefunden werden, und meldest dafür eine eigene aus den Test-Ressourcen an.
    Definition of Done

    Kanäle per ServiceLoader

    • EmailChannel und ChatChannel sind in src/main/resources/META-INF/services/aufbau.spi.NotificationChannel angemeldet.
    • BookingApp gibt beide Kanäle aus und verschickt die Buchung über beide; im BookingService steht kein new für einen Kanal.

    Test

    • BookingServiceTest läuft ohne @Disabled grün und erwartet die Kanäle, die beim Testlauf tatsächlich gefunden werden.
    • Ein zweiter Test prüft, dass RecordingChannel die Nachricht einer Buchung bekommt.

    Kür (optional)

    • Ein zweites Maven-Projekt java-aufbau-sms liefert SmsChannel als JAR; BookingApp findet den Kanal, wenn das JAR auf dem Klassenpfad liegt.

    Für die ganze Seite

    • Du hast die Kontrollfragen beantwortet

    Nach jeder Buchung soll die Raumbuchung Bescheid geben – per E-Mail, im Team-Chat und irgendwann über Kanäle, die heute noch niemand kennt. Der BookingService soll dafür weder new EmailChannel() noch eine if-Kaskade enthalten. Er fragt zur Laufzeit, welche Kanäle da sind.

    Arbeitsschritte

    Den Service und zwei Kanäle anlegen

    Im Ordner src/main/java des Projekts java-aufbau lege das Package aufbau.spi an und kopiere die folgenden Klassen hinein, jede in ihre eigene Datei.

    Das Interface, das jeder Kanal erfüllt:

    package aufbau.spi;

public interface NotificationChannel {

    String name();

    void send(String message);
}

    Ein Kanal, der eine E-Mail vortäuscht:

    package aufbau.spi;

public class EmailChannel implements NotificationChannel {

    @Override
    public String name() {
        return "email";
    }

    @Override
    public void send(String message) {
        // Imagine a real e-mail to the facility management here.
        System.out.println("[email] " + message);
    }
}

    Ein Kanal, der eine Nachricht im Team-Chat vortäuscht:

    package aufbau.spi;

public class ChatChannel implements NotificationChannel {

    @Override
    public String name() {
        return "chat";
    }

    @Override
    public void send(String message) {
        // Imagine a post in the team chat here.
        System.out.println("[chat] " + message);
    }
}

    Der Service fragt den ServiceLoader nach allen Kanälen – er kennt keine ihrer Klassen:

    package aufbau.spi;

import java.util.ArrayList;
import java.util.List;
import java.util.ServiceLoader;
import java.util.Set;
import java.util.TreeSet;

public class BookingService {

    private final List<NotificationChannel> channels = new ArrayList<>();

    public BookingService() {
        ServiceLoader<NotificationChannel> loader = ServiceLoader.load(NotificationChannel.class);
        for (NotificationChannel channel : loader) {
            channels.add(channel);
        }
    }

    public Set<String> channelNames() {
        Set<String> names = new TreeSet<>();
        for (NotificationChannel channel : channels) {
            names.add(channel.name());
        }
        return names;
    }

    public void book(String roomId, int attendees) {
        String message = "Room " + roomId + " booked for " + attendees + " people";
        for (NotificationChannel channel : channels) {
            channel.send(message);
        }
    }
}

    Und eine Klasse zum Starten:

    package aufbau.spi;

public class BookingApp {

    public static void main(String[] args) {
        BookingService service = new BookingService();
        System.out.println("Channels found: " + service.channelNames());
        service.book("R1", 3);
    }
}

    Vorhersage: Noch weiß niemand, dass es EmailChannel und ChatChannel gibt. Was gibt BookingApp aus – oder bricht sie ab? Notier Deine Erwartung.

    Baue das Projekt java-aufbau erneut mit Maven.

    Starte BookingApp:

    java -cp target/classes aufbau.spi.BookingApp

    Die Kanäle anmelden

    Leg unter src/main/resources/ den Ordner META-INF/services/ an – zwei Ordner ineinander, nicht ein Ordner mit Punkt im Namen. Darin legst Du eine Datei an, die genau so heißt wie das Interface, voll qualifiziert und ohne Endung: aufbau.spi.NotificationChannel. Ihr Inhalt ist eine Klasse je Zeile:

    aufbau.spi.EmailChannel
aufbau.spi.ChatChannel

    Übersetze und starte BookingApp erneut wie oben. Beide Kanäle verschicken die Buchung.

    Hinweis: Maven kopiert die Datei beim Übersetzen nach target/classes/META-INF/services/. Findet BookingApp keine Kanäle, sieh zuerst dort nach.

    Eine falsche Zeile

    Ergänze in der Datei eine dritte Zeile mit einer Klasse, die es nicht gibt:

    aufbau.spi.SmsChannel

    Vorhersage: Was passiert beim Start – und wann genau: beim Aufruf von ServiceLoader.load oder später? Übersetze, starte und vergleiche die Ausgabe mit Deiner Erwartung. Entferne die Zeile danach wieder.

    Die gefundenen Kanäle testen

    Ein Test bekommt einen eigenen Kanal, der Nachrichten mitschreibt, statt sie zu verschicken. Im Ordner src/test/java lege dafür ebenfalls das Package aufbau.spi an und darin den Kanal:

    package aufbau.spi;

import java.util.ArrayList;
import java.util.List;

public class RecordingChannel implements NotificationChannel {

    static final List<String> MESSAGES = new ArrayList<>();

    @Override
    public String name() {
        return "recording";
    }

    @Override
    public void send(String message) {
        MESSAGES.add(message);
    }
}

    Melde ihn in den Test-Ressourcen an: Leg die Datei src/test/resources/META-INF/services/aufbau.spi.NotificationChannel an, mit einer Zeile:

    aufbau.spi.RecordingChannel

    Leg daneben den Test BookingServiceTest an:

    package aufbau.spi;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.Set;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

class BookingServiceTest {

    @Test
    @Disabled("Predict the result first, then remove @Disabled")
    void findsTheRegisteredChannels() {
        BookingService service = new BookingService();

        assertEquals(Set.of("chat", "email"), service.channelNames());
    }
}

    Vorhersage: Welche Kanäle findet der Service im Test? Notier Deine Erwartung, entferne @Disabled und starte die Testklasse in der IDE.

    Erklär das Ergebnis und korrigier die Assertion auf das tatsächliche Verhalten.

    Ergänze dann den Test bookingNotifiesTheRecordingChannel: Leere RecordingChannel.MESSAGES, erzeuge einen BookingService, buche Raum R2 für 8 Personen und prüfe, dass die Liste genau die Nachricht Room R2 booked for 8 people enthält.

    Kür: Ein Kanal aus einem zweiten JAR

    Ein neuer Kanal soll als eigenes JAR dazukommen, ohne dass sich im Projekt java-aufbau etwas ändert.

    Leg das Projekt java-aufbau in Dein lokales Maven-Repository, damit ein anderes Projekt es als Abhängigkeit findet. Im Ordner java-aufbau:

    mvn install

    Leg neben dem Ordner java-aufbau einen Ordner java-aufbau-sms an, darin diese pom.xml:

    <?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>de.schulung</groupId>
    <artifactId>java-aufbau-sms</artifactId>
    <version>1.0.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <java-aufbau.version>1.0.0-SNAPSHOT</java-aufbau.version>
    </properties>

    <dependencies>
        <dependency>
            <groupId>de.schulung</groupId>
            <artifactId>java-aufbau</artifactId>
            <version>${java-aufbau.version}</version>
        </dependency>
    </dependencies>
</project>

    Hinweis: Trägt Dein Projekt java-aufbau eine andere groupId oder version, übernimm sie hier.

    Im Ordner src/main/java von java-aufbau-sms lege das Package aufbau.sms an und darin die Klasse SmsChannel:

    package aufbau.sms;

import aufbau.spi.NotificationChannel;

public class SmsChannel implements NotificationChannel {

    @Override
    public String name() {
        return "sms";
    }

    @Override
    public void send(String message) {
        // Imagine a text message to the room's host here.
        System.out.println("[sms] " + message);
    }
}

    Melde den Kanal in java-aufbau-sms an – in einer eigenen Datei src/main/resources/META-INF/services/aufbau.spi.NotificationChannel mit der Zeile:

    aufbau.sms.SmsChannel

    Bau das JAR im Ordner java-aufbau-sms:

    mvn package

    Starte BookingApp aus dem Projekt java-aufbau mit dem neuen JAR auf dem Klassenpfad, im Ordner java-aufbau-sms. Das Trennzeichen zwischen den Einträgen hängt vom Betriebssystem ab:

    macOS und Linux

    Starte mit : als Trennzeichen:

    java -cp "../java-aufbau/target/classes:target/java-aufbau-sms-1.0.0-SNAPSHOT.jar" aufbau.spi.BookingApp
    Windows

    Starte mit ; als Trennzeichen (die Anführungszeichen braucht PowerShell):

    java -cp "..\java-aufbau\target\classes;target\java-aufbau-sms-1.0.0-SNAPSHOT.jar" aufbau.spi.BookingApp

    Drei Kanäle, und im BookingService hat sich keine Zeile geändert.

    Für Schnelle

    • Gib die Klassen aller Kanäle aus, ohne ein Objekt zu erzeugen: ServiceLoader.load(NotificationChannel.class).stream() liefert ServiceLoader.Provider-Objekte; type() nennt die Klasse, erst get() erzeugt das Objekt.
    • Gib ChatChannel einen Konstruktor mit einem String-Parameter (und keinen ohne). Was meldet der ServiceLoader?

    Reflexionsfragen

    • Was gibt BookingApp ohne die Datei unter META-INF/services aus – und warum gibt es keinen Fehler?
    • Warum findet der Test einen Kanal mehr als BookingApp?
    • Wann wird der Fehler bei der Zeile aufbau.spi.SmsChannel geworfen – bei ServiceLoader.load oder später?
    • Warum muss der Test über ein statisches Feld an die Nachrichten von RecordingChannel kommen?
