    Das Maven-Projekt anlegen

    User Story

    Als Java-Entwickler:in möchte ich ein eigenes Maven-Projekt mit JUnit aufsetzen, damit ich meine Erwartungen an Code als Tests festhalten kann.

    Lernziele
    • Du legst in Deiner IDE ein Maven-Projekt mit sinnvollen Koordinaten an und legst es mit maven.compiler.release auf Java 17 oder höher fest.
    • Du bindest JUnit über die junit-bom ein und deklarierst junit-jupiter ohne Version.
    • Du liest den Abhängigkeitsbaum mit mvn dependency:tree.
    Definition of Done
    • Das Projekt java-aufbau hat groupId de.schulung, artifactId java-aufbau, eine -SNAPSHOT-Version und maven.compiler.release 17 oder höher; die Beispielklasse der IDE ist gelöscht.
    • mvn verify endet im Terminal mit BUILD SUCCESS.
    • JUnit kommt über die junit-bom ins Projekt, ihre Version steht als Property junit.version; junit-jupiter steht ohne Version im POM, und mvn dependency:tree zeigt es.
    • Du hast die Kontrollfragen beantwortet

    Im Einstieg stand Deine Erwartung als Kommentar im Code. Jetzt legst Du das Projekt an, in dem Du für den Rest des Kurses arbeitest, holst JUnit hinein. Das Projekt legst Du in der IDE an und baust es mit Maven.

    Arbeitsschritte

    Das Projekt in der IDE anlegen

    Leg in Deiner IDE ein neues Maven-Projekt an – ohne Archetype, mit einem JDK 17 oder neuer. Die Koordinaten des Projekts:

    Angabe Wert Bedeutung
    groupId de.schulung Wer das Projekt herausgibt, meist ein umgedrehter Domainname
    artifactId java-aufbau Der Name des Projekts, zugleich der Name des JARs
    version 1.0.0-SNAPSHOT -SNAPSHOT heißt: in Arbeit, noch keine fertige Version

    Das POM auf Java 17 festlegen

    Sorg dafür, dass in den <properties> Deiner pom.xml diese beiden Einträge stehen – die Java-Version 17 oder höher und UTF-8 als Kodierung der Quelltexte:

    <properties>
    <maven.compiler.release>17</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>
    Gesamtstand der pom.xml 
    <?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>de.schulung</groupId>
    <artifactId>java-aufbau</artifactId>
    <version>1.0.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>
</project>

    Hat Deine IDE eine Beispielklasse erzeugt, lösch sie.

    Das Projekt im Terminal bauen

    Öffne ein Terminal im Projektordner java-aufbau und bau das Projekt:

    mvn verify

    Am Ende steht BUILD SUCCESS. Was die Zeilen dazwischen bedeuten, siehst Du Dir in Maven-Plugins und Lifecycle genauer an.

    JUnit über die BOM einbinden

    Schlag auf Maven Central (https://central.sonatype.com) die neueste stabile Version von org.junit:junit-bom nach – ohne Vorabversionen wie -M1 oder -RC1, die Maven Central oft als neueste führt. Leg die Version als Property an – ergänze in <properties> diese Zeile und ersetze VERSION durch die gefundene Version:

    <junit.version>VERSION</junit.version>

    Ergänze dann Dein POM nach </properties> um die BOM und die Abhängigkeit. Die BOM verweist auf die Property:

    <dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.junit</groupId>
            <artifactId>junit-bom</artifactId>
            <version>${junit.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>org.junit.jupiter</groupId>
        <artifactId>junit-jupiter</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
    Gesamtstand der pom.xml 
    <?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>de.schulung</groupId>
    <artifactId>java-aufbau</artifactId>
    <version>1.0.0-SNAPSHOT</version>

    <properties>
        <maven.compiler.release>17</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <junit.version>VERSION</junit.version>
    </properties>

    <dependencyManagement>
        <dependencies>
            <dependency>
                <groupId>org.junit</groupId>
                <artifactId>junit-bom</artifactId>
                <version>${junit.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>
        </dependencies>
    </dependencyManagement>

    <dependencies>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>

    Lass Dir anzeigen, welche Artefakte damit ins Projekt kommen:

    mvn dependency:tree

    Wie Maven Abhängigkeiten, transitive Abhängigkeiten und Scopes behandelt, zeigt die Visualisierung Maven.

    Reflexionsfragen

    • Woher kennt Maven die Version von junit-jupiter, obwohl sie nicht im POM steht – und was passiert, wenn Du später ein weiteres JUnit-Artefakt brauchst?
