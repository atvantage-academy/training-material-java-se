    Früh scheitern, nicht spät

    User Story

    Als Java-Entwickler:in möchte ich, dass ungültige Daten sofort auffallen, damit ich den Fehler dort finde, wo er entsteht – und nicht zehn Aufrufe später.

    Lernziele
    • Du sagst voraus, in welcher Zeile eine NullPointerException auftritt, und begründest es.
    • Du prüfst Argumente im Konstruktor mit Objects.requireNonNull und testest das mit assertThrows.
    • Du misst, was eine Exception als Abbruchbedingung einer Schleife kostet.
    Definition of Done
    • Das Paket aufbau.exceptions enthält ExceptionTimeTest und ExceptionControlFlowTest, keiner trägt mehr @Disabled.
    • Der Konstruktor von Person lehnt ein fehlendes Geburtsdatum ab; ein Test prüft das mit assertThrows und der Meldung.
    • mvn test läuft grün.
    • Du hast die beiden Laufzeiten aus ExceptionControlFlowTest notiert und kannst den Unterschied erklären.
    • Du hast die Kontrollfragen beantwortet

    Eine Exception ist eine Nachricht: Hier stimmt etwas nicht. Wie nützlich sie ist, hängt davon ab, wann sie fliegt – und ob sie überhaupt einen Fehler meldet. Die beiden Tests stammen aus Effective Java. Sie kompilieren, sind aber mit @Disabled abgeschaltet. Die Spielregel:

    1. Lies den Test und notiere Deine Erwartung.
    2. Entferne @Disabled und starte den Test.
    3. Erkläre jede Abweichung.
    4. Korrigiere den Test auf das tatsächliche Verhalten, bis er grün ist.

    Arbeitsschritte

    Das Paket anlegen

    Leg in Deinem Projekt aufbau unter src/test/java das Paket aufbau.exceptions an. Beide Tests dieser Übung kommen dort hinein.

    Vorhersagen, wann es knallt

    Speichere den Test als ExceptionTimeTest.java:

    package aufbau.exceptions;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.time.LocalDate;
import java.time.Period;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class ExceptionTimeTest {

    static class Person {

        private static final int ADULT_AGE = 18;

        private final String name;
        private final LocalDate birthDate;

        Person(String name, LocalDate birthDate) {
            this.name = name;
            this.birthDate = birthDate;
        }

        String getName() {
            return name;
        }

        LocalDate getBirthDate() {
            return birthDate;
        }

        boolean isAdult() {
            return Period.between(birthDate, LocalDate.now()).getYears() >= ADULT_AGE;
        }
    }

    @Test
    void personWithoutBirthDate() {
        Person person = new Person("Max", null);
        System.out.println("Person created: " + person.getName());

        // imagine many more lines of code here ...

        boolean adult = person.isAdult();
        assertEquals(false, adult);
    }
}

    Bevor Du startest: Läuft der Test durch? Wenn nicht – in welcher Zeile fliegt welche Exception, und wird Person created noch ausgegeben? Entferne @Disabled und starte den Test:

    mvn test -Dtest=ExceptionTimeTest

    Lies die Meldung der Exception genau: Welche Zeile nennt sie, und welche Zeile hat den Fehler verursacht?

    Den Fehler an den Anfang verlegen

    Eine Person ohne Geburtsdatum soll gar nicht erst entstehen. Ersetze den Test personWithoutBirthDate durch diesen:

    @Test
void personWithoutBirthDateIsRejected() {
    NullPointerException exception = assertThrows(NullPointerException.class, () -> new Person("Max", null));
    assertEquals("birthDate must not be null", exception.getMessage());
}

    Ergänze den Import import static org.junit.jupiter.api.Assertions.assertThrows; und starte den Test – er muss zuerst scheitern:

    mvn test -Dtest=ExceptionTimeTest

    Ändere dann den Konstruktor von Person so, dass er ein fehlendes Geburtsdatum mit Objects.requireNonNull und genau dieser Meldung ablehnt. Starte den Test erneut, bis er grün ist.

    Hinweis: Objects.requireNonNull gibt sein Argument zurück – Prüfen und Zuweisen passen in eine Zeile.

    Exceptions als Schleifenende messen

    Beide Tests laufen 100 000-mal über eine Liste mit zwei Elementen. Der erste hört auf, wenn next() eine NoSuchElementException wirft, der zweite fragt vorher hasNext(). Bevor Du startest: Schätze, um welchen Faktor die erste Variante langsamer ist. Speichere den Test als ExceptionControlFlowTest.java:

    package aufbau.exceptions;

import java.util.Iterator;
import java.util.List;
import java.util.NoSuchElementException;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class ExceptionControlFlowTest {

    static final int REPETITIONS = 100_000;
    static final List<String> MESSAGES = List.of("x", "y");

    @Test
    void stopWithException() {
        long start = System.nanoTime();
        for (int i = 0; i < REPETITIONS; i++) {
            Iterator<String> iterator = MESSAGES.iterator();
            try {
                while (true) {
                    iterator.next();
                }
            } catch (NoSuchElementException e) {
                // done
            }
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Exception: " + millis + " ms");
    }

    @Test
    void stopWithHasNext() {
        long start = System.nanoTime();
        for (int i = 0; i < REPETITIONS; i++) {
            Iterator<String> iterator = MESSAGES.iterator();
            while (iterator.hasNext()) {
                iterator.next();
            }
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("hasNext(): " + millis + " ms");
    }
}

    Entferne @Disabled und starte den Test:

    mvn test -Dtest=ExceptionControlFlowTest

    Die Laufzeiten stehen in der Konsole. Vergleiche sie mit Deiner Schätzung.

    Für Schnelle: Was ist erwachsen?

    Ein Geburtsdatum in der Zukunft ist ebenso unsinnig wie keines. Schreib einen Test, der dafür eine IllegalArgumentException erwartet, und erweitere den Konstruktor. Wie testest Du das, ohne dass der Test vom heutigen Datum abhängt?

    Reflexionsfragen

    • In welcher Zeile ist der Fehler entstanden, in welcher ist er aufgefallen – und was bedeutet der Abstand im echten Code?
    • Warum ist NullPointerException hier die richtige Exception – und wann wäre es IllegalArgumentException?
    • Warum ist die Schleife mit Exception so viel langsamer als die mit hasNext()?
    • Wo in Deinem Projekt prüft ein Konstruktor seine Argumente nicht – und wo fällt das dann auf?
