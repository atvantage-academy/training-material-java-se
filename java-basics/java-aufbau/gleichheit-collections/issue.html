    Zauberei mit Collections: Wo ist der Raum geblieben?

    User Story

    Als Entwickler:in der Raumbuchung möchte ich wissen, wann zwei Räume für Java gleich sind, damit meine Räume in HashSet und HashMap dort bleiben, wo ich sie abgelegt habe.

    Lernziele
    • Du sagst voraus, wie sich HashSet und List ohne eigenes equals und hashCode verhalten.
    • Du lässt equals und hashCode von der IDE erzeugen und entscheidest, welche Felder hineingehören.
    • Du erklärst, warum ein Objekt aus einem HashSet verschwindet, wenn sich ein Feld aus hashCode ändert.
    • Du misst, wie sich ein schlechter hashCode auf die Suche in einer HashMap auswirkt.
    Definition of Done
    • Room hat ein von der IDE erzeugtes equals und hashCode über die Raumnummer.
    • RoomSetTest und BookedRoomInASetTest sind grün, ohne dass Du ihre Assertions geändert hast.
    • Der Maven-Build läuft grün, auch die Abdeckungsregel für Room.
    • Du hast die beiden Laufzeiten aus HashCodePerformanceTest notiert und kannst den Unterschied erklären.
    • Du hast die Kontrollfragen beantwortet

    Ein HashSet soll Dubletten aussortieren, eine HashMap einen Raum wiederfinden. Beides verlässt sich auf equals und hashCode – und darauf, dass sie zueinander passen. Sonst ist ein Raum plötzlich doppelt da oder verschwindet.

    Hinweis: Ein Test bricht an der ersten Assertion ab, die nicht stimmt. Korrigier sie und starte erneut – so arbeitest Du Dich Zeile für Zeile vor.

    Arbeitsschritte

    Leg das Package an

    Du arbeitest mit dem Room aus Den Raum mit JUnit testen (Package aufbau.junit). Im Ordner src/test/java Deines Projekts java-aufbau lege das Package aufbau.collections an; alle Tests dieser Übung kommen dort hinein.

    Sag vorher, wie viele Räume im Set liegen

    Leg den Test RoomSetTest an:

    package aufbau.collections;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;

import aufbau.junit.Room;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class RoomSetTest {

    @Test
    void sameRoomTwiceInASet() {
        Set<Room> rooms = new HashSet<>();
        rooms.add(new Room("R111", "Berlin", 6));
        rooms.add(new Room("R111", "Berlin", 6));

        assertEquals(1, rooms.size());
    }

    @Test
    void findRoomInAList() {
        List<Room> rooms = List.of(new Room("R111", "Berlin", 6), new Room("R112", "Hamburg", 10));

        assertTrue(rooms.contains(new Room("R112", "Hamburg", 10)));
    }
}

    Was passiert, wenn Du die beiden Tests startest? Notier Deine Erwartung, entferne @Disabled und starte die Testklasse in der IDE. Erklär das Ergebnis – die Assertions bleiben diesmal, wie sie sind.

    Lass equals und hashCode erzeugen

    Lass Deine IDE in Room die Methoden equals und hashCode erzeugen – so, wie sie es vorschlägt, mit allen Feldern. Starte RoomSetTest erneut: Beide Tests sind jetzt grün, ohne dass Du eine Assertion geändert hast.

    Buche einen Raum, der im Set liegt

    Leg den Test BookedRoomInASetTest an:

    package aufbau.collections;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;

import aufbau.junit.Room;
import aufbau.junit.RoomAlreadyBookedException;
import java.time.LocalDate;
import java.util.HashSet;
import java.util.Set;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class BookedRoomInASetTest {

    @Test
    void bookARoomThatIsInASet() throws RoomAlreadyBookedException {
        Room berlin = new Room("R111", "Berlin", 6);
        Set<Room> rooms = new HashSet<>();
        rooms.add(berlin);

        berlin.book(LocalDate.of(2026, 3, 2));

        assertEquals(1, rooms.size());
        assertTrue(rooms.contains(berlin));
    }
}

    Was passiert, wenn Du einen Raum buchst, der schon im Set liegt? Notier Deine Erwartung, entferne @Disabled und starte den Test in der IDE. Erklär das Ergebnis.

    Lass danach equals und hashCode neu erzeugen – diesmal nur über die Raumnummer: Sie macht einen Raum aus, Name, Kapazität und Buchungen nicht. Starte den Test erneut: Er ist grün, ohne dass Du eine Assertion geändert hast. Baue danach erneut mit Maven.

    Hinweis: Scheitert der Build an der Abdeckungsregel für Room, hat Deine IDE in equals zusätzlich if (this == o) return true; erzeugt – ein Zweig, den kein Test durchläuft. Die Zeile ist nur eine Abkürzung; nimm sie heraus.

    Lösung

    So oder ähnlich erzeugt es die IDE; dazu der Import java.util.Objects. Manche IDEs prüfen zuerst noch this == o.

    @Override
public boolean equals(Object o) {
    if (o == null || getClass() != o.getClass()) {
        return false;
    }
    Room room = (Room) o;
    return Objects.equals(number, room.number);
}

@Override
public int hashCode() {
    return Objects.hashCode(number);
}

    Miss die Suche mit einem schlechten hashCode

    Der Test misst, wie lange es dauert, jeden von 20 000 Räumen in einer HashMap wiederzufinden – einmal mit dem erzeugten hashCode über die Raumnummer, einmal mit einem, der immer 1 liefert. Den schlechten hashCode bringt eine anonyme Unterklasse von Room mit, die nur im Test existiert. Leg den Test HashCodePerformanceTest an:

    package aufbau.collections;

import aufbau.junit.Room;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.HashMap;
import java.util.Map;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class HashCodePerformanceTest {

    // Adjust to your machine: smaller if the test runs too long, larger if the times are too short to compare.
    static final int NUMBER_OF_ROOMS = 20_000;

    static Room roomWithSameHashCode(String number) {
        return new Room(number, "Room " + number, 10) {
            @Override
            public int hashCode() {
                return 1;
            }
        };
    }

    @Test
    void searchWithCalculatedHashCode() {
        Map<Room, Integer> rooms = new HashMap<>();
        for (int i = 0; i < NUMBER_OF_ROOMS; i++) {
            rooms.put(new Room("R" + i, "Room " + i, 10), i);
        }
        long start = System.nanoTime();
        for (int i = 0; i < NUMBER_OF_ROOMS; i++) {
            assertEquals(i, rooms.get(new Room("R" + i, "Room " + i, 10)));
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Calculated hash code: " + millis + " ms");
    }

    @Test
    void searchWithSameHashCode() {
        Map<Room, Integer> rooms = new HashMap<>();
        for (int i = 0; i < NUMBER_OF_ROOMS; i++) {
            rooms.put(roomWithSameHashCode("R" + i), i);
        }
        long start = System.nanoTime();
        for (int i = 0; i < NUMBER_OF_ROOMS; i++) {
            assertEquals(i, rooms.get(roomWithSameHashCode("R" + i)));
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Same hash code:       " + millis + " ms");
    }
}

    Was erwartest Du für die beiden Laufzeiten? Notier Deine Schätzung, entferne @Disabled und starte den Test in der IDE. Die Laufzeiten stehen in der Konsole.

    Hinweis: Der Test misst nur grob – ein Lauf, ohne Aufwärmen der JVM. Für eine Größenordnung reicht das.

    Für Schnelle: Virtuelle Räume mit URL

    Für Online-Besprechungen gibt es virtuelle Räume. Sie sind gleich, wenn ihr Besprechungslink gleich ist. Leg im Ordner src/main/java das Package aufbau.collections an und darin die Klasse VirtualRoom – equals und hashCode hat die IDE über den Link erzeugt:

    package aufbau.collections;

import java.net.URL;
import java.util.Objects;

public class VirtualRoom {

    private final String name;
    private final URL meetingLink;

    public VirtualRoom(String name, URL meetingLink) {
        this.name = name;
        this.meetingLink = meetingLink;
    }

    public String getName() {
        return name;
    }

    public URL getMeetingLink() {
        return meetingLink;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) {
            return true;
        }
        if (o == null || getClass() != o.getClass()) {
            return false;
        }
        VirtualRoom that = (VirtualRoom) o;
        return Objects.equals(meetingLink, that.meetingLink);
    }

    @Override
    public int hashCode() {
        return Objects.hashCode(meetingLink);
    }
}

    Leg dazu den Test VirtualRoomSetTest an:

    package aufbau.collections;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.net.URI;
import java.util.HashSet;
import java.util.Set;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class VirtualRoomSetTest {

    private static final int ITERATIONS = 1_000;
    private static final int DISTINCT_ROOMS = 100;

    @Test
    void distinctVirtualRooms() throws Exception {
        long start = System.nanoTime();
        Set<VirtualRoom> rooms = new HashSet<>();
        for (int i = 0; i < ITERATIONS; i++) {
            int number = i % DISTINCT_ROOMS;
            String link = "https://meet" + number + ".example.com/room-" + number;
            rooms.add(new VirtualRoom("Online " + number, URI.create(link).toURL()));
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Set<VirtualRoom>: " + rooms.size() + " rooms, " + millis + " ms");

        assertEquals(DISTINCT_ROOMS, rooms.size());
    }
}

    Was erwartest Du für die Laufzeit? Entferne @Disabled und starte den Test in der IDE. Lies danach in der API-Dokumentation nach, was URL.equals und URL.hashCode mit dem Host tun. Stell VirtualRoom auf java.net.URI um und miss erneut.

    Reflexionsfragen

    • Warum sollten hashCode und equals nicht von den Raumbuchungen abhängen?
    • Warum ist die Suche mit einem konstanten hashCode so viel langsamer, obwohl equals korrekt ist?
