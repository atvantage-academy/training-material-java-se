    Wann sind zwei Objekte gleich?

    User Story

    Als Java-Entwickler:in möchte ich wissen, wann zwei Objekte für Java gleich sind, damit meine Objekte in HashSet und HashMap dort bleiben, wo ich sie abgelegt habe.

    Lernziele
    • Du sagst das Ergebnis von equals zwischen Ober- und Unterklasse voraus und begründest es.
    • Du prüfst eine equals-Implementierung gegen die Regeln reflexiv und symmetrisch.
    • Du erklärst, warum ein veränderter Schlüssel in einer HashMap nicht mehr gefunden wird.
    • Du misst, wie sich ein schlechter hashCode auf die Suche in einer HashMap auswirkt.
    Definition of Done
    • Das Paket aufbau.equality enthält die Tests EqualsContractTest, MutableKeyTest und HashCodePerformanceTest, keiner trägt mehr @Disabled.
    • Vor jedem Start hast Du Deine Erwartung notiert; jede Assertion beschreibt jetzt das tatsächliche Verhalten, und mvn test läuft grün.
    • Medium.equals ist symmetrisch, und zwei Bücher mit gleichen Daten sind gleich.
    • Du hast die beiden Laufzeiten aus HashCodePerformanceTest notiert und kannst den Unterschied erklären.
    • Du hast die Kontrollfragen beantwortet

    Ein HashSet soll Dubletten aussortieren, eine HashMap ein Objekt wiederfinden. Beides verlässt sich auf equals und hashCode – und darauf, dass sie zueinander passen. Die folgenden Tests stammen aus Effective Java. Jeder kompiliert, ist aber mit @Disabled abgeschaltet. Die Spielregel:

    1. Lies den Test und notiere Deine Erwartung als Kommentar neben jeder Assertion.
    2. Entferne @Disabled und starte den Test.
    3. Erkläre jede Abweichung.
    4. Korrigiere die Assertion auf das tatsächliche Verhalten, bis der Test grün ist.

    Hinweis: Ein Test bricht an der ersten Assertion ab, die nicht stimmt. Korrigier sie und starte erneut – so arbeitest Du Dich Zeile für Zeile vor.

    Arbeitsschritte

    Das Paket anlegen

    Leg in Deinem Projekt aufbau unter src/test/java das Paket aufbau.equality an. Alle Tests dieser Übung kommen dort hinein.

    Gleichheit zwischen Medium und Buch vorhersagen

    Zwei Medien gelten als gleich, wenn ihre ISBN übereinstimmt. Speichere den Test als EqualsContractTest.java:

    package aufbau.equality;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class EqualsContractTest {

    // Two media are equal if their ISBNs are equal.
    static class Medium {

        private String isbn;
        private String title;

        public String getIsbn() {
            return isbn;
        }

        public void setIsbn(String isbn) {
            this.isbn = isbn;
        }

        public String getTitle() {
            return title;
        }

        public void setTitle(String title) {
            this.title = title;
        }

        @Override
        public int hashCode() {
            final int prime = 31;
            int result = 1;
            result = prime * result + ((isbn == null) ? 0 : isbn.hashCode());
            result = prime * result + ((title == null) ? 0 : title.hashCode());
            return result;
        }

        @Override
        public boolean equals(Object obj) {
            if (this == obj)
                return true;
            if (obj == null)
                return false;
            if (Medium.class != obj.getClass())
                return false;
            Medium other = (Medium) obj;
            if (isbn == null) {
                if (other.isbn != null)
                    return false;
            } else if (!isbn.equals(other.isbn))
                return false;
            if (title == null) {
                if (other.title != null)
                    return false;
            } else if (!title.equals(other.title))
                return false;
            return true;
        }
    }

    static class Book extends Medium {

        private int pages;

        public int getPages() {
            return pages;
        }

        public void setPages(int pages) {
            this.pages = pages;
        }
    }

    Medium medium;
    Book book1;
    Book book2;

    @BeforeEach
    void createMedia() {
        medium = new Medium();
        medium.setIsbn("12345");
        medium.setTitle("A Book");

        book1 = new Book();
        book1.setIsbn("12345");
        book1.setTitle("A Book");
        book1.setPages(100);

        book2 = new Book();
        book2.setIsbn("12345");
        book2.setTitle("A Book");
        book2.setPages(100);
    }

    @Test
    void isReflexive() {
        assertEquals(true, medium.equals(medium));
        assertEquals(true, book1.equals(book1));
    }

    @Test
    void isSymmetric() {
        assertEquals(true, medium.equals(book1));
        assertEquals(true, book1.equals(medium));
    }

    @Test
    void twoEqualBooksAreEqual() {
        assertEquals(true, book1.equals(book2));
        assertEquals(true, book2.equals(book1));
    }
}

    Notier für die sechs Assertions Deine Erwartung, entferne @Disabled und starte den Test:

    mvn test -Dtest=EqualsContractTest

    equals reparieren

    Ändere Medium.equals so, dass die Symmetrie gilt und zwei Bücher mit gleichen Daten gleich sind. Probier beide Varianten aus und pass die Assertions jeweils an:

    • getClass() != obj.getClass() statt Medium.class != obj.getClass()
    • if (!(obj instanceof Medium other)) return false; – mit Pattern Matching

    Lass anschließend Deine Entwicklungsumgebung equals und hashCode neu erzeugen (IntelliJ: Code | Generate…, Eclipse: Source | Generate hashCode() and equals()) und vergleiche das Ergebnis mit Deiner Fassung.

    Hinweis: Die Aufgabe sagt „gleich, wenn die ISBN übereinstimmt“. Vergleicht equals das auch?

    Einen Schlüssel nach dem Einfügen ändern

    Speichere den Test als MutableKeyTest.java:

    package aufbau.equality;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.HashMap;
import java.util.Map;
import java.util.Objects;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class MutableKeyTest {

    static class Medium {

        private String isbn;

        public String getIsbn() {
            return isbn;
        }

        public void setIsbn(String isbn) {
            this.isbn = isbn;
        }

        @Override
        public int hashCode() {
            return Objects.hashCode(isbn);
        }

        @Override
        public boolean equals(Object obj) {
            if (this == obj) {
                return true;
            }
            if (obj == null || getClass() != obj.getClass()) {
                return false;
            }
            Medium other = (Medium) obj;
            return Objects.equals(isbn, other.isbn);
        }
    }

    @Test
    void changeKeyAfterPut() {
        Map<Medium, Integer> copies = new HashMap<>();
        Medium medium = new Medium();
        medium.setIsbn("12345");
        copies.put(medium, 3);

        assertEquals(3, copies.get(medium));

        medium.setIsbn("54321");

        assertEquals(3, copies.get(medium));
        assertEquals(1, copies.size());
    }

    @Test
    void searchWithOldKey() {
        Map<Medium, Integer> copies = new HashMap<>();
        Medium medium = new Medium();
        medium.setIsbn("12345");
        copies.put(medium, 3);
        medium.setIsbn("54321");

        Medium sameIsbnAsBefore = new Medium();
        sameIsbnAsBefore.setIsbn("12345");

        assertEquals(3, copies.get(sameIsbnAsBefore));
    }
}

    Notier Deine Erwartungen, entferne @Disabled und starte den Test:

    mvn test -Dtest=MutableKeyTest

    Die Suche mit einem schlechten hashCode messen

    Dieser Test misst, wie lange es dauert, jedes von 20 000 Medien in einer HashMap wiederzufinden – einmal mit berechnetem hashCode, einmal mit einem, der immer 1 liefert. Bevor Du startest: Schätze, um welchen Faktor die zweite Variante langsamer ist. Speichere den Test als HashCodePerformanceTest.java:

    package aufbau.equality;

import static org.junit.jupiter.api.Assertions.assertEquals;

import java.util.HashMap;
import java.util.Map;
import java.util.Objects;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class HashCodePerformanceTest {

    static final int NUMBER_OF_MEDIA = 20_000;

    static class Medium {

        private String isbn;

        public String getIsbn() {
            return isbn;
        }

        public void setIsbn(String isbn) {
            this.isbn = isbn;
        }

        @Override
        public int hashCode() {
            return Objects.hashCode(isbn);
        }

        @Override
        public boolean equals(Object obj) {
            if (this == obj) {
                return true;
            }
            if (obj == null || getClass() != obj.getClass()) {
                return false;
            }
            Medium other = (Medium) obj;
            return Objects.equals(isbn, other.isbn);
        }
    }

    static class MediumWithSameHashCode extends Medium {

        @Override
        public int hashCode() {
            return 1;
        }
    }

    @Test
    void searchWithCalculatedHashCode() {
        Map<Medium, Integer> media = new HashMap<>();
        for (int i = 0; i < NUMBER_OF_MEDIA; i++) {
            Medium medium = new Medium();
            medium.setIsbn("ISBN" + i);
            media.put(medium, i);
        }
        long start = System.nanoTime();
        for (int i = 0; i < NUMBER_OF_MEDIA; i++) {
            Medium query = new Medium();
            query.setIsbn("ISBN" + i);
            assertEquals(i, media.get(query));
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Calculated hash code: " + millis + " ms");
    }

    @Test
    void searchWithSameHashCode() {
        Map<Medium, Integer> media = new HashMap<>();
        for (int i = 0; i < NUMBER_OF_MEDIA; i++) {
            Medium medium = new MediumWithSameHashCode();
            medium.setIsbn("ISBN" + i);
            media.put(medium, i);
        }
        long start = System.nanoTime();
        for (int i = 0; i < NUMBER_OF_MEDIA; i++) {
            Medium query = new MediumWithSameHashCode();
            query.setIsbn("ISBN" + i);
            assertEquals(i, media.get(query));
        }
        long millis = (System.nanoTime() - start) / 1_000_000;
        System.out.println("Same hash code:       " + millis + " ms");
    }
}

    Entferne @Disabled und starte den Test:

    mvn test -Dtest=HashCodePerformanceTest

    Die Laufzeiten stehen in der Konsole. Vergleiche sie mit Deiner Schätzung.

    Hinweis: Der Test misst nur grob – ein Lauf, ohne Aufwärmen der JVM. Für eine Größenordnung reicht das.

    Für Schnelle: URLs in einem HashSet

    Aus 1 000 URLs mit zehn verschiedenen Hosts sollen die Dubletten verschwinden – einmal als Set<URL>, einmal als Set<String>. Bevor Du startest: Welche Variante ist schneller, und um wie viel? Speichere den Test als UrlSetPerformanceTest.java:

    package aufbau.equality;

import java.net.URI;
import java.net.URL;
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;

@Disabled("Predict the result first, then remove @Disabled")
class UrlSetPerformanceTest {

    static List<URL> createUrls() throws Exception {
        List<URL> urls = new ArrayList<>();
        for (int i = 0; i < 1_000; i++) {
            String address = "http://www.server" + (i % 10) + ".example.com/api";
            urls.add(URI.create(address).toURL());
        }
        return urls;
    }

    @Test
    void urlsInHashSet() throws Exception {
        List<URL> urls = createUrls();

        long start = System.nanoTime();
        Set<URL> distinctUrls = new HashSet<>(urls);
        long millis = (System.nanoTime() - start) / 1_000_000;

        System.out.println("Set<URL>:    " + distinctUrls.size() + " elements, " + millis + " ms");
    }

    @Test
    void urlStringsInHashSet() throws Exception {
        List<URL> urls = createUrls();

        long start = System.nanoTime();
        Set<String> distinctUrls = new HashSet<>();
        for (URL url : urls) {
            distinctUrls.add(url.toExternalForm());
        }
        long millis = (System.nanoTime() - start) / 1_000_000;

        System.out.println("Set<String>: " + distinctUrls.size() + " elements, " + millis + " ms");
    }
}

    Entferne @Disabled und starte den Test:

    mvn test -Dtest=UrlSetPerformanceTest

    Lies anschließend in der API-Dokumentation nach, was URL.equals und URL.hashCode mit dem Host tun.

    Hinweis: Dieser Test braucht eine Namensauflösung (DNS). Ohne Netz oder hinter einem restriktiven Proxy kann er sehr lange dauern – dann brich ihn ab; die Erklärung findest Du trotzdem in der API-Dokumentation.

    Reflexionsfragen

    • Warum ist book1.equals(medium) wahr, medium.equals(book1) aber falsch – und warum sind zwei gleiche Bücher nicht gleich?
    • getClass() != obj.getClass() oder instanceof – welche Variante wählst Du für Medium, und was gibst Du dafür auf?
    • Wo ist das Medium geblieben, nachdem Du seine ISBN geändert hast?
    • Warum ist die Suche mit einem konstanten hashCode so viel langsamer, obwohl equals korrekt ist?
    • Welche Klassen in Deinem Projekt landen als Schlüssel in einer HashMap oder in einem HashSet – und sind sie unveränderlich?
