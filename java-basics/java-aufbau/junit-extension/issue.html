    Eigene JUnit-Extension: Räume einspritzen und Tests messen

    User Story

    Als Java-Entwickler:in möchte ich wiederkehrende Vorbereitung und Querschnittsaufgaben meiner Tests in eine eigene Extension auslagern, damit die Testmethoden nur noch prüfen, worum es geht.

    Lernziele
    • Du schreibst einen ParameterResolver, der Testmethoden einen Parameter liefert.
    • Du schreibst eine Extension mit BeforeTestExecutionCallback und AfterTestExecutionCallback und legst Zwischenwerte im ExtensionContext.Store ab.
    • Du hängst Extensions mit @ExtendWith an eine Testklasse.
    Definition of Done
    • RoomExtensionTest läuft mit RoomParameterResolver grün; jeder Test bekommt einen frischen Raum.
    • TimingExtension gibt für jeden Test seine Dauer auf der Konsole aus.
    • Beide Extensions hängen mit einem @ExtendWith an der Testklasse.
    • ExceptionControlFlowTest misst nicht mehr von Hand, sondern mit @ExtendWith(TimingExtension.class).
    • Du hast die Kontrollfragen beantwortet

    Viele Tests beginnen gleich: einen Raum anlegen. Und manchmal will man für alle Tests dasselbe zusätzlich tun, etwa messen, wie lange sie laufen. Beides gehört nicht in jede Testmethode, sondern in eine Extension – so, wie JUnit selbst @TempDir umsetzt und Mockito seine MockitoExtension. Du arbeitest im Package aufbau.junit mit dem Room aus JUnit.

    Arbeitsschritte

    Kopiere den Test und das Gerüst

    Leg im Package aufbau.junit unter src/test/java die beiden Dateien an.

    RoomParameterResolver.java:

    package aufbau.junit;

import org.junit.jupiter.api.extension.ExtensionContext;
import org.junit.jupiter.api.extension.ParameterContext;
import org.junit.jupiter.api.extension.ParameterResolver;

// provides a fresh room "Seminar 1" for 12 persons to every test parameter of type Room
public class RoomParameterResolver implements ParameterResolver {

    @Override
    public boolean supportsParameter(ParameterContext parameterContext, ExtensionContext extensionContext) {
        return false; // TODO
    }

    @Override
    public Object resolveParameter(ParameterContext parameterContext, ExtensionContext extensionContext) {
        throw new UnsupportedOperationException("TODO");
    }
}

    RoomExtensionTest.java:

    package aufbau.junit;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertFalse;
import static org.junit.jupiter.api.Assertions.assertTrue;

import java.time.LocalDate;
import org.junit.jupiter.api.Disabled;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;

@Disabled("Remove @Disabled once you have implemented RoomParameterResolver")
@ExtendWith(RoomParameterResolver.class)
class RoomExtensionTest {

    private static final LocalDate MONDAY = LocalDate.of(2026, 3, 2);

    @Test
    void receivesARoom(Room room) {
        assertEquals("Seminar 1", room.getName());
        assertEquals(12, room.getCapacity());
    }

    @Test
    void firstTestBooksMonday(Room room) throws RoomAlreadyBookedException {
        room.book(MONDAY);
        assertTrue(room.isBooked(MONDAY));
    }

    @Test
    void secondTestGetsAFreshRoom(Room room) {
        assertFalse(room.isBooked(MONDAY));
    }
}

    Die Testmethoden haben einen Parameter – woher er kommt, entscheidet die Extension.

    Gib jedem Test einen frischen Raum

    Implementier die beiden Methoden von RoomParameterResolver: Die Extension ist für jeden Parameter vom Typ Room zuständig und liefert dafür einen neuen Raum Seminar 1 für 12 Personen. Entferne @Disabled an der Testklasse und mach die Tests grün.

    Hinweis: Den Parameter selbst liefert parameterContext.getParameter() – ein java.lang.reflect.Parameter mit getType().

    Lösung 
    @Override
public boolean supportsParameter(ParameterContext parameterContext, ExtensionContext extensionContext) {
    return parameterContext.getParameter().getType() == Room.class;
}

@Override
public Object resolveParameter(ParameterContext parameterContext, ExtensionContext extensionContext) {
    return new Room("R101", "Seminar 1", 12);
}

    Miss jeden Test

    Schreib im Package aufbau.junit unter src/test/java eine TimingExtension, die BeforeTestExecutionCallback und AfterTestExecutionCallback umsetzt: Vor dem Test merkt sie sich System.nanoTime(), danach gibt sie Namen und Dauer des Tests aus, etwa receivesARoom(Room) took 361 µs. Häng sie zusätzlich an RoomExtensionTest und starte die Tests.

    Hinweis: Zwischen den beiden Aufrufen merkst Du Dir die Startzeit im Store des ExtensionContext: context.getStore(namespace).put(…) und get(…, Long.class). Den Namespace legst Du einmal mit ExtensionContext.Namespace.create(TimingExtension.class) an. Den Namen des Tests liefert context.getDisplayName(). Mehrere Extensions nimmt @ExtendWith als Liste: @ExtendWith({ A.class, B.class }).

    Lösung 
    public class TimingExtension implements BeforeTestExecutionCallback, AfterTestExecutionCallback {

    private static final ExtensionContext.Namespace NAMESPACE =
            ExtensionContext.Namespace.create(TimingExtension.class);

    @Override
    public void beforeTestExecution(ExtensionContext context) {
        context.getStore(NAMESPACE).put("start", System.nanoTime());
    }

    @Override
    public void afterTestExecution(ExtensionContext context) {
        long start = context.getStore(NAMESPACE).get("start", Long.class);
        long micros = (System.nanoTime() - start) / 1_000;
        System.out.println(context.getDisplayName() + " took " + micros + " µs");
    }
}

    Ersetz die Messung von Hand

    In Exceptions: früh scheitern, nicht spät misst ExceptionControlFlowTest die Laufzeit von Hand: Startzeit merken, Differenz rechnen, ausgeben – in jedem Test aufs Neue. Genau das kann jetzt Deine TimingExtension.

    Häng sie mit @ExtendWith(TimingExtension.class) an ExceptionControlFlowTest (Package aufbau.exceptions) und entferne dort die Messung von Hand. Starte die Testklasse in der IDE und vergleich die Ausgabe mit den Werten von damals.

    Hinweis: TimingExtension liegt im Package aufbau.junit; im Test brauchst Du dafür einen Import.

    Für Schnelle: eine eigene Test-Annotation

    Schreib eine Annotation @RoomTest, die selbst mit @Test und @ExtendWith({ RoomParameterResolver.class, TimingExtension.class }) markiert ist, und ersetze damit an einer Methode @Test. Was ändert sich an der Testklasse? Wie eine Annotation geschrieben wird, ist Thema des Moduls Eigene Annotationen; hier genügt: @Retention(RetentionPolicy.RUNTIME), @Target(ElementType.METHOD) und public @interface RoomTest { }.
