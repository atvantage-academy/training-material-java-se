    Das Banking-Diagramm in Java

    Als Entwickler:in möchte ich mein Klassendiagramm in Java-Code übertragen, damit aus den gezeichneten Kästchen ein Programm wird, das ich starten kann.

    Lernziele

    • Du übersetzt Kästchen in Klassen, Eigenschaften in Instanzvariablen und Fähigkeiten in Methoden.
    • Du erzeugst mit new mehrere Objekte einer Klasse und gibst ihnen eigene Werte.
    • Du setzt eine Beziehung aus dem Diagramm als Referenz auf ein anderes Objekt um.
    • Du machst die Ausgabe eines Objekts mit toString() lesbar.

    Definition of Done

    • Für jedes Kästchen Deines Diagramms gibt es eine Klasse in einer eigenen Datei.
    • Die Eigenschaften stehen als Instanzvariablen, mindestens eine Fähigkeit je Klasse als Methode darin.
    • Die Beziehung aus dem Diagramm ist im Code umgesetzt.
    • In Main entstehen Beispielobjekte: Werte setzen, wieder abfragen, ausgeben.
    • Beide Klassen haben ein toString(), das die wichtigsten Werte ausgibt.
    • Das Programm startet und läuft fehlerfrei.
    • Du hast die Kontrollfragen beantwortet

    Hinweis: Du machst hier dasselbe wie der Trainer eben in der Demo – nur mit Deinem eigenen Diagramm zur Bank. Die Visualisierung Objektorientierung mit Java (einfach) (unter „Weiterführende Informationen“) zeigt jeden Baustein noch einmal an einem anderen Beispiel. Schlag dort nach, statt zu fragen.

    Hinweis: Konstruktoren, private, Getter und Setter brauchst Du hier noch nicht – die Variablen bleiben ohne Vorsatz und werden direkt gesetzt. Das ist Absicht: Wir halten die Sprache klein, bis das Prinzip sitzt.

    Arbeitsschritte

    Die Klassen anlegen

    Nimm Dein Klassendiagramm von gestern und übersetze es Kästchen für Kästchen: jede Klasse in eine eigene Datei, die genauso heißt wie die Klasse. Die Eigenschaften aus dem Kästchen werden zu Instanzvariablen, die Fähigkeiten zu Methoden.

    Hinweis: Der Name einer Variablen wird im Kontext ihrer Klasse gelesen. In Konto genügt deshalb stand statt kontostand – der Klassenname steht ja schon davor.

    Hinweis: Führe den Kontostand als ganze Cent in einem long – so, wie es schon der prozedurale Ausschnitt vom Vortag getan hat und wie es der Merksatz aus Java-Syntax auf einen Blick verlangt: double rundet ungenau, für Geld ist das untauglich. Die Einheit gehört dann auch in den Namen: standInCent.

    Die Beziehung umsetzen

    In Deinem Diagramm verbindet eine Linie zwei Kästchen. Überlege, wie diese Linie im Code aussieht, und setze sie um.

    Beispielobjekte in main erzeugen

    Leg eine Klasse Main mit einer main-Methode an. Erzeuge dort mit new mehrere Beispielobjekte, setz ihre Werte, ruf eine Methode auf und gib die Werte anschließend wieder aus.

    Hinweis: Nimm bewusst mehr als ein Objekt derselben Klasse und gib ihnen unterschiedliche Werte. Dann siehst Du an der Ausgabe, was eine Instanzvariable ausmacht.

    Die Ausgabe lesbar machen

    Gib einmal ein ganzes Objekt aus – die Ausgabe sieht aus wie Konto@1b6d3586, also Klassenname und eine interne Kennung. Ergänze in beiden Klassen ein toString() und lass dieselbe Zeile noch einmal laufen.

    Hinweis: toString() wird automatisch benutzt, sobald ein Objekt als Text gebraucht wird – Du musst es nicht selbst aufrufen. Damit beschreibt sich die Klasse selbst, statt dass jede Ausgabestelle die Felder einzeln zusammensetzt.

    Anregung: mit dem Debugger hineinschauen

    Den Debugger kennst Du aus Tag 1 – jetzt lohnt er sich richtig. Setz in main einen Breakpoint auf die erste Zeile und lass das Programm dann Schritt für Schritt laufen. Sieh Dir nach jeder Zeile im Variablen-Fenster an, was sich verändert hat.

    Achte dabei auf drei Dinge:

    • Wie stellt der Debugger ein Objekt dar? Vor dem new steht dort null, danach etwas wie Konto@1b6d3586 – dieselbe kryptische Form, die Du auch bei System.out.println gesehen hast.
    • Klapp das Objekt auf. Darin stecken genau die Instanzvariablen, die Du deklariert hast – mit ihren aktuellen Werten. Sieh zu, wie sich der Stand beim Aufruf Deiner Methode ändert.
    • Folge der Beziehung. Hinter der Referenz steht kein Text, sondern wieder ein Objekt, das sich seinerseits aufklappen lässt.

    Hinweis: Sobald toString() existiert, zeigen die meisten IDEs im Variablen-Fenster diese Textform statt Klasse@Kennung – ein Grund mehr für eine gute toString()-Methode.

    Für Schnelle

    • Ergänze eine zweite Methode, die etwas prüft, bevor sie den Zustand ändert – zum Beispiel Abheben nur bis zur Höhe des Guthabens.
    • Bau eine Methode, mit der ein Kunde umzieht, und ruf sie auf. Gib den Wohnort davor und danach aus.
    • Gib in toString() auch etwas aus dem verbundenen Objekt mit aus.

    Reflexionsfragen

    • Wie ist der Zusammenhang zwischen Klassen und Objekten? Erkläre beispielhaft.
    • Wie werden Beziehungen zwischen Klassen im Code umgesetzt?
    • Wofür war toString() gut?
