    Das Banking-Beispiel modernisieren

    Als Entwickler:in möchte ich meinen Code mit den Sprachmitteln von heute schreiben, damit er kürzer wird und der Compiler mehr für mich prüft.

    Hinweis: Sichere Deinen Stand, bevor Du anfängst – mit einem Git-Commit oder einer Kopie des Projekts. Der Umbau berührt viele Stellen.

    Lernziele

    Du…

    • überführst eine bestehende Klasse in einen Record und passt ihre Aufrufer an.
    • versiegelst eine Klassenhierarchie mit sealed und permits.
    • schreibst eine Switch-Expression mit Typmustern, die ohne default vollständig ist.
    • setzt var und einen Text-Block dort ein, wo sie den Code lesbarer machen.

    Definition of Done

    • Buchung ist ein Record; ein kompakter Konstruktor weist einen Betrag von 0 zurück.
    • Konto ist versiegelt und nennt seine erlaubten Unterklassen.
    • Eine Methode liefert per Switch-Expression über die Kontoart eine Beschreibung – ohne default.
    • Mindestens zwei lokale Variablen verwenden var, wo der Typ offensichtlich ist.
    • Ein Kontoauszug wird mit einem Text-Block ausgegeben.
    • Eine vierte Kontoart ist ergänzt, und alle Stellen, die der Compiler meldet, sind nachgezogen.
    • Das Programm startet und läuft fehlerfrei.
    • Du hast die Reflexionsfragen schriftlich beantwortet.

    Arbeitsschritte

    Die Buchung als Record

    Mach aus Buchung einen Record. Lass einen Betrag von 0 im kompakten Konstruktor nicht zu.

    public record Buchung(long betragInCent, String verwendungszweck) {
    public Buchung {
        if (betragInCent == 0) {
            throw new IllegalArgumentException("Eine Buchung über 0 Cent gibt es nicht.");
        }
    }
}

    Hinweis: Die Felder Deiner bisherigen Klasse heißen vielleicht anders – übernimm Deine Namen. Danach meldet der Compiler die Aufrufer: Die Zugriffsmethoden eines Records heißen wie die Komponente, ohne get.

    Hinweis: Was ist mit equals, hashCode und toString passiert, die Du vielleicht geschrieben hattest?

    Die Kontenhierarchie versiegeln

    Erlaube für Konto nur die Unterklassen, die es gibt.

    Hinweis: Jede erlaubte Unterklasse muss sich ihrerseits festlegen: final, sealed oder non-sealed. Was passt zu Giro- und Sparkonto?

    Die Kontoart beschreiben

    Schreib eine Methode beschreibe(Konto konto), die per Switch-Expression einen Text zurückgibt – beim Girokonto mit Dispolimit, beim Sparkonto mit Habenzins.

    static String beschreibe(Konto konto) {
    return switch (konto) {
        case Girokonto giro -> "Girokonto, Dispo " + giro.getDispolimitInCent() / 100 + " €";
        // …
    };
}

    Hinweis: Kein default. Probier aus, was passiert, wenn Du einen case weglässt.

    var und ein Text-Block

    Ersetz lokale Variablen durch var, wo der Typ auf derselben Zeile steht. Gib einen Kontoauszug – IBAN, Inhaber:in, Stand – mit einem Text-Block und formatted(…) aus.

    Hinweis: Wo würdest Du var nicht einsetzen? Such Dir bewusst eine Stelle, an der es den Code schlechter macht.

    Eine vierte Kontoart

    Ergänze ein Tagesgeldkonto (oder eine Kontoart Deiner Wahl). Folge den Meldungen des Compilers, bis alles wieder läuft.

    Hinweis: Zähl mit, wie viele Stellen der Compiler Dir meldet – und überleg, wie Du sie ohne versiegelte Hierarchie gefunden hättest.

    Für Schnelle

    • Nutze instanceof mit Bindung an einer Stelle, an der Du bisher gecastet hast.
    • Mach aus dem Ergebnis einer Auswertung aus Lambdas & Streams einen Record, statt eine Map herumzureichen.

    Reflexionsfragen

    • Warum kann Konto kein Record werden, Buchung aber schon?
    • Wo hat var Deinen Code lesbarer gemacht, wo schlechter?
    • Was ist passiert, als Du die vierte Kontoart ergänzt hast – und warum steht im switch kein default?
    • Welches dieser Sprachmittel kennst Du aus Deiner bisherigen Sprache, und was macht Java anders?
