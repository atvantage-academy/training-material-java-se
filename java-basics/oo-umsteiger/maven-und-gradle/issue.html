    Dasselbe Projekt mit Maven bauen

    Als Entwickler:in möchte ich ein Java-Projekt mit Maven genauso bauen können wie mit Gradle, damit mich in einem neuen Projekt keines der beiden Werkzeuge aufhält.

    Lernziele

    • Du ergänzt ein bestehendes Projekt um eine pom.xml und baust es mit Maven.
    • Du deklarierst dieselbe Abhängigkeit in Maven und in Gradle.
    • Du ordnest Maven-Phasen und Gradle-Tasks einander zu.
    • Du erkennst an einem Projekt, welches Build-Werkzeug es benutzt.

    Definition of Done

    • Im Gradle-Projekt aus Build & Ökosystem liegt zusätzlich eine pom.xml.
    • Die Bibliothek aus Build & Ökosystem ist auch in der pom.xml deklariert.
    • mvn package baut das Projekt ohne Fehler.
    • Die Vergleichstabelle unten ist ausgefüllt.
    • Du hast die Kontrollfragen beantwortet

    Arbeitsschritte

    Die pom.xml anlegen

    Leg im Projektwurzelverzeichnis eine pom.xml an. Für den Anfang genügt das Gerüst:

    <project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>de.beispiel</groupId>
  <artifactId>banking</artifactId>
  <version>1.0-SNAPSHOT</version>

  <properties>
    <maven.compiler.release>21</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
</project>

    Hinweis: Übernimm groupId und version aus Deiner Gradle-Datei, und setz die Java-Version auf die, mit der Du arbeitest.

    Hinweis: Das Encoding ist wichtig: Deine Bezeichner enthalten Umlaute.

    Bauen

    Bau das Projekt mit Maven – auf der Kommandozeile oder über die Maven-Unterstützung Deiner IDE:

    mvn package

    Sieh Dir an, wohin Maven das Ergebnis schreibt.

    Hinweis: Du hast keine einzige Datei verschoben. Warum findet Maven Deinen Code trotzdem?

    Die Abhängigkeit übertragen

    Übertrag die Bibliothek, die Du in Build & Ökosystem eingebunden hast, in die pom.xml. Die Koordinaten stehen in Deiner Gradle-Datei.

    Hinweis: In Gradle stehen die Koordinaten in einer Zeile mit Doppelpunkten, in Maven als drei Elemente. Es sind dieselben drei Angaben.

    Die Werkzeuge gegenüberstellen

    Füll die Tabelle aus – aus dem, was Du gerade gemacht hast:

    Frage Maven Gradle
    Name der Build-Datei
    Wo landet das Ergebnis?
    Projekt bauen
    Tests ausführen
    Abhängigkeit nur für Tests
    Woran erkennst Du das Werkzeug in einem fremden Projekt?

    Für Schnelle

    • Ergänze JUnit als Test-Abhängigkeit in der pom.xml und führ die Tests aus:

      mvn test

    • Lass Dir die Abhängigkeiten von Maven anzeigen:

      mvn dependency:tree

      Lass sie Dir dann von Gradle anzeigen und vergleich die Ausgaben:

      gradle dependencies

    Reflexionsfragen

    • Warum musstest Du keine Datei verschieben, als Maven dazukam?
    • Woher holen beide Werkzeuge die Bibliothek – und was haben die Koordinaten damit zu tun?
    • Warum gibt es in einem echten Projekt trotzdem nur eine Build-Datei?
    • Wie bindet Deine bisherige Plattform eine Bibliothek ein, und wo steht dort die Version?
