Collections-API

Listen, Mengen und Zuordnungen – die zehn Typen, die Du im Alltag wirklich brauchst. Klicke einen Typ an: Du bekommst seine Besonderheiten, bei den konkreten Klassen ein Beispiel mit echter Ausgabe und einen Blick darauf, wie er intern gebaut ist. Darunter stehen die Grundgriffe, die für alle gelten.

erweitert (Interface → Interface) implementiert (Klasse → Interface) Kursiv mit «interface»: nur Vertrag · Kasten mit Streifen: konkrete Klasse, die Du mit new erzeugst

Interface

Collection<E>

Der gemeinsame Nenner aller Listen und Mengen.

Erklärung

Was es ist

Collection beschreibt, was jede Gruppe von Elementen kann: hinzufügen, entfernen, nachsehen, zählen, durchlaufen. Es sagt aber nichts darüber, ob es eine Reihenfolge gibt und ob Duplikate erlaubt sind – das legen erst List und Set fest. Einen Index gibt es hier deshalb nicht.

Ein Interface kannst Du nicht mit new erzeugen. Du verwendest es als Typ einer Variablen oder eines Parameters – das Objekt dahinter ist immer eine konkrete Klasse:

Collection<String> obst = new ArrayList<>();   // links allgemein, rechts konkret

int zähleLange(Collection<String> wörter) {   // nimmt jede Liste UND jede Menge
    int anzahl = 0;
    for (String w : wörter) {
        if (w.length() > 4) anzahl++;
    }
    return anzahl;
}

Stärken

  • Eine Methode mit Collection-Parameter funktioniert mit jeder Liste und jeder Menge.
  • Erbt von Iterable – deshalb geht die for-each-Schleife über jede Collection.

Stolpersteine

  • contains und remove vergleichen mit equals – bei eigenen Klassen musst Du es überschreiben.
  • Map ist keine Collection: Sie hat Schlüssel und Werte, also kein add(E).

Wann verwenden? Als Parametertyp, wenn eine Methode nur durchlaufen, zählen oder nachsehen will – und ihr egal ist, ob eine Liste oder eine Menge hereinkommt.

Interface

List<E>

Eine Folge mit fester Reihenfolge und Index.

Erklärung

Was es ist

Eine List merkt sich die Reihenfolge, in der Du einfügst, und gibt jedem Element eine Position (Index ab 0). Duplikate sind erlaubt – dasselbe Element darf mehrfach vorkommen.

Stärken

  • Zugriff und Änderung an einer bestimmten Stelle: get(i), set(i, e), add(i, e).
  • Die Reihenfolge ist verlässlich – die Ausgabe sieht aus wie die Eingabe.
  • Seit Java 21 auch getFirst() und getLast().

Stolpersteine

  • remove hat zwei Bedeutungen. Bei List<Integer> entfernt remove(1) die Stelle 1, nicht die Zahl 1 (siehe Reiter „Methoden“).
  • Ein falscher Index wirft IndexOutOfBoundsException.
  • Eindeutigkeit prüft sie nicht – dafür gibt es Set.

Wann verwenden? Wenn die Reihenfolge zählt oder Elemente mehrfach vorkommen dürfen: ein Buchungsverlauf, die Positionen einer Bestellung, eine Rangliste. Als Implementierung im Zweifel ArrayList.

Methoden

Alles aus Collection, dazu der Zugriff über die Position:

MethodeWas sie tut
get(int index)liest das Element an der Stelle
set(int index, E e)ersetzt das Element an der Stelle, liefert das alte
add(int index, E e)fügt an der Stelle ein, der Rest rückt nach hinten
remove(int index)entfernt die Stelle, liefert das entfernte Element
indexOf(Object o)erste Position des Elements, sonst -1
List<String> obst = new ArrayList<>(List.of("Birne", "Apfel", "Kiwi"));
System.out.println(obst.get(0));          // Birne
System.out.println(obst.indexOf("Kiwi")); // 2
System.out.println(obst.set(1, "Mango")); // Apfel
System.out.println(obst);                 // [Birne, Mango, Kiwi]

Die remove-Falle bei Zahlen

List<Integer> zahlen = new ArrayList<>(List.of(10, 20, 30));
zahlen.remove(1);                    // int → remove(int index)
System.out.println(zahlen);          // [10, 30]
zahlen.remove(Integer.valueOf(10));  // Objekt → remove(Object o)
System.out.println(zahlen);          // [30]
Interface

Set<E>

Eine Menge – jedes Element höchstens einmal.

Erklärung

Was es ist

Ein Set ist eine Menge im mathematischen Sinn: keine Duplikate. Ein zweites add mit einem gleichen Element ändert nichts und liefert false. Neue Methoden bringt Set nicht mit – es verschärft nur die Regeln von Collection.

Ob es eine Reihenfolge gibt, entscheidet die Implementierung: HashSet gar keine verlässliche, TreeSet eine sortierte, LinkedHashSet die Einfügereihenfolge.

Stärken

  • Eindeutigkeit ohne eigenen Prüfcode.
  • contains ist schnell (Hash: konstant, Baum: logarithmisch) – viel schneller als in einer Liste.
  • Duplikate aus einer Liste entfernen: new HashSet<>(liste).

Stolpersteine

  • Was „gleich“ ist, bestimmen equals/hashCode (HashSet) bzw. compareTo/Comparator (TreeSet).
  • Kein Index: kein get(i).

Wann verwenden? Wenn jedes Element nur einmal zählen soll oder Du schnell fragen willst „ist das schon drin?“: Kunden-IDs, besuchte Seiten, vergebene Benutzernamen.

Methoden

Dieselben wie Collection – nur mit strengerer Bedeutung:

MethodeBedeutung im Set
add(E e)false, wenn ein gleiches Element schon da ist – es wird nicht ersetzt
contains(Object o)die Kernfrage einer Menge – und schnell
remove(Object o)entfernt das Element (es gibt höchstens eines)
size()Anzahl verschiedener Elemente
addAll / retainAll / removeAllVereinigung, Schnittmenge, Differenz – siehe Mengenoperationen
Interface

Map<K, V>

Zuordnung Schlüssel → Wert, zum Nachschlagen.

Erklärung

Was es ist

Eine Map ordnet jedem Schlüssel (K) genau einen Wert (V) zu – wie ein Wörterbuch. Schlüssel sind eindeutig, Werte dürfen sich wiederholen. Ein put mit einem vorhandenen Schlüssel überschreibt den alten Wert.

Eine Map ist keine Collection – deshalb steht sie im Diagramm daneben. Sie liefert aber Collection-Sichten auf ihren Inhalt: keySet(), values() und entrySet(); darüber wird sie auch durchlaufen.

Stärken

  • Nachschlagen per Schlüssel statt Suchen in einer Liste.
  • getOrDefault erspart die null-Prüfung.

Stolpersteine

  • get liefert null, wenn der Schlüssel fehlt – oder wenn der Wert null ist.
  • Schlüssel sollten unveränderlich sein (String, Integer, Records).
  • Suchen nach einem Wert (containsValue) läuft alles durch.

Wann verwenden? Wenn Du über etwas Eindeutiges nachschlagen willst: IBAN → Konto, Artikelnummer → Artikel, Wort → Häufigkeit.

Methoden
MethodeWas sie tut
put(K key, V value)legt ab oder überschreibt; liefert den alten Wert oder null
get(Object key)Wert zum Schlüssel oder null
getOrDefault(key, ersatz)Wert oder der Ersatzwert
remove(Object key)entfernt den Eintrag, liefert den Wert
containsKey(Object key)Schlüssel vorhanden?

Map<String, Integer> bestand = new HashMap<>();
bestand.put("Birne", 3);
bestand.put("Apfel", 5);
bestand.put("Kiwi", 2);
System.out.println(bestand.keySet());           // [Birne, Kiwi, Apfel]
System.out.println(bestand.values());           // [3, 2, 5]
System.out.println(bestand.containsKey("Kiwi")); // true
System.out.println(bestand.remove("Kiwi"));      // 2
System.out.println(bestand);                     // {Birne=3, Apfel=5}
Klasse · implementiert List

ArrayList<E>

Die Standard-Liste: ein Array, das von selbst wächst.

Erklärung

Besonderheiten

Behält die Einfügereihenfolge, erlaubt Duplikate und null. Der Zugriff über den Index ist sofort da, egal wie lang die Liste ist – weil intern ein Array steckt.

Stärken

  • get(i) und set(i, e) in konstanter Zeit.
  • add am Ende ist im Mittel schnell.
  • Kompakt im Speicher; Durchlaufen ist sehr schnell.

Stolpersteine

  • Einfügen oder Löschen am Anfang oder in der Mitte verschiebt alle folgenden Elemente.
  • contains und indexOf laufen die Liste von vorn durch.
  • Nicht für gleichzeitigen Zugriff aus mehreren Threads gedacht.

Wann verwenden? Fast immer, wenn Du eine Liste brauchst. Sie ist die richtige Vorgabe, bis eine Messung etwas anderes sagt.

Codebeispiel

Nach jedem add die Ausgabe: Die Reihenfolge bleibt, das zweite "Apfel" wird aufgenommen.

List<String> obst = new ArrayList<>();

obst.add("Birne");  System.out.println(obst);  // [Birne]
obst.add("Apfel");  System.out.println(obst);  // [Birne, Apfel]
obst.add("Kiwi");   System.out.println(obst);  // [Birne, Apfel, Kiwi]
obst.add("Apfel");  System.out.println(obst);  // [Birne, Apfel, Kiwi, Apfel]  ← Duplikat bleibt

System.out.println(obst.get(1));   // Apfel
System.out.println(obst.size());   // 4

obst.remove("Apfel");    System.out.println(obst);  // [Birne, Kiwi, Apfel]  ← nur das erste
obst.add(0, "Mango");    System.out.println(obst);  // [Mango, Birne, Kiwi, Apfel]
Interne Umsetzung

Eine ArrayList besteht aus einem gewöhnlichen Array (Object[] elementData) und einem Zähler size. Das Array ist meist größer als nötig – die freien Plätze sind Reserve für die nächsten add.

Nach den vier add: size = 4, Kapazität = 10
0"Birne"

3"Apfel"

get(2) rechnet nur die Adresse von Platz 2 aus – deshalb ist der Zugriff sofort da.

Was bei den Operationen passiert

  • add(e) am Ende: nächster freier Platz, size++. Ist das Array voll, wird ein neues mit rund 1,5-facher Größe angelegt (10 → 15 → 22 …) und alles hinüberkopiert. Das ist selten, deshalb ist add im Mittel trotzdem schnell.
  • add(0, e) / remove(0): Alle Elemente dahinter rücken um einen Platz (System.arraycopy). Bei einer Million Elemente ist das eine Million Verschiebungen.
  • contains / indexOf: vergleicht von vorn mit equals, bis es passt.

Weißt Du vorher, wie viele Elemente kommen, spart new ArrayList<>(1_000) das wiederholte Umkopieren.
Klasse · implementiert List (und Deque)

LinkedList<E>

Eine Kette von Knoten, die einander kennen.

Erklärung

Besonderheiten

Nach außen eine ganz normale List: Reihenfolge, Duplikate, Index. Zusätzlich ist sie eine Warteschlange mit zwei Enden (Deque): addFirst, addLast, removeFirst, peekFirst …

Stärken

  • Einfügen und Entfernen an beiden Enden in konstanter Zeit.
  • Kein Umkopieren beim Wachsen.
  • Einfügen/Löschen über einen Iterator mitten in der Liste, ohne zu verschieben.

Stolpersteine

  • get(i) muss Knoten für Knoten laufen. Eine for-Schleife mit get(i) wird dadurch quadratisch langsam.
  • Mehr Speicher je Element (Knotenobjekt mit zwei Verweisen).
  • In der Praxis meist langsamer als ArrayList, auch beim Durchlaufen.

Wann verwenden? Selten. Wenn Du hauptsächlich vorn und hinten einfügst und entnimmst. Für eine reine Warteschlange ist ArrayDeque meist die bessere Wahl.

Codebeispiel

Wie eine Liste – plus Einfügen am Anfang. Duplikate bleiben auch hier.

LinkedList<String> schlange = new LinkedList<>();

schlange.add("Birne");       System.out.println(schlange);  // [Birne]
schlange.add("Apfel");       System.out.println(schlange);  // [Birne, Apfel]
schlange.addFirst("Kiwi");   System.out.println(schlange);  // [Kiwi, Birne, Apfel]  ← vorn
schlange.add("Apfel");       System.out.println(schlange);  // [Kiwi, Birne, Apfel, Apfel]  ← Duplikat bleibt

System.out.println(schlange.get(2));          // Apfel  (läuft die Kette ab, hier vom Ende her)
System.out.println(schlange.removeFirst());   // Kiwi
System.out.println(schlange);                 // [Birne, Apfel, Apfel]
Interne Umsetzung

Jedes Element steckt in einem eigenen Knoten (Node) mit drei Feldern: dem Element selbst, einem Verweis auf den Vorgänger (prev) und einem auf den Nachfolger (next). Die Liste kennt nur den ersten und den letzten Knoten.

Doppelt verkettet: [Kiwi, Birne, Apfel, Apfel]
first → prev"Kiwi"next ⇄ prev"Birne"next ⇄ prev"Apfel"next ⇄ prev"Apfel"next ← last
Die Knoten liegen irgendwo im Speicher – zusammengehalten nur durch die Verweise. 
private static class Node<E> {   // so steht es im JDK
    E item;
    Node<E> next;
    Node<E> prev;
}

Was bei den Operationen passiert

  • addFirst / addLast / removeFirst: neuen Knoten anlegen bzw. lösen und zwei, drei Verweise umbiegen – unabhängig von der Länge.
  • get(i): läuft ab first (oder ab last, wenn i in der hinteren Hälfte liegt) Verweis für Verweis bis zur Stelle.
  • add(i, e) in der Mitte: Das Umhängen selbst ist billig – aber erst muss die Stelle gefunden werden, und das ist wieder ein Lauf durch die Kette.
Klasse · implementiert Set

HashSet<E>

Die schnelle Menge – ohne Reihenfolge.

Erklärung

Besonderheiten

Keine Duplikate, und keine verlässliche Reihenfolge: Die Ausgabe folgt der internen Ablage, nicht der Einfügereihenfolge – und kann sich ändern, wenn die Menge wächst. Ein null ist erlaubt.

Stärken

  • add, remove und contains im Mittel in konstanter Zeit – auch bei Millionen Elementen.
  • Die richtige Vorgabe für ein Set.

Stolpersteine

  • Eigene Klassen brauchen equals UND hashCode. Fehlt hashCode, gelten zwei gleiche Objekte als verschieden.
  • Ändert sich ein Feld, das in den Hash eingeht, findet das Set das Objekt nicht mehr.
  • Brauchst Du eine Reihenfolge: LinkedHashSet (Einfügen) oder TreeSet (sortiert).

Wann verwenden? Wenn Eindeutigkeit zählt und die Reihenfolge egal ist: Kunden-IDs, Schlagwörter, „schon gesehen?“-Prüfungen.

Codebeispiel

Dieselben Daten wie bei der Liste. Achte auf zwei Dinge: das zweite "Apfel" wird abgelehnt, und "Kiwi" landet nicht am Ende.

Set<String> obst = new HashSet<>();

System.out.println(obst.add("Birne"));  // true
System.out.println(obst);               // [Birne]
System.out.println(obst.add("Apfel"));  // true
System.out.println(obst);               // [Birne, Apfel]
System.out.println(obst.add("Kiwi"));   // true
System.out.println(obst);               // [Birne, Kiwi, Apfel]  ← nicht Einfügereihenfolge
System.out.println(obst.add("Apfel"));  // false                 ← Duplikat abgelehnt
System.out.println(obst);               // [Birne, Kiwi, Apfel]

System.out.println(obst.contains("Kiwi"));  // true
System.out.println(obst.size());            // 3

Warum gerade diese Reihenfolge? Das zeigt der Reiter „Interne Umsetzung“.

Interne Umsetzung

Ein HashSet ist eine Hash-Tabelle: ein Array von „Eimern“ (Buckets). In welchen Eimer ein Element gehört, berechnet sich aus seinem hashCode(). (Genau genommen benutzt HashSet intern eine HashMap und legt die Elemente als deren Schlüssel ab.)

Die Ausgabe läuft die Plätze von vorn ab – daher [Birne, Kiwi, Apfel].
Wächst die Tabelle, ändern sich die Plätze – und damit die Ausgabereihenfolge.

So arbeiten hashCode und equals zusammen

  1. hashCode() wählt den Eimer. Nur dieser eine Eimer wird angesehen – deshalb ist die Suche so schnell.
  2. equals() entscheidet im Eimer. Verschiedene Objekte können im selben Eimer landen (Kollision, z. B. haben "Aa" und "BB" beide den Hash 2112). Dann wird mit equals verglichen.
  3. Ist ein gleiches Element schon da, lehnt add ab (false).

Der Vertrag: Gleiche Objekte (equals liefert true) müssen denselben hashCode haben. Sonst landen sie in verschiedenen Eimern und werden nie verglichen – das Set enthält dann „gleiche“ Objekte doppelt.

class Kunde {
    private final String nummer;   // fachliche Identität, ändert sich nie
    private String name;

    @Override
    public boolean equals(Object o) {
        return o instanceof Kunde k && nummer.equals(k.nummer);
    }

    @Override
    public int hashCode() {
        return Objects.hash(nummer);  // dieselben Felder wie in equals
    }
}

Wachstum

Die Tabelle startet mit 16 Plätzen. Ist sie zu drei Vierteln gefüllt (Ladefaktor 0,75 – hier also beim 13. Element), wird sie verdoppelt und jedes Element neu einsortiert. Deshalb kann sich die Ausgabereihenfolge ändern, wenn die Menge wächst. Läuft ein Eimer durch viele Kollisionen voll, baut Java ihn intern zu einem kleinen Baum um.
Klasse · implementiert Set (sortiert)

TreeSet<E>

Die sortierte Menge.

Erklärung

Besonderheiten

Keine Duplikate, und die Elemente sind immer sortiert – egal, in welcher Reihenfolge Du einfügst. Sortiert wird nach der natürlichen Ordnung (Comparable: Zahlen aufsteigend, Texte alphabetisch) oder nach einem Comparator, den Du mitgibst.

Wichtig: Ob zwei Elemente „gleich“ sind, entscheidet hier nicht equals, sondern der Vergleich: Liefert er 0, gilt das neue Element als Duplikat.

Stärken

  • Sortierung ohne eigenen Aufwand.
  • Navigieren: first(), last(), headSet, tailSet, ceiling, floor.
  • Operationen in logarithmischer Zeit – bei einer Million Elemente rund 20 Schritte.

Stolpersteine

  • Elemente müssen vergleichbar sein, sonst ClassCastException.
  • Ein Comparator legt auch fest, was als Duplikat gilt – siehe Codebeispiel.
  • Kein null; langsamer als HashSet.

Wann verwenden? Wenn eindeutige Elemente sortiert gebraucht werden oder Du nach Bereichen fragst: Ranglisten ohne Doppel, „alle Termine ab heute“, kleinstes/größtes Element.

Codebeispiel

Zahlen in beliebiger Reihenfolge – die Ausgabe ist trotzdem sortiert, die zweite 7 wird abgelehnt.

TreeSet<Integer> zahlen = new TreeSet<>();

zahlen.add(42);  System.out.println(zahlen);  // [42]
zahlen.add(7);   System.out.println(zahlen);  // [7, 42]         ← einsortiert
zahlen.add(19);  System.out.println(zahlen);  // [7, 19, 42]     ← einsortiert
zahlen.add(7);   System.out.println(zahlen);  // [7, 19, 42]     ← Duplikat abgelehnt
zahlen.add(3);   System.out.println(zahlen);  // [3, 7, 19, 42]

System.out.println(zahlen.first() + " " + zahlen.last());  // 3 42

Mit Comparator: Er bestimmt auch, was gleich ist

Set<String> nachLänge = new TreeSet<>(Comparator.comparing(String::length));

nachLänge.add("Birne");  System.out.println(nachLänge);  // [Birne]
nachLänge.add("Kiwi");   System.out.println(nachLänge);  // [Kiwi, Birne]  ← 4 vor 5 Zeichen
nachLänge.add("Apfel");  System.out.println(nachLänge);  // [Kiwi, Birne]  ← Apfel fehlt!

"Apfel" hat wie "Birne" fünf Zeichen. Der Comparator liefert 0 – für das TreeSet ist das ein Duplikat. Abhilfe: einen zweiten Vergleich anhängen, Comparator.comparing(String::length).thenComparing(Comparator.naturalOrder()).

Interne Umsetzung

Ein TreeSet ist ein binärer Suchbaum (genauer: ein Rot-Schwarz-Baum, intern über eine TreeMap). Jeder Knoten hat höchstens zwei Kinder: links das Kleinere, rechts das Größere. Beim Einfügen wird von der Wurzel aus verglichen und links oder rechts abgebogen, bis ein freier Platz kommt.

Nach 42, 7, 19, 7, 3 – der Baum hat sich selbst ausbalanciert Von links nach rechts gelesen: 3, 7, 19, 42 – genau die Ausgabe. Die zweite 7 kam bis zum Knoten 7, der Vergleich lieferte 0: abgelehnt.

Woher weiß der Baum, was kleiner ist?

Comparable – die natürliche Ordnung

Die Elemente vergleichen sich selbst über compareTo. String, Integer, LocalDate können das schon.

class Konto implements Comparable<Konto> {
    private final String iban;

    @Override
    public int compareTo(Konto anderes) {
        return iban.compareTo(anderes.iban);
    }
}

Set<Konto> konten = new TreeSet<>();

Comparator – eine Ordnung von außen

Ein eigenes Vergleichsobjekt, beim Anlegen mitgegeben. Geht auch für Klassen, die Du nicht ändern kannst, und für mehrere Sortierungen.

Set<Konto> nachSaldo = new TreeSet<>(
    Comparator.comparing(Konto::saldo)
              .thenComparing(Konto::iban));

Set<String> absteigend =
    new TreeSet<>(Comparator.reverseOrder());

Ein Ergebnis < 0 heißt „kleiner“, > 0 „größer“, 0 „gleich“ – und „gleich“ heißt im TreeSet: kommt nicht noch einmal hinein.
Klasse · implementiert Map

HashMap<K, V>

Die schnelle Zuordnung – ohne Reihenfolge.

Erklärung

Besonderheiten

Schlüssel sind eindeutig, ein zweites put mit demselben Schlüssel überschreibt den Wert (und liefert den alten zurück). Die Einträge haben keine verlässliche Reihenfolge. Ein null-Schlüssel ist erlaubt.

Stärken

  • put, get und containsKey im Mittel in konstanter Zeit.
  • Die richtige Vorgabe für eine Map.

Stolpersteine

  • Der Schlüssel braucht passendes equals und hashCode – wie beim HashSet.
  • Schlüssel nicht nachträglich ändern; am besten unveränderliche Typen.
  • Reihenfolge nötig? LinkedHashMap (Einfügen) oder TreeMap (sortiert).

Wann verwenden? Immer, wenn Du per Schlüssel nachschlägst und die Reihenfolge egal ist: IBAN → Konto, Artikelnummer → Bestand.

Codebeispiel

Ein Lagerbestand. Achte auf das zweite put mit "Apfel": kein zweiter Eintrag, sondern ein neuer Wert.

Map<String, Integer> bestand = new HashMap<>();

System.out.println(bestand.put("Birne", 3));  // null  (gab es noch nicht)
System.out.println(bestand);                  // {Birne=3}
System.out.println(bestand.put("Apfel", 5));  // null
System.out.println(bestand);                  // {Birne=3, Apfel=5}
System.out.println(bestand.put("Kiwi", 2));   // null
System.out.println(bestand);                  // {Birne=3, Kiwi=2, Apfel=5}  ← nicht Einfügereihenfolge
System.out.println(bestand.put("Apfel", 8));  // 5     ← alter Wert, überschrieben
System.out.println(bestand);                  // {Birne=3, Kiwi=2, Apfel=8}

System.out.println(bestand.get("Kiwi"));               // 2
System.out.println(bestand.get("Mango"));              // null
System.out.println(bestand.getOrDefault("Mango", 0));  // 0
Interne Umsetzung

Dieselbe Hash-Tabelle wie beim HashSet – nur liegt in jedem Eimer ein Paar aus Schlüssel und Wert. Den Platz bestimmt allein der Schlüssel; der Wert spielt dafür keine Rolle.

Das zweite put("Apfel", 8) landet wieder in Platz 6, findet dort per equals den Schlüssel "Apfel" – und ersetzt nur den Wert.
Wächst die Tabelle, ändern sich die Plätze – und damit die Ausgabereihenfolge.

Ablauf von put(key, value) und get(key)

  1. key.hashCode() berechnen und auf einen Platz der Tabelle abbilden.
  2. Im Eimer jeden Eintrag mit key.equals(…) prüfen.
  3. put: Treffer → Wert ersetzen, alten zurückgeben. Kein Treffer → neuen Eintrag anhängen, null zurückgeben.
    get: Treffer → Wert. Kein Treffer → null.

Wachstum wie beim HashSet: Start mit 16 Plätzen, bei 75 % Füllung verdoppeln und neu verteilen.
Klasse · implementiert Map (sortiert)

TreeMap<K, V>

Die nach Schlüsseln sortierte Zuordnung.

Erklärung

Besonderheiten

Eine Map, deren Einträge immer nach dem Schlüssel sortiert sind – natürliche Ordnung oder ein mitgegebener Comparator. Für die Werte gilt keine Sortierung. Was über das TreeSet gesagt ist, gilt hier für die Schlüssel.

Stärken

  • Sortierte Ausgabe ohne eigenen Aufwand.
  • Bereichsabfragen: firstKey(), lastKey(), headMap, tailMap, floorKey, ceilingKey.

Stolpersteine

  • Schlüssel müssen vergleichbar sein; kein null-Schlüssel.
  • Der Vergleich (nicht equals) entscheidet, ob ein Schlüssel schon da ist.
  • Langsamer als HashMap (logarithmisch statt konstant).

Wann verwenden? Wenn Schlüssel sortiert gebraucht werden: ein Index von A bis Z, Messwerte nach Datum, „alle Buchungen bis zum 31.“.

Codebeispiel

Derselbe Lagerbestand wie bei der HashMap – jetzt alphabetisch nach Schlüssel.

TreeMap<String, Integer> bestand = new TreeMap<>();

bestand.put("Birne", 3);  System.out.println(bestand);  // {Birne=3}
bestand.put("Apfel", 5);  System.out.println(bestand);  // {Apfel=5, Birne=3}          ← einsortiert
bestand.put("Kiwi", 2);   System.out.println(bestand);  // {Apfel=5, Birne=3, Kiwi=2}
bestand.put("Apfel", 8);  System.out.println(bestand);  // {Apfel=8, Birne=3, Kiwi=2}  ← überschrieben

System.out.println(bestand.firstKey());       // Apfel
System.out.println(bestand.headMap("Kiwi"));  // {Apfel=8, Birne=3}  ← alles vor "Kiwi"
Interne Umsetzung

Ein Rot-Schwarz-Baum wie beim TreeSet (das TreeSet benutzt intern sogar eine TreeMap). Jeder Knoten trägt Schlüssel und Wert; einsortiert wird nur nach dem Schlüssel – links kleiner, rechts größer.

Nach den vier put put("Apfel", 8): an der Wurzel ist „Apfel“ kleiner als „Birne“ → links; dort liefert der Vergleich 0 → Wert ersetzen.

Der Vergleich kommt wie beim TreeSet aus Comparable (die Schlüssel vergleichen sich selbst) oder aus einem Comparator im Konstruktor:

Map<String, Integer> ohneGroßKlein = new TreeMap<>(String.CASE_INSENSITIVE_ORDER);
Map<LocalDate, Double> kurse = new TreeMap<>();   // LocalDate ist Comparable

1 Anlegen

Mit new – veränderbar

List<String> obst = new ArrayList<>();            // leer
Set<String> einmalig = new HashSet<>(obst);       // Kopie einer anderen Collection
Map<String, Integer> bestand = new HashMap<>();
List<String> groß = new ArrayList<>(1_000);       // mit Startkapazität

Links das Interface, rechts die Klasse. Der Konstruktor mit einer Collection übernimmt deren Elemente – praktisch zum Umwandeln, etwa Liste → Menge ohne Duplikate.

List.of, Set.of, Map.of – unveränderlich

List<String> obst = List.of("Birne", "Apfel", "Kiwi");
System.out.println(obst);   // [Birne, Apfel, Kiwi]
obst.add("Mango");          // UnsupportedOperationException

Set.of("Apfel", "Apfel");
// IllegalArgumentException: duplicate element: Apfel

Map<String, Integer> bestand = Map.of("Apfel", 5, "Kiwi", 2);
System.out.println(bestand.get("Apfel"));   // 5

Kurz und sicher für feste Werte. Kein add, kein remove, kein null (NullPointerException).

Veränderbare Kopie

List<String> obst = new ArrayList<>(List.of("Birne", "Apfel", "Kiwi"));
obst.add("Mango");
System.out.println(obst);   // [Birne, Apfel, Kiwi, Mango]

Das gängige Muster, wenn Du mit festen Startwerten beginnen und danach weiter ändern willst.

Helfer aus Arrays und Collections

List<String> fest = Arrays.asList("Birne", "Apfel");
fest.set(0, "Kiwi");        // erlaubt → [Kiwi, Apfel]
fest.add("Mango");          // UnsupportedOperationException – feste Größe

List<String> leer = Collections.emptyList();

List<String> obst = new ArrayList<>(List.of("Birne", "Apfel", "Kiwi"));
Collections.sort(obst);                       // [Apfel, Birne, Kiwi]
System.out.println(Collections.max(obst));    // Kiwi

List<String> sicht = Collections.unmodifiableList(obst);  // Nur-Lese-Sicht
List<String> kopie = List.copyOf(obst);                   // unveränderliche Kopie

Sicht oder Kopie? unmodifiableList zeigt Änderungen am Original weiterhin an, lässt selbst aber keine zu – ideal für Getter. List.copyOf friert den Stand ein.

2 Generics: der Elementtyp in spitzen Klammern

Nur dieser Typ kommt hinein

List<String> namen = new ArrayList<>();   // <> rechts: Typ wird abgeleitet
namen.add("Mia");                         // ✓
namen.add(42);
// Fehler: Inkompatible Typen: int kann nicht in String konvertiert werden

String erster = namen.get(0);             // kein Cast nötig

Der Compiler prüft beim Übersetzen, dass nur String hineinkommt – und weiß deshalb auch, dass nur String herauskommt.

Mehrere Typparameter

Map<String, Integer> bestand = new HashMap<>();
bestand.put("Apfel", 5);       // ✓ String → Integer
bestand.put(5, "Apfel");       // Compilerfehler: 5 ist kein String

Map<String, List<String>> kategorien = new HashMap<>();
kategorien.put("Obst", List.of("Apfel", "Birne"));

Eine Map hat zwei: Schlüssel- und Werttyp. Typparameter lassen sich auch schachteln.

Keine primitiven Typen

List<int> zahlen;
// Fehler: Unerwarteter Typ – Erforderlich: Referenz, Ermittelt: int

List<Integer> zahlen = new ArrayList<>();
zahlen.add(42);            // Autoboxing: int → Integer
int x = zahlen.get(0);     // Unboxing:   Integer → int

Collections speichern Objekte. Für int, double, boolean nimmst Du die Hüllklassen Integer, Double, Boolean – das Umwandeln erledigt Java selbst.

Warum das ein Gewinn ist

List roh = new ArrayList();      // ohne Typangabe („Raw Type“)
roh.add("Mia");
roh.add(42);                     // wird angenommen …
String s = (String) roh.get(1);  // … und knallt erst hier:
// ClassCastException – zur Laufzeit

Ohne Generics fällt der Fehler erst beim Ausführen auf, irgendwo später. Mit Generics meldet ihn der Compiler sofort, an der richtigen Stelle.

3 Iterieren

Mit dem Iterator

List<String> obst = new ArrayList<>(List.of("Birne", "Apfel", "Kiwi", "Apfel"));

Iterator<String> it = obst.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("Apfel")) {
        it.remove();             // sicher entfernen
    }
}
System.out.println(obst);        // [Birne, Kiwi]

hasNext() fragt, ob noch etwas kommt; next() liefert es (am Ende: NoSuchElementException). Der einzige Weg, während des Durchlaufens sicher zu entfernen.

Mit for-each

for (String s : obst) {
    System.out.println(s);
}
// Birne
// Kiwi

List<String> liste = new ArrayList<>(List.of("Birne", "Apfel", "Kiwi"));
for (String s : liste) {
    if (s.equals("Birne")) liste.remove(s);
}
// ConcurrentModificationException

Die kürzeste Form – intern ist es derselbe Iterator, nur unsichtbar. Deshalb darfst Du die Collection darin nicht ändern; dafür gibt es it.remove() oder obst.removeIf(…).

Mit stream()

List<String> obst = List.of("Birne", "Apfel", "Kiwi", "Apfel");

List<String> ergebnis = obst.stream()
    .distinct()                     // Duplikate raus
    .sorted()                       // sortieren
    .map(String::toUpperCase)       // umwandeln
    .toList();
System.out.println(ergebnis);       // [APFEL, BIRNE, KIWI]

long anzahl = obst.stream().filter(s -> s.startsWith("A")).count();
System.out.println(anzahl);         // 2
System.out.println(obst);           // [Birne, Apfel, Kiwi, Apfel]  ← unverändert

Beschreibt, was passieren soll, statt einer Schleife. Ein Stream verändert die Quelle nicht, er liefert ein neues Ergebnis.

Über eine Map

Map<String, Integer> bestand = new TreeMap<>(Map.of("Birne", 3, "Apfel", 5, "Kiwi", 2));

for (Map.Entry<String, Integer> e : bestand.entrySet()) {
    System.out.println(e.getKey() + " → " + e.getValue());
}
// Apfel → 5
// Birne → 3
// Kiwi → 2

Eine Map ist nicht Iterable; durchlaufen wird eine ihrer Sichten. entrySet() liefert Schlüssel und Wert zusammen.

4 Mengenoperationen

OperationMethodea = [Apfel, Birne, Kiwi], b = [Apfel, Kiwi, Mango]
Vereinigung a ∪ bv.addAll(b)[Apfel, Birne, Kiwi, Mango]
Schnittmenge a ∩ bs.retainAll(b)[Apfel, Kiwi]
Differenz a \ bd.removeAll(b)[Birne]
Teilmenge?a.containsAll(…)a.containsAll(Set.of("Apfel", "Kiwi")) → true
Disjunkt?Collections.disjoint(a, …)Collections.disjoint(a, Set.of("Mango")) → true

Erst kopieren, dann rechnen

Set<String> a = new TreeSet<>(Set.of("Apfel", "Birne", "Kiwi"));
Set<String> b = new TreeSet<>(Set.of("Kiwi", "Mango", "Apfel"));

Set<String> vereinigung = new TreeSet<>(a);
vereinigung.addAll(b);
System.out.println(vereinigung);  // [Apfel, Birne, Kiwi, Mango]

Set<String> schnitt = new TreeSet<>(a);
schnitt.retainAll(b);
System.out.println(schnitt);      // [Apfel, Kiwi]

Set<String> differenz = new TreeSet<>(a);
differenz.removeAll(b);
System.out.println(differenz);    // [Birne]

System.out.println(a);            // [Apfel, Birne, Kiwi]  ← unverändert

addAll, retainAll und removeAll ändern die Menge, auf der sie aufgerufen werden. Wer a behalten will, rechnet auf einer Kopie.

Symmetrische Differenz und Streams

// in genau einer der beiden Mengen: (a ∪ b) \ (a ∩ b)
Set<String> nurEinmal = new TreeSet<>(vereinigung);
nurEinmal.removeAll(schnitt);
System.out.println(nurEinmal);    // [Birne, Mango]

// Schnittmenge als Stream – lässt a und b unberührt
Set<String> schnitt2 = a.stream()
    .filter(b::contains)
    .collect(Collectors.toCollection(TreeSet::new));
System.out.println(schnitt2);     // [Apfel, Kiwi]

Die Methoden funktionieren auch mit Listen – dann bleiben aber Duplikate erhalten. Für Mengenrechnung ist ein Set der passende Typ.
