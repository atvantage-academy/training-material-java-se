    Fehlerfälle mit Ausnahmen behandeln

    Als Entwickler:in möchte ich, dass eine unmögliche Abhebung nicht stillschweigend passiert, sondern klar signalisiert wird, damit aufrufender Code den Fehler bewusst behandeln muss.

    Lernziele

    Du…

    • definierst eine eigene Exception-Klasse.
    • wirfst eine Ausnahme an der passenden Stelle und behandelst sie mit try/catch.
    • begründest, ob eine Ausnahme checked oder unchecked sein sollte.

    Definition of Done

    • Es gibt eine Exception KeineDeckungException (checked).
    • abheben wirft diese Exception, wenn der Betrag nicht verfügbar ist.
    • Der Aufrufer in Main fängt die Exception mit try/catch und gibt eine sinnvolle Meldung aus.
    • Ein Programmierfehler (z. B. ein negativer Betrag) wird über eine unchecked Exception abgelehnt.
    • Du hast die Reflexionsfragen schriftlich beantwortet.

    Arbeitsschritte

    Eine fachliche Exception definieren

    Lege eine checked Exception an (erbt von Exception).

    public class KeineDeckungException extends Exception {
  public KeineDeckungException(String message) {
    super(message);
  }
}

    Hinweis: „Checked“ = erbt von Exception (nicht RuntimeException). Der Compiler erzwingt dann die Behandlung.

    Die Ausnahme werfen

    Lass abheben die Ausnahme werfen, wenn istGedeckt false liefert. Deklariere sie mit throws.

    Hinweis: Prüfe zuerst die Vorbedingung; erst wenn sie erfüllt ist, verändere den Kontostand – sonst bleibt das Konto im gültigen Zustand.

    Den Fehler behandeln

    Rufe abheben in Main in einem try/catch auf und reagiere sinnvoll.

    try {
  konto.abheben(100_00);
} catch (KeineDeckungException e) {
  System.out.println("Abhebung nicht möglich: " + e.getMessage());
}
