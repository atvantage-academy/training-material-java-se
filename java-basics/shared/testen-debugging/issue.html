    Das Konto mit JUnit testen

    Als Entwickler:in möchte ich das Verhalten von Ein- und Auszahlungen automatisiert absichern, damit ich Änderungen später ohne Angst vor Regressionen vornehmen kann.

    Lernziele

    Du…

    • schreibst einen JUnit-Test für eine Domänenklasse und lässt ihn laufen.
    • formulierst Erwartungen als Assertions und interpretierst einen fehlschlagenden Test.
    • setzt einen Breakpoint und inspizierst Variablen im Debugger.

    Definition of Done

    • Es gibt eine Testklasse mit mindestens zwei Tests (z. B. erfolgreiche Einzahlung, abgelehnte Überziehung).
    • Die Tests laufen grün.
    • Du hast einen Test bewusst zum Fehlschlagen gebracht, die Meldung gelesen und wieder repariert.
    • Du hast einen Breakpoint gesetzt und den Kontostand während der Ausführung inspiziert.
    • Du hast die Reflexionsfragen schriftlich beantwortet.

    Arbeitsschritte

    Einen ersten Test schreiben

    Schreibe einen Test, der nach einer Einzahlung den erwarteten Kontostand prüft.

    @Test
void einzahlungErhöhtDenKontostand() {
  Konto konto = new Sparkonto("DE...", anna);
  konto.einzahlen(50_00);
  assertEquals(50_00, konto.getStandInCent());
}

    Hinweis: Ein Test folgt dem Muster Arrange – Act – Assert: Objekt aufbauen, Aktion ausführen, Erwartung prüfen.

    Einen Fehlerfall testen

    Prüfe, dass eine unzulässige Abhebung die erwartete Ausnahme wirft.

    Hinweis: Für erwartete Ausnahmen eignet sich assertThrows(KeineDeckungException.class, () -> konto.abheben(...)).

    Mit dem Debugger nachsehen

    Setze im abheben-Pfad einen Breakpoint und verfolge, wie sich der Kontostand verändert.

    Reflexionsfragen

    • Was sagt Dir ein grüner Test – und was ausdrücklich nicht?
    • Warum ist ein automatisierter Test wertvoller als eine einmalige println-Kontrolle?
    • Wann bringt Dich der Debugger schneller ans Ziel als zusätzliche Ausgaben?
