Objektorientierung mit Java (Vererbung)

Der dritte Teil der Reihe – wieder in der Bibliothek: Aus dem einzelnen Buch wird eine Familie. Wie aus dem Vererbungspfeil im Diagramm Java-Code wird, in vier Bausteinen: extends, super(…), die Oberklasse Object und die Regel für Variablen. Überschreiben und abstrakte Klassen kommen später im Kurs.

1 Der Pfeil wird zu extends

Beide Pfeile zeigen nach oben auf Medium, und die hohle Dreiecksspitze an der Oberklasse ist in UML das Zeichen für Vererbung. Gelesen wird der Pfeil als „ist ein“: Ein Buch ist ein Medium. Das ist die verlässlichste Prüfung der Richtung – „Ein Medium ist ein Buch“ stimmt nicht.

Warum steht die ISBN oben? Weil ein Hörbuch genauso eine hat wie ein Buch – und was für alle gilt, gehört in die Oberklasse. Unten bleibt nur, was die Arten wirklich unterscheidet: die Seitenzahl beim Buch, die Spieldauer beim Hörbuch.

Ein Wort, und alles ist da

class Medium {
    String titel;
    int jahr;
    String isbn;

    void ausleihen() { … }
}

class Buch extends Medium {
    int seiten;
}

Buch schreibt nichts ab: titel, jahr und ausleihen() sind durch extends schon da. Unten steht nur noch das Eigene.

Und so fühlt sich das an

Buch b = new Buch();
b.titel  = "Erdsee";   // von Medium geerbt
b.isbn   = "978-…";    // von Medium geerbt
b.seiten = 320;        // aus Buch selbst
b.ausleihen();         // von Medium geerbt

Am Objekt ist nicht zu sehen, woher was kommt – das Buch ist ein Medium und hat deshalb alles, was ein Medium hat.

Java kennt keine Mehrfachvererbung: Jede Klasse hat genau eine Oberklasse. Was man tut, wenn etwas zu zwei Familien gehören soll, kommt bei den Interfaces.

2 super(…): die Oberklasse zuerst

✗ Geht nicht

class Medium {
    private final String titel;
    …
}

class Buch extends Medium {
    public Buch(String titel, int seiten) {
        this.titel = titel;   // Fehler:
        // titel has private access in Medium
    }
}

Geerbt heißt nicht „darf ich anfassen“: Was in der Oberklasse private ist, bleibt ihr überlassen.

✓ Nach oben durchreichen

class Buch extends Medium {
    private final int seiten;

    public Buch(String titel, int jahr,
                String isbn, int seiten) {
        super(titel, jahr, isbn);  // MUSS zuerst stehen
        this.seiten = seiten;
    }
}

Die Unterklasse nimmt die Werte entgegen und gibt sie weiter. Erst danach kümmert sie sich um ihr Eigenes.

Warum zuerst? Ein Objekt wird von unten nach oben gebaut wie ein Haus: erst das Fundament, dann das eigene Stockwerk. Solange der Oberklassen-Teil nicht steht, gibt es nichts, worauf die Unterklasse aufsetzen könnte – deshalb besteht der Compiler auf der Reihenfolge.

3 Object: die Wurzel aller Klassen

Auch ohne extends wird geerbt

class Medium { … }

// bedeutet in Wahrheit:
class Medium extends Object { … }

Jede Klasse in Java hat eine Oberklasse – steht keine da, ist es Object. Ganz oben endet also jede Familie in derselben Wurzel.

Daher kam toString()

System.out.println(new Medium());
// Medium@1b6d3586   ← aus Object

// Deine eigene Fassung:
public String toString() {
    return titel + " (" + jahr + ")";
}

Die Methode gab es immer schon – Du hast sie nicht erfunden, sondern ersetzt. Wie dieses Ersetzen heißt und was es alles ermöglicht, kommt später im Kurs.

4 Links allgemein, rechts konkret

Die Variable darf allgemeiner sein als das Objekt

Buch   b = new Buch("Erdsee", 1968, "978-…", 320);   // konkret
Medium m = new Buch("Erdsee", 1968, "978-…", 320);   // erlaubt: ein Buch IST ein Medium

// umgekehrt nicht:
// Buch x = new Medium("Irgendwas", 2020, "978-…");  // ein Medium ist KEIN Buch

Es ist derselbe Satz wie am Pfeil. Wenn „ist ein“ stimmt, ist die Zuweisung erlaubt.

Was Du über die Variable siehst

Medium m = new Buch("Erdsee", 1968, "978-…", 320);

m.titel;       // ✓ Medium hat einen Titel
m.ausleihen(); // ✓ kann jedes Medium
// m.seiten;   // ✗ sieht Medium nicht

Die Seitenzahl ist im Objekt – die Variable zeigt sie nur nicht. Der Typ links entscheidet, was sichtbar ist; das Objekt rechts entscheidet, was es wirklich ist.

Warum man das will

Medium[] regal = {
    new Buch("Erdsee", 1968, "978-…", 320),
    new Hörbuch("Momo", 1973, "978-…", 480),
    new Buch("Momo", 1973, "978-…", 288)
};

for (Medium m : regal) {
    m.ausleihen();
}

Ein Regal, in dem Bücher und Hörbücher liegen – möglich, weil beide Medien sind. Die Schleife muss nicht wissen, was genau sie in der Hand hält.

Die Faustregel: links so allgemein wie möglich, rechts so konkret wie nötig. Was daraus wird, wenn die Unterklassen dieselbe Methode unterschiedlich ausführen, ist das nächste große Thema im Kurs.
