Lambdas, Streams und Optional

    Ein Lambda ist ein Stück Code, das man weitergibt, statt es gleich auszuführen. Darauf bauen Streams und Optional auf: Man beschreibt, was mit den Daten geschehen soll – ausgeführt wird es erst, wenn jemand das Ergebnis abholt.

    seit Java 8 Stream.toList() seit Java 16

    Lambdas: Code für später

    Ein Lambda legt Code fest, führt ihn aber nicht aus. Ausgeführt wird er erst, wenn jemand die Methode des Interfaces aufruft – einmal, mehrmals oder gar nicht.

    Runnable gruß = () -> System.out.println("Hallo");   // nur festgelegt
System.out.println("vorher");
gruß.run();                                          // jetzt läuft es
gruß.run();                                          // und noch einmal

    Ausgabe

    vorher
Hallo
Hallo

    Wozu das gut ist, zeigt ein Standardwert, dessen Berechnung teuer ist. orElse bekommt einen Wert – der muss vor dem Aufruf feststehen. orElseGet bekommt ein Lambda und ruft es nur, wenn der Wert wirklich fehlt:

    Optional<String> name = Optional.of("Ada");
System.out.println(name.orElse(teuer()));             // teuer() läuft – umsonst
System.out.println(name.orElseGet(() -> teuer()));    // teuer() läuft nicht

    Ausgabe (teuer() meldet sich mit einer eingerückten Zeile)

      teuer() läuft
Ada
Ada

    Funktionale Interfaces: der Typ eines Lambdas

    Java hat keinen eigenen Typ für Funktionen. Ein Lambda braucht deshalb einen Zieltyp: ein Interface mit genau einer abstrakten Methode – ein funktionales Interface. Das Lambda ist die Umsetzung dieser einen Methode; default- und static-Methoden darf das Interface zusätzlich haben.

    @FunctionalInterface                     // optional: der Compiler prüft „genau eine“
interface Prüfung {
    boolean prüfe(String text);
}

Prüfung nichtLeer = text -> !text.isBlank();
System.out.println(nichtLeer.prüfe("   "));      // false
System.out.println(nichtLeer.prüfe("Lambda"));   // true

    Welches Interface gemeint ist, ergibt sich aus der Stelle, an der das Lambda steht: Dasselbe text -> !text.isBlank() ist einmal eine Prüfung, einmal ein Predicate<String>. Ohne Zieltyp übersetzt es nicht – var p = text -> … geht nicht.

    Von der anonymen Klasse zum Lambda

    Ein Lambda ist zunächst eine Kurzschreibweise: Alles, was der Compiler aus dem Zieltyp ohnehin weiß, darf man weglassen. Geh die Schritte durch – das Verhalten bleibt in jedem Schritt dasselbe.

    1 · Anonyme Klasse

    namen.forEach(new Consumer<String>() {
    @Override
    public void accept(String name) {
        System.out.println(name);
    }
});

    Eine Klasse ohne Namen, die Consumer<String> umsetzt, und sofort ein Objekt davon. Von den sechs Zeilen tragen genau zwei Wörter Inhalt: name und System.out.println(name).

    2 · Lambda mit Block

    namen.forEach((String name) -> {
    System.out.println(name);
});

    Weg sind new Consumer<String>(), @Override, public void accept – das alles kennt der Compiler aus dem Parametertyp von forEach. Es bleiben Parameterliste, Pfeil und Rumpf.

    3 · Einzeilig

    namen.forEach(name -> System.out.println(name));

    Sonderfall einzeilig: Besteht der Rumpf aus einem Ausdruck, entfallen geschweifte Klammern, Semikolon und – bei einem Rückgabewert – auch return. Der Parametertyp darf weg, und bei einem Parameter auch die runden Klammern.

    4 · Methodenreferenz

    namen.forEach(System.out::println);

    Sonderfall Methodenreferenz: Reicht das Lambda seinen Parameter nur an eine vorhandene Methode weiter, nennt der Operator :: diese Methode direkt. Vier Formen:

    Form Methodenreferenz entspricht
    statische Methode Integer::parseInt s -> Integer.parseInt(s)
    Methode eines bestimmten Objekts System.out::println x -> System.out.println(x)
    Methode des Parameters String::length s -> s.length()
    Konstruktor ArrayList::new () -> new ArrayList<>()

    Mehr als Kurzschrift: kein new, keine Klasse. Für die anonyme Klasse erzeugt der Compiler eine eigene Klassendatei und an der Stelle im Code ein new. Für das Lambda entsteht keine Klassendatei; an seiner Stelle steht invokedynamic – das passende Objekt baut die JVM beim ersten Durchlauf und darf es danach wiederverwenden.

    Quelltext Kurz.java

    Runnable anonym = new Runnable() {
    @Override
    public void run() {
        System.out.println("anonym");
    }
};
Runnable lambda = () -> System.out.println("lambda");

    Nach javac Kurz.java

    Kurz.class
Kurz$1.class        ← die anonyme Klasse

    Ausschnitt aus javap -c Kurz.class

    new           #7   // class Kurz$1
invokespecial #9   // Method Kurz$1."<init>":()V
invokedynamic #10  // InvokeDynamic #0:run:()Ljava/lang/Runnable;

    Sichtbar wird das, wenn man dasselbe zweimal erzeugt: Die anonyme Klasse liefert zwei Objekte, das Lambda (es greift auf keine Variable von außen zu) in OpenJDK beide Male dasselbe. Verlassen darf man sich darauf nicht – die Sprache erlaubt die Wiederverwendung, sie verlangt sie nicht.

    for (int i = 0; i < 2; i++) {
    anonym[i] = new Runnable() { @Override public void run() { } };
    lambda[i] = () -> { };
}
System.out.println(anonym[0] == anonym[1]);   // false
System.out.println(lambda[0] == lambda[1]);   // true

    Die fertigen funktionalen Interfaces

    Eigene funktionale Interfaces braucht man selten: java.util.function bringt die üblichen Formen mit. Vier davon genügen für den Anfang – unterschieden danach, was hineingeht und was herauskommt.

    Supplier<T> – nichts hinein, ein Wert heraus

    T get()

    Supplier<String> gruß = () -> "Hallo";
System.out.println(gruß.get());                       // Hallo

DoubleSupplier zufall = Math::random;                 // liefert ein double, kein Double
System.out.println(zufall.getAsDouble() < 1.0);       // true

    Typisch für: Werte, die erst bei Bedarf entstehen – orElseGet, Objects.requireNonNull(…, Supplier), Fabriken.

    Ableitungen: IntSupplier, LongSupplier, DoubleSupplier, BooleanSupplier.

    Consumer<T> – ein Wert hinein, nichts heraus

    void accept(T t)

    Consumer<String> drucker = System.out::println;
drucker.accept("Hallo");                              // Hallo

    Typisch für: Wirkungen am Ende – forEach, ifPresent.

    Ableitungen: BiConsumer<T, U> (zwei Werte, etwa in Map.forEach), IntConsumer, LongConsumer, DoubleConsumer, ObjIntConsumer<T> …

    Function<T, R> – ein Wert hinein, ein anderer heraus

    R apply(T t)

    Function<String, Integer> länge = String::length;
System.out.println(länge.apply("Lambda"));            // 6

ToIntFunction<String> längeOhneBoxing = String::length;
System.out.println(längeOhneBoxing.applyAsInt("Lambda"));   // 6, als int

UnaryOperator<String> laut = String::toUpperCase;     // Function<String, String>
System.out.println(laut.andThen(s -> s + "!").apply("hallo"));   // HALLO!

    Typisch für: Umwandeln – map, Comparator.comparing, computeIfAbsent.

    Ableitungen: BiFunction<T, U, R>, UnaryOperator<T> und BinaryOperator<T> (Ein- und Ausgabe vom selben Typ), IntFunction<R>, ToIntFunction<T>, IntUnaryOperator … Verknüpfen mit andThen und compose.

    Predicate<T> – ein Wert hinein, ja oder nein heraus

    boolean test(T t)

    Predicate<String> leer = String::isBlank;
System.out.println(leer.negate().test("Lambda"));     // true

IntPredicate gerade = n -> n % 2 == 0;
System.out.println(gerade.test(7));                   // false

    Typisch für: Bedingungen – filter, removeIf, anyMatch.

    Ableitungen: BiPredicate<T, U>, IntPredicate, LongPredicate, DoublePredicate. Verknüpfen mit and, or, negate.

    Warum es DoubleSupplier & Co. gibt: Generics gehen nur mit Objekten. Ein Supplier<Double> packt jede Zahl in ein Double und wieder aus; die Ableitungen für int, long und double sparen dieses Autoboxing – ihre Methode heißt dann getAsDouble, applyAsInt, test usw.

    Streams: ein Fließband

    Ein Stream ist ein Fließband: Vorn legt eine Quelle die Stücke auf, unterwegs bearbeiten Maschinen sie – aussortieren, umformen, ordnen –, und am Ende fängt ein Eimer sie auf. Der Eimer ist der Collector: Er entscheidet, was am Ende herauskommt – eine Liste, eine Map, eine Zahl, ein Text.

    Quelle

    Jede Collection hat stream(); dazu kommen Stream.of(…), Arrays.stream(…), IntStream.range(…) und Dateien (Files.lines). Die Quelle wird nicht verändert – das Fließband arbeitet mit dem, was sie auflegt.

    Maschine: filter

    Lässt nur Stücke durch, für die das Predicate true liefert. Weitere Maschinen dieser Art: distinct, limit, skip, takeWhile.

    Maschine: map

    Formt jedes Stück mit einer Function um – hier zu Großbuchstaben, ebenso gut zu einem anderen Typ (map(String::length)). flatMap macht aus einem Stück mehrere, mapToInt ein Fließband für int mit sum und average.

    Maschine: sorted

    Ordnet die Stücke – natürlich oder nach einem Comparator (sorted(Comparator.comparing(String::length))). Sie muss alle Stücke gesehen haben, bevor sie eines weitergibt; die übrigen Maschinen arbeiten Stück für Stück.

    Eimer: der Collector

    Erst die Endoperation setzt das Band in Gang. toList() sammelt in eine unveränderliche Liste; collect(Collectors.…) kennt weitere Eimer: toSet, toMap, groupingBy, partitioningBy, joining, counting. Andere Endoperationen liefern gleich einen Wert: count, anyMatch, findFirst, forEach.

    Ohne Eimer läuft nichts – und dann Stück für Stück. Die Maschinen sind Lambdas, also Code für später: Solange keine Endoperation folgt, wird kein einziges Lambda aufgerufen. Läuft das Band, wandert jedes Stück einzeln durch alle Maschinen, bevor das nächste kommt:

    List<String> spur = Stream.of("Ada", "Grace", "Alan")
        .filter(n -> {
            System.out.println("filter " + n);
            return n.length() > 3;
        })
        .map(n -> {
            System.out.println("map    " + n);
            return n.toUpperCase();
        })
        .toList();
System.out.println(spur);

    Ausgabe

    filter Ada
filter Grace
map    Grace
filter Alan
map    Alan
[GRACE, ALAN]

    Optional: ein Fließband für höchstens ein Stück

    Optional ist dasselbe Bild mit einem Unterschied: Auf dem Band liegt kein oder genau ein Stück, nicht beliebig viele. Die Maschinen heißen gleich – filter, map, flatMap –, und am Ende steht statt eines Eimers die Frage, was gilt, wenn nichts ankommt.

    Optional<String> raum = suche(nummer);       // leer oder ein Name
String anzeige = raum
        .filter(n -> !n.isBlank())
        .map(String::toUpperCase)
        .orElse("unbekannt");
    1. suche("R102")Seminar 2
    2. filterSeminar 2
    3. mapSEMINAR 2
    4. orElseSEMINAR 2

    Ein Stück liegt auf dem Band und durchläuft alle Maschinen; orElse gibt es heraus.

    1. suche("R999")leer
    2. filterleer
    3. mapleer
    4. orElseunbekannt

    Das Band ist leer; die Maschinen laufen leer durch, ohne ihre Lambdas aufzurufen. Erst orElse liefert den Ersatz – ohne ein einziges if und ohne NullPointerException.

    Gemessene Ausgabe für beide Nummern

    R102 -> SEMINAR 2
R999 -> unbekannt
    Stream (0..*) Optional (0..1)
    filter, map, flatMap filter, map, flatMap
    toList(), collect(…) orElse(…), orElseGet(…), orElseThrow()
    forEach(…) ifPresent(…), ifPresentOrElse(…)
    findFirst() – liefert ein Optional stream() – macht ein Band mit 0 oder 1 Stück

    Optional ist ein Rückgabetyp. Eine Methode, die etwas sucht, sagt mit Optional<Room> statt Room, dass es auch nichts geben kann – der Aufrufer kann es nicht übersehen. Als Feld oder Parameter macht es Code nur länger. Und get() ohne Prüfung ist dieselbe Falle wie null ohne Prüfung.

    Merksatz: Ein Lambda ist Code für später, sein Typ ein Interface mit einer Methode. Ein Stream ist ein Fließband aus solchen Lambdas, das erst der Eimer am Ende in Gang setzt – und Optional ist dasselbe Band für höchstens ein Stück.
