Records

Ein record erklärt nur noch die Daten – den Rest erzeugt der Compiler. Genauso wichtig ist, was er nicht erzeugt: Daran entscheidet sich, ob ein Record in eine bestehende Anwendung passt. Wähle einen Bestandteil und sieh nach, was der Compiler daraus macht.

seit Java 16 LTS 17 JEP 395

Was der Compiler erzeugt – und was nicht

Quelltext

```java public record Position(String artikel, int menge, BigDecimal einzelpreis) { public Position { // kompakter Konstruktor if (menge <= 0) { throw new IllegalArgumentException("Menge muss positiv sein: " + menge); } } public BigDecimal gesamt() { return einzelpreis.multiply(BigDecimal.valueOf(menge)); } } ```

✓ Erzeugt der Compiler

✗ Gibt es nicht

Wo passen Records – und wo nicht?

Aus den fehlenden Bestandteilen folgt, wo ein Record trägt. Entscheidend ist meist, ob ein Framework das Objekt leer erzeugen und danach befüllen oder ableiten will.

EinsatzRecord?Warum
Rückgabe mehrerer Werte, Schlüssel in einer Map✓ passtequals und hashCode aus allen Komponenten – zwei gleiche Werte sind gleich.
DTO einer REST-Schnittstelle (JSON)✓ passtJackson ab 2.12 und Jakarta JSON Binding 3.0 (Eclipse Yasson 3) lesen und schreiben Records über den kanonischen Konstruktor und die Zugriffsmethoden.
Ergebnis einer Abfrage (select new …)✓ passtDie Projektion ruft nur einen Konstruktor auf – genau den, den der Record hat.
Wert mit Prüfung (Geldbetrag, Zeitraum, IBAN)✓ passtDer kompakte Konstruktor prüft einmal; danach ist der Wert gültig und unveränderlich.
Eingebetteter Wert einer JPA-Entität (@Embeddable)△ ab Jakarta Persistence 3.2Seit Jakarta EE 11 sind Records als einbettbare Klassen erlaubt; ältere Fassungen verlangen eine Klasse mit parameterlosem Konstruktor.
JPA-Entität (@Entity)✗ passt nichtDer Persistenz-Provider erzeugt die Entität leer, setzt Felder, verfolgt Änderungen und leitet für Lazy Loading ab – alles, was ein Record nicht erlaubt.
CDI-Bean mit normalem Scope (@ApplicationScoped)✗ passt nichtDer Container legt einen Proxy als Unterklasse an; ein Record ist final und damit nicht „proxyable“.
Fachobjekt mit eigener Identität und Zustand (Bestellung, Konto)✗ passt nichtEs ändert sich über die Zeit und ist nicht gleich, nur weil die Werte gleich sind.

Wozu Records da sind, warum die Zugriffsmethode artikel() und nicht getArtikel() heißt und wie sich Record und Java Bean Punkt für Punkt unterscheiden: Enums, Annotations und Records, Reiter „Records“.

Merksatz: Ein Record ist kein kürzer geschriebenes Bean. Was der Compiler weglässt – Setter, leerer Konstruktor, Ableitung –, ist Absicht. Wo ein Framework genau das braucht, bleibt es bei einer Klasse.
