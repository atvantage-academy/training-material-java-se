Objektorientierung mit Java (einfach)

Wie aus einem Klassendiagramm Java-Code wird – auf das Nötigste beschränkt: Klassen mit Variablen und Methoden, Objekte mit new, Beziehungen als Referenz und eine lesbare Ausgabe mit toString(). Das Beispiel ist bewusst ein anderes als in Deiner Übung, damit Du übertragen musst statt abzuschreiben. Konstruktoren, private, Getter/Setter und Packages fehlen hier ebenfalls mit Absicht – die kommen später im Kurs.

2 Die Klasse: der Bauplan

Variablen und Methoden in einer Klasse

class Buch {

    // Instanzvariablen – der Zustand
    String titel;
    int seiten;
    int bewertung;

    // Methode – das Verhalten
    void bewerten(int sterne) {
        bewertung = bewertung + sterne;
    }
}

Die Klasse beschreibt, was ein Buch hat und kann. Sie ist selbst noch kein Buch – so wie ein Bauplan noch kein Haus ist.

Innen ohne Punkt, außen mit Punkt

// innerhalb der Klasse: direkt
bewertung = bewertung + sterne;

// außerhalb: über das Objekt
erdsee.titel = "Erdsee";
erdsee.bewerten(5);

Innerhalb einer Methode ist klar, um welches Objekt es geht: um das, auf dem die Methode gerade läuft. Von außen musst Du sagen, welches gemeint ist.

Der Dateiname muss zum Klassennamen passen: Buch lebt in Buch.java. Klassennamen schreibt man groß, Variablen und Methoden klein. Und: Der Name einer Variablen wird immer im Kontext ihrer Klasse gelesen – in Buch heißt das Feld titel und nicht buchtitel. Der Klassenname steht ja schon davor: buch.titel.

3 Objekte erzeugen mit new

Ein Bauplan, viele Objekte

Buch erdsee = new Buch();
erdsee.titel = "Erdsee";
erdsee.seiten = 320;

Buch dunkelheit = new Buch();
dunkelheit.titel = "Die linke Hand der Dunkelheit";
dunkelheit.seiten = 288;

System.out.println(erdsee.seiten);      // 320
System.out.println(dunkelheit.seiten);  // 288

new Buch() baut ein neues Buch und gibt Dir den Zugriff darauf. Beide Bücher haben dieselben Variablen – aber jedes seine eigenen Werte.

Deshalb: Instanzvariablen

erdsee.seiten = 320;
dunkelheit.seiten = 288;

erdsee.bewerten(5);

// erdsee bewertet, dunkelheit unberührt

Jede Instanz – also jedes Objekt – hat ihren eigenen Satz Variablen. Was Du an einem Objekt änderst, lässt die anderen unberührt.

Wer new vergisst, hat nur eine leere Variable: Buch erdsee; zeigt noch auf nichts (null). Der Zugriff darauf endet in einer NullPointerException.

4 Beziehungen: Referenz statt Text

✓ So gehört es

class Buch {
    String titel;
    Autor autor;        // die Linie im Diagramm
}

Autor ursula = new Autor();
ursula.name = "Ursula K. Le Guin";
ursula.geburtsjahr = 1929;

Buch erdsee = new Buch();
erdsee.autor = ursula;

// alles, was der Autor weiß, hängt am Buch
System.out.println(erdsee.autor.geburtsjahr);

Das Buch kennt das Autorenobjekt – mit allem, was daran hängt.

✗ Die häufigste Falle

class Buch {
    String titel;
    String autor;       // nur der Name
}

erdsee.autor = "Ursula K. Le Guin";

// und jetzt? Geburtsjahr? Weitere Bücher?
// Und was, wenn zwei Autoren
// gleich heißen?

Ein Text ist eine Kopie, die niemand mitpflegt. Damit zerfällt das Objektmodell wieder in verstreute Daten – genau das, was wir hinter uns lassen wollten.

Die Punkt-Schreibweise folgt der Linie

System.out.println(erdsee.titel);              // Erdsee
System.out.println(erdsee.autor.name);         // Ursula K. Le Guin
System.out.println(erdsee.autor.geburtsjahr);  // 1929

erdsee.autor.name heißt: nimm das Buch erdsee, geh zu seinem Autor, und lies dort den Namen. So entsteht aus einzelnen Objekten ein Objektgeflecht, durch das Du Dich hangeln kannst.

5 Lesbare Ausgabe mit toString()

Ohne toString()

System.out.println(erdsee);

// Ausgabe:
// Buch@1b6d3586

Java kennt keine sinnvolle Textform für Deine Klasse und gibt Klassenname plus eine interne Kennung aus.

Mit toString()

class Buch {
    String titel;
    int seiten;

    public String toString() {
        return titel + " (" + seiten + " Seiten)";
    }
}

// Ausgabe:
// Erdsee (320 Seiten)

Die Methode wird automatisch benutzt, sobald ein Objekt als Text gebraucht wird – aufrufen musst Du sie nicht.

Die Klasse beschreibt sich selbst. Ohne toString() müsste jede Ausgabestelle die Felder einzeln zusammensetzen – und bei jeder Änderung nachziehen.
