Die Geschichte der String-Interpolation in Java

Viele Sprachen setzen Werte direkt in eine Zeichenkette ein: "Hallo ${name}". Java hat das bis heute nicht – es war schon da, als Preview, und wurde wieder entfernt. Die Zeitleiste zeigt, womit man stattdessen arbeitet, was die String Templates anders machen wollten und warum sie zurückgezogen wurden. Wähle eine Station.

Exkurs: formatted() kennt kein Locale

formatted() (seit Java 15) ist dasselbe wie String.format(this, …) – und nutzt damit das Default-Locale der JVM. Eine Überladung mit Locale gibt es nicht. Dasselbe Programm schreibt deshalb auf einem deutschen Rechner ein Komma, auf einem amerikanischen einen Punkt. Schalte um:

Aufruf (name = "Ada", summe = 1234.5)Ausgabehängt vom Default-Locale ab?

Für Ausgaben, die eine Maschine liest – CSV, JSON, Logzeilen, Dateinamen –, legt String.format(Locale.ROOT, …) das Format fest. formatted() passt, wo der Text für Menschen ist und das Locale der Anwendung gelten soll.

Merksatz: Java hat keine String-Interpolation – und das ist eine Entscheidung, keine Lücke: Die erste Fassung band das Einsetzen an einen Verarbeiter, und dafür fand sich kein Design, das alle überzeugte. Bis dahin: + für wenige Teile, formatted() für Formatierung, Text-Blöcke für mehrere Zeilen – und für SQL nie etwas davon, sondern PreparedStatement.
