Das Projekt mit Gradle anlegen und eine Bibliothek einbinden

Als Entwickler:in möchte ich mein Projekt von einem Build-Werkzeug verwalten lassen, damit der Build reproduzierbar ist und ich fremde Bibliotheken ohne manuelles Kopieren nutzen kann.

Lernziele

Du…

  • legst ein Java-Projekt mit Gradle an und ordnest dessen Standard-Verzeichnisstruktur ein.
  • baust das Projekt mit einem einzigen Befehl reproduzierbar.
  • deklarierst eine externe Abhängigkeit in der Build-Datei.
  • nutzt eine Klasse der eingebundenen Bibliothek im eigenen Code.

Definition of Done

  • Es gibt ein Gradle-Projekt mit Build-Datei, Wrapper (gradlew) und dem Ordner src/main/java.
  • Der bisherige Banking-Code liegt im Projekt und wird mitgebaut.
  • Das Projekt baut mit einem einzigen Befehl fehlerfrei.
  • In der Build-Datei ist eine neue Abhängigkeit deklariert.
  • Eine Klasse der Bibliothek wird im Code verwendet und das Programm läuft.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Ein Gradle-Projekt anlegen

Lege ein neues Projekt mit dem Build-System Gradle an – über den Projekt-Assistenten Deiner IDE oder auf der Kommandozeile:

gradle init --type java-application

Hinweis: Beide Wege erzeugen dasselbe Gerüst: eine Build-Datei (build.gradle bzw. build.gradle.kts), den Wrapper (gradlew) und die Standard-Ordner src/main/java und src/test/java.

Den bisherigen Code übernehmen

Bring Deine Klassen aus dem bisherigen Projekt nach src/main/java – die Paketstruktur behältst Du bei.

Hinweis: Dass der Code genau dort liegt, ist Konvention: Gradle findet ihn ohne eine einzige Zeile Konfiguration.

Das Projekt bauen

Baue das Projekt und stelle sicher, dass der Build grün ist.

./gradlew build

Hinweis: Der Wrapper lädt beim ersten Aufruf die passende Gradle-Version aus dem Netz – deshalb dauert der erste Build länger. Genau dadurch bauen alle im Team mit derselben Version.

Die Build-Datei ansehen

Sieh Dir die erzeugte Build-Datei an und finde die Java-Version, den repositories- und den dependencies-Block.

Hinweis: Eine Abhängigkeit steht schon drin – die Test-Bibliothek. Die brauchst Du im nächsten Modul.

Eine Abhängigkeit deklarieren

Ergänze im dependencies-Block eine kleine, nützliche Bibliothek (z. B. Apache Commons Lang).

dependencies {
    implementation 'org.apache.commons:commons-lang3:3.14.0'
}

Hinweis: Nach dem Ändern der Build-Datei muss das Projekt neu synchronisiert/gebaut werden, damit die IDE die Bibliothek kennt.

Die Bibliothek verwenden

Nutze eine Methode der Bibliothek an einer sinnvollen Stelle (z. B. StringUtils.isBlank(...) bei der Kunden-Validierung).

Reflexionsfragen

  • Warum ist es besser, Abhängigkeiten zu deklarieren, statt .jar-Dateien manuell abzulegen?
  • Was gehört in die Versionsverwaltung – die Bibliotheken selbst oder die Build-Beschreibung?
  • Was könnte passieren, wenn zwei Bibliotheken unterschiedliche Versionen derselben Abhängigkeit verlangen?
