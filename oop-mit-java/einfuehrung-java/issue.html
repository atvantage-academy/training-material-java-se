Die Java-Plattform erkunden

Als Entwickler:in möchte ich sehen, was zwischen meinem Quellcode und der laufenden Anwendung passiert, damit ich verstehe, warum dasselbe Java-Programm auf jedem Betriebssystem läuft.

Hinweis: Arbeite in dieser Übung bewusst mit einem einfachen Texteditor und der Kommandozeile – ohne IDE. So machst Du jeden Schritt selbst, den Dir die IDE später abnimmt. Die IDE kommt im nächsten Modul.

Lernziele

Du…

  • kompilierst eine vorgegebene .java-Datei mit javac zu einer .class-Datei.
  • betrachtest den erzeugten Bytecode mit javap und ordnest die Rolle der JVM ein.
  • erklärst am Beispiel das Prinzip „Write once, run anywhere“.
  • benennst, wozu der Classpath dient.

Definition of Done

  • Die vorgegebene Klasse HelloWorld liegt als Datei HelloWorld.java vor.
  • Die Klasse ist mit javac zu einer .class-Datei kompiliert.
  • Du hast Dir den Bytecode mit javap -c angesehen.
  • Das Programm läuft mit java HelloWorld und gibt „Hello, World!“ aus.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Die vorgegebene Klasse anlegen

Übernimm den folgenden Quellcode unverändert mit einem einfachen Texteditor in eine Datei HelloWorld.java.

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Hinweis: Der Dateiname muss zum Klassennamen passen (HelloWorld.java → class HelloWorld).

Kompilieren und den Bytecode ansehen

Übersetze die Datei und wirf einen Blick auf den erzeugten Bytecode.

javac HelloWorld.java
javap -c HelloWorld

Hinweis: javap -c zeigt den plattformunabhängigen Bytecode – genau das, was die JVM ausführt (nicht Maschinencode Deiner CPU).

Ausführen

Starte das Programm über die JVM.

java HelloWorld

Hinweis: Die JVM findet HelloWorld, weil sie im aktuellen Verzeichnis sucht. Wo sie überhaupt nach Klassen sucht, steuert der Classpath – probier zum Vergleich einen Start aus einem anderen Verzeichnis, einmal ohne und einmal mit java -cp <Verzeichnis> HelloWorld.

Reflexionsfragen

  • Warum übersetzt Java den Quellcode in Bytecode und nicht direkt in ein nativ ausführbares Format?
  • Worauf musst Du beim Entwickeln achten, damit Deine Anwendung wirklich plattformunabhängig bleibt?
  • Was ist der sogenannte „Classpath“?
