Prozedurale Logik nach Java übertragen

Prozedurale Logik nach Java übertragen

Als Entwickler:in möchte ich vertraute Konstrukte wie Variablen, Schleifen und Methoden in Java schreiben, damit mir die Syntax für den Rest der Woche flüssig von der Hand geht.

Hinweis: Die Visualisierung Java-Syntax auf einen Blick (rechts unter „Weiterführende Informationen“) fasst Datentypen, Schreibweisen, Typumwandlung, Methoden und Kontrollstrukturen zum Nachschlagen zusammen. Schreib den Code selbst und schlag dort nach, wenn Du hängst.

Die Übung wächst in vier Teilen: Jeder Teil baut auf dem vorigen auf, und nach jedem Teil läuft Dein Programm. Diesmal arbeitest Du allein in der IDE – das gemeinsame Vormachen aus dem letzten Modul entfällt.

Am Ende jedes Teils kannst Du die Musterlösung aufdecken – sie erscheint mittig über der Seite, ein Klick daneben schließt sie wieder. Öffne sie erst, wenn Dein eigener Code läuft – oder wenn Du wirklich feststeckst. Es ist eine Lösung, nicht die Lösung: Deine darf anders aussehen und trotzdem richtig sein. (Im Ausdruck der Seite sind die Musterlösungen bewusst nicht enthalten.)

Lernziele

Du…

  • arbeitest eigenständig in der IDE: legst eine Klasse an, schreibst Code, startest das Programm und liest Fehlermeldungen selbst.
  • deklarierst Variablen mit passendem Typ und gibst Ergebnisse mit System.out.println(…) aus.
  • lagerst eine Berechnung in eine Methode mit Parametern und Rückgabewert aus und rufst sie auf.
  • nutzt eine Schleife und eine Bedingung, um über ein Array zu laufen.
  • benennst die Signatur einer Methode und überlädst sie.
  • erklärst, warum die Division zweier int-Werte nicht den erwarteten Mittelwert liefert, und setzt den Cast an der richtigen Stelle.

Definition of Done

  • Teil 1: Im Projekt liegt eine Klasse Wetterstation; main deklariert zwei Messwerte, berechnet ihren Mittelwert und gibt ihn aus.
  • Teil 2: Die Berechnung steckt in einer Methode mittelwert, die zwei int-Werte entgegennimmt und einen double zurückgibt; main ruft sie mit mehreren Wertepaaren auf, und das Ergebnis stimmt jetzt.
  • Teil 3: Eine Methode durchschnitt läuft mit einer Schleife über ein int[] und liefert den Mittelwert; der Fall „leere Messreihe“ ist mit einer Bedingung abgefangen.
  • Teil 4: Es gibt eine zweite, überladene Methode durchschnitt mit zusätzlichem Standardwert; sie ruft die Variante aus Teil 3 auf, statt die Berechnung zu kopieren.
  • main ruft am Ende alle Varianten auf – auch einmal mit einer leeren Messreihe – und gibt die Ergebnisse aus.
  • Du hast die Reflexionsfragen schriftlich beantwortet.

Arbeitsschritte

Teil 1: Zwei Messwerte, ein Mittelwert

Deine Wetterstation misst die Temperatur in ganzen Grad. Lege im Projekt aus dem letzten Modul eine neue Klasse Wetterstation an, deklariere in main zwei Messwerte (z. B. 17 morgens und 24 mittags), berechne ihren Mittelwert und gib ihn mit System.out.println(…) aus.

Hinweis: Das Gerüst public static void main(String[] args) findest Du in der Visualisierung im Abschnitt Einstieg über main – tipp es zunächst einfach ab. Was die einzelnen Schlüsselwörter davor bedeuten, klären wir später in der Woche.

Hinweis: Mit + hängst Du Text und Werte aneinander: System.out.println("Mittelwert: " + mittelwert);

Sieh Dir das Ergebnis genau an: Für 17 und 24 erwartest Du 20.5 – was gibt Dein Programm aus? Lass den Befund erst einmal so stehen, Du reparierst ihn in Teil 2.

Musterlösung – Teil 1: Zwei Messwerte, ein Mittelwert 
public class Wetterstation {

    public static void main(String[] args) {
        int morgens = 17;
        int mittags = 24;

        double mittelwert = (morgens + mittags) / 2;

        System.out.println("Mittelwert: " + mittelwert);
    }
}

// Ausgabe: Mittelwert: 20.0
// Erwartet hättest Du 20.5 – warum das so ist, klärt Teil 2.

Teil 2: Die Berechnung in eine Methode auslagern

Verschiebe die Rechnung aus main in eine eigene Methode mittelwert, die zwei int-Werte entgegennimmt und das Ergebnis zurückgibt. Überleg Dir dabei, welchen Rückgabetyp das Ergebnis braucht – der Mittelwert ganzer Zahlen ist selten wieder eine ganze Zahl. Ruf die Methode aus main mit mehreren Wertepaaren auf.

Hinweis: Den Aufbau einer Methode zeigt die Visualisierung im Abschnitt Methoden. Das Wort static vor dem Rückgabetyp übernimmst Du dort einfach mit – warum es nötig ist, klärt sich am zweiten Tag.

Achtung, Stolperstein: Teilst Du zwei int-Werte, rechnet Java ganzzahlig und schneidet den Rest ab – 41 / 2 ergibt 20, nicht 20.5. Ein Rückgabetyp double allein repariert das nicht: Da ist der Rest schon weg. Setze den Cast an der Stelle, an der er wirkt, und probier beide Varianten aus.

Musterlösung – Teil 2: Die Berechnung in eine Methode auslagern 
public class Wetterstation {

    public static void main(String[] args) {
        System.out.println("Mittelwert: " + mittelwert(17, 24));
        System.out.println("Mittelwert: " + mittelwert(19, 22));
    }

    // Der Cast steht vor der Division: Sobald einer der Operanden ein
    // Gleitkommatyp ist, rechnet Java nicht mehr ganzzahlig.
    static double mittelwert(int a, int b) {
        return (double) (a + b) / 2;
    }
}

// Ausgabe: Mittelwert: 20.5
//          Mittelwert: 20.5

Teil 3: Eine ganze Messreihe

Eine Woche hat mehr als zwei Messwerte. Lege in main ein int[] mit den Temperaturen einer Woche an (z. B. {17, 24, 19, 22, 25, 18, 21}) und schreibe eine Methode durchschnitt, die ein solches Array entgegennimmt und den Mittelwert aller Werte zurückgibt.

Hinweis: Die Anzahl der Elemente liefert messwerte.length – beim Array ohne Klammern, anders als length() beim String. Über die Elemente kommst Du mit einer klassischen for-Schleife oder mit for-each.

Probier danach aus, was bei einer leeren Messreihe ({}) passiert – die Station war einfach eine Woche lang aus. Sieh Dir an, was Dein Programm tut, und fang den Fall mit einer Bedingung ab.

Hinweis: Was Du im leeren Fall zurückgeben sollst, ist gar nicht so klar – 0 behauptet 0 °C, obwohl gar nichts gemessen wurde. Halt diesen Zwiespalt kurz fest, Teil 4 greift ihn auf.

Musterlösung – Teil 3: Eine ganze Messreihe 
public class Wetterstation {

    public static void main(String[] args) {
        int[] woche = {17, 24, 19, 22, 25, 18, 21};
        int[] keineMessung = {};

        System.out.println("Durchschnitt: " + durchschnitt(woche));
        System.out.println("Durchschnitt: " + durchschnitt(keineMessung));
    }

    static double durchschnitt(int[] messwerte) {
        if (messwerte.length == 0) {
            // Notbehelf: 0 behauptet 0 Grad, obwohl nichts gemessen wurde.
            // Teil 4 macht daraus etwas Ehrlicheres.
            return 0;
        }

        int summe = 0;
        for (int wert : messwerte) {
            summe += wert;
        }

        return (double) summe / messwerte.length;
    }
}

// Ausgabe: Durchschnitt: 20.857142857142858
//          Durchschnitt: 0.0

Teil 4: Denselben Namen zweimal – Überladen

Schreibe eine zweite Methode mit demselben Namen durchschnitt, die zusätzlich einen Standardwert entgegennimmt: Ist die Messreihe leer, gibt sie diesen Wert zurück, sonst den berechneten Mittelwert. Ruf am Ende in main beide Varianten auf – mit gefüllter und mit leerer Messreihe – und gib die Ergebnisse aus.

Hinweis: Beide Methoden heißen gleich und unterscheiden sich nur in der Parameterliste – genau das ist Überladen. Ein anderer Rückgabetyp allein würde dafür nicht genügen. Ruf die Variante aus Teil 3 auf, statt die Berechnung zu kopieren.

Musterlösung – Teil 4: Denselben Namen zweimal – Überladen 
public class Wetterstation {

    public static void main(String[] args) {
        int[] woche = {17, 24, 19, 22, 25, 18, 21};
        int[] keineMessung = {};

        System.out.println("Mittelwert:   " + mittelwert(17, 24));
        System.out.println("Durchschnitt: " + durchschnitt(woche));
        System.out.println("Durchschnitt: " + durchschnitt(keineMessung));
        System.out.println("Durchschnitt: " + durchschnitt(keineMessung, -99.0));
    }

    static double mittelwert(int a, int b) {
        return (double) (a + b) / 2;
    }

    static double durchschnitt(int[] messwerte) {
        if (messwerte.length == 0) {
            return 0;
        }

        int summe = 0;
        for (int wert : messwerte) {
            summe += wert;
        }

        return (double) summe / messwerte.length;
    }

    // Gleicher Name, andere Parameterliste – das ist Überladen.
    // Die Berechnung wird nicht kopiert, sondern aufgerufen.
    static double durchschnitt(int[] messwerte, double standardwert) {
        if (messwerte.length == 0) {
            return standardwert;
        }

        return durchschnitt(messwerte);
    }
}

// Ausgabe: Mittelwert:   20.5
//          Durchschnitt: 20.857142857142858
//          Durchschnitt: 0.0
//          Durchschnitt: -99.0

Für Schnelle: eine dritte Variante

Schreibe die Schleife aus Teil 3 einmal anders – hast Du eine klassische for-Schleife genommen, probier for-each, und umgekehrt. Vergleiche, welche der beiden Varianten sich für Dich flüssiger liest.

Hinweis: Beide sind gleich richtig. Interessant ist, was Du beim Umbau über Index, Länge und Elementzugriff bemerkst.

Reflexionsfragen

  • Was gehört zur Signatur einer Methode – und wodurch unterscheiden sich zwei überladene Methoden?
  • Warum liefert die Division zweier int-Werte nicht den erwarteten Mittelwert – und wo genau muss der Cast stehen, damit er hilft?
