    Backend: starten, debuggen, die Beans im Blick

    User Story

    Als Entwickler:in einer Jakarta-EE-Anwendung möchte ich das Backend in IntelliJ über Maven auf Open Liberty starten und debuggen, damit ich Server und Anwendung genauso bediene wie im Team – über die pom.xml, nicht über eine Server-Einstellung meiner IDE.

    Lernziele
    • Du startest Open Liberty im Dev-Modus aus dem Werkzeugfenster Maven.
    • Du hängst den Debugger über eine Run-Konfiguration Remote JVM Debug an den laufenden Server.
    • Du findest die CDI-Beans im Werkzeugfenster Beans und springst vom Injektionspunkt zur Bean.
    • Du weißt, wie Du ein solches Projekt mit dem Assistenten New Project neu anlegst.
    Definition of Done
    • Der Dev-Modus (liberty:dev) läuft, und http://localhost:9080/api/rooms liefert die Räume.
    • Eine Run-Konfiguration Remote JVM Debug auf Port 7777 hängt am Server; ein Haltepunkt in RoomResource hat bei einem Aufruf angehalten.
    • Eine Änderung an RoomResource ist ohne Neustart des Servers im Browser angekommen.
    • Du hast im Werkzeugfenster Beans die Beans des Backends gefunden, darunter den Mapper.
    • Du hast die Kontrollfragen beantwortet

    Diese Übung ist eine von zwei zur Wahl. Nimm sie, wenn Du an Jakarta-EE-Anwendungen arbeitest. Wenn Du fertig bist, nimm die Übung zum Frontend dazu.

    Das Backend ist eine kleine Raumbuchung: Räume, Buchungen und eine Suche nach freien Räumen, mit Jakarta EE auf Open Liberty und einer H2-Datenbank im Speicher. Wie jeder Schritt in IntelliJ heißt und wie Du ihn aus Deiner bisherigen IDE kennst, steht in der Übersicht „Projekte in IntelliJ“.

    Arbeitsschritte

    Starten

    Öffne das Werkzeugfenster Maven und starte unter Plugins das Goal liberty:dev. Beim ersten Start lädt das Plugin die Open-Liberty-Laufzeit aus dem Maven-Spiegel – das dauert einen Moment.

    Sobald die Konsole meldet, dass der Server bereit ist, rufe im Browser http://localhost:9080/api/rooms auf. Sieh Dir dann die Suche nach freien Räumen an: http://localhost:9080/api/rooms/free?date=2026-12-01&attendees=4.

    Hinweis: Aus dem Start ist eine Run-Konfiguration geworden. Über Modify Run Configuration machst Du sie dauerhaft – dann startest Du den Server künftig aus dem Run-Widget.

    Den Debugger anhängen

    Der Dev-Modus öffnet einen Debug-Port, voreingestellt 7777. Lege eine neue Run-Konfiguration vom Typ Remote JVM Debug an, setze den Port auf 7777 und gib ihr den Namen „Liberty“.

    Setze einen Haltepunkt in die Methode von RoomResource, die die freien Räume liefert, und starte die Konfiguration „Liberty“ im Debugger, während liberty:dev weiterläuft. Lade die Suche im Browser neu – IntelliJ hält an Deinem Haltepunkt. Steige von dort in den Aufruf von BookingService hinein.

    Ohne Neustart ändern

    Ergänze in RoomResource einen Endpunkt count, der die Anzahl der Räume als Zahl zurückgibt. Starte nichts neu: Rufe nur http://localhost:9080/api/rooms/count im Browser auf. Der Dev-Modus hat die Änderung übernommen.

    Die Beans im Blick

    Sieh Dir in RoomResource an den Feldern mit @Inject den Zeilenrand an. Folge dem Symbol dort zur Bean – und von der Bean zurück zu ihren Injektionspunkten.

    Öffne das Werkzeugfenster Beans und finde die Beans des Backends. Eine davon ist der Mapper RoomBookingMapper – sieh nach, wo seine Implementierung liegt. Sieh Dir danach im Werkzeugfenster Endpoints die Schnittstelle der Anwendung an.

    Die Abhängigkeiten ansehen

    Sieh Dir im Werkzeugfenster Maven unter Dependencies an, was das Backend mitbringt. Finde Lombok und MapStruct und sieh in der pom.xml nach, wie sie eingebunden sind.

    Beende dann den Server sauber, entweder über Stop oder in der Konsole mit q und Enter.

    Wenn Du früher fertig bist: ein Projekt neu anlegen

    Lege über File | New | Project ein eigenes Projekt mit dem Generator Jakarta EE an: Vorlage REST service, Build-Werkzeug Maven, Dein JDK. Als Application server wählst Du keinen – Open Liberty steht dort nicht zur Wahl. Vergleiche die erzeugte pom.xml mit der des Backends: Was müsstest Du übernehmen, damit liberty:dev auch hier läuft?

    Oder nimm die Übung zum Frontend dazu.

    Reflexionsfragen

    • In Eclipse hättest Du vielleicht einen Server in der Ansicht Servers eingerichtet. Warum richtet diese Übung keinen Server in IntelliJ ein?
    • Warum musst Du den Debugger anhängen, statt liberty:dev einfach im Debugger zu starten?
    • Im Werkzeugfenster Beans steht ein Mapper, für den es im Projekt keine Klasse gibt, nur ein Interface. Woher kommt die Bean?
    • Was hat der Dev-Modus getan, als Du RoomResource geändert hast – und was hättest Du dafür in Eclipse getan?
