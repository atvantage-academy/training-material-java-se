Kursbeschreibung

IntelliJ IDEA Ultimate für Umsteiger

Zielgruppe

Softwareentwickler:innen mit Java-Praxis, die ihre Arbeit bisher in einer anderen Entwicklungsumgebung erledigt haben – typischerweise Eclipse – und künftig IntelliJ IDEA Ultimate einsetzen. Java, Maven und Git sind im Alltag vertraut; neu ist ausschließlich das Werkzeug.

Technische Voraussetzung: IntelliJ IDEA Ultimate ist vor Kursbeginn auf dem Arbeitsgerät installiert und lizenziert, das Übungsprojekt ist ausgecheckt. Die Installation ist nicht Teil des Kurses.

Überblick

Eine neue Entwicklungsumgebung kostet erst einmal Geschwindigkeit: Die Handgriffe sitzen, aber die Tasten liegen anders. Wer dann anfängt, IntelliJ wie ein Eclipse mit anderen Farben zu bedienen, bleibt für Monate langsamer als vorher – denn die Stellen, an denen IntelliJ wirklich mehr kann, findet man nicht im Menü, sondern im Arbeitsfluss. Dieser Tag räumt genau das ab. Er geht die Wege durch, die Du täglich gehst – Projekt öffnen, zu einer Klasse springen, Code umformen, einen Fehler einkreisen, committen – und zeigt an jeder Station, was in IntelliJ anders heißt, anders funktioniert oder in Eclipse gar nicht existiert. Statt einer Tour durch die Oberfläche lernst Du den Zugriffsweg: Jede Aktion ist über eine Suche erreichbar, und wer den Weg kennt, braucht kein Menü mehr.

Lernziele

Die Lernenden…

  • richten ein bestehendes Maven-Projekt so in IntelliJ ein, dass Bauen, Testen und Formatieren wie im Team funktionieren.
  • nutzen die Funktionen der Entwicklungsumgebung, um sich in einem unbekannten Codebestand zurechtzufinden, statt ihn zu durchsuchen.
  • lassen wiederkehrende Änderungen am Code von der Entwicklungsumgebung ausführen, statt sie von Hand zu schreiben.
  • finden Fehler durch Debugging mit IntelliJ, ohne den untersuchten Code dafür zu verändern.
  • arbeiten mit Git aus der Entwicklungsumgebung heraus und halten ihre Änderungen dabei thematisch getrennt.
  • erschließen sich eine unbekannte Funktion der Entwicklungsumgebung selbst.

Agenda (1 Tag)

Ankommen im Werkzeug

  • Das Projektmodell von IntelliJ und wie ein Maven-Projekt darin aufgeht
  • Die Oberfläche als Arbeitsmittel: Werkzeugfenster, Informationen am Zeilenrand
  • Grundkonfiguration und das Auffinden von Einstellungen
  • Formatierung, die das ganze Team teilt (EditorConfig)
  • Warum es keinen Speichern-Knopf gibt – und was stattdessen absichert

Tempo im Alltag

  • Sich im Code bewegen, ohne ihn zu durchsuchen
  • Eine unbekannte Funktion der Umgebung selbst finden
  • Code entstehen lassen statt ihn auszuschreiben
  • Wiederkehrende Änderungen in einem Zug erledigen

Code umformen

  • Umformungen, die über die Cursorposition hinaus wirken – und ihre Vorschau (Refactoring)
  • Dauerhafte Code-Prüfungen und wie sie sich von Compilerfehlern unterscheiden (Inspections)
  • Funktionale Schreibweisen ineinander überführen
  • Wann ein Vorschlag der Umgebung abzulehnen ist

Fehler finden (Debugging)

  • Ein Programm gezielt an der interessanten Stelle anhalten
  • Im angehaltenen Zustand Fragen an das Programm stellen
  • Fehlersuche, ohne den untersuchten Code zu verändern
  • Verarbeitungsketten nachvollziehen, die sich nicht Zeile für Zeile lesen lassen

Mit Git arbeiten

  • Änderungen statt Dateien in einen Commit geben
  • Angefangene Arbeit zwischenlagern (Stashing)
  • Die Historie lesen und die Herkunft einer Zeile klären
  • Konflikte im Werkzeug auflösen, ohne die Umgebung zu wechseln (Merging)

Weitere Themen

  • Effizientes Programmieren mit Code-Generatoren (Lombok, MapStruct)
  • HTTP-Anfragen als versionierter Teil des Projekts (HTTP Client)
