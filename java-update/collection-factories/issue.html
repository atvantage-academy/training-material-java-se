    Collection Factories und Sequenced Collections

    Als Entwickler:in, die eine Java-8-Anwendung auf ein aktuelles Release heben soll, möchte ich unveränderliche Sammlungen kurz anlegen und ihr erstes und letztes Element direkt abfragen, damit Konstanten und Stammdaten lesbar bleiben.

    Lernziele

    • Du legst unveränderliche Listen, Mengen und Abbildungen mit den Fabrikmethoden an.
    • Du benennst, worin sich List.of von Collections.unmodifiableList unterscheidet – bei null, Duplikaten und Reihenfolge.
    • Du fragst erstes und letztes Element und die umgekehrte Reihenfolge über die Sequenced Collections ab.
    • Du bewertest, wo sich der Umbau in Deinem Bestand lohnt.

    Definition of Done

    • Das Modul neuerungen/collection-factories baut mit Release 21, und StammdatenTest ist unverändert grün.
    • Stammdaten nutzt die Fabrikmethoden und die Methoden der Sequenced Collections statt Arrays.asList, Collections.unmodifiable… und Indexrechnung.
    • Du hast Voraussetzungen, Vorteile, Herausforderungen und den Nutzen je Anwendungsart notiert.
    • Du hast die Kontrollfragen beantwortet

    Mit Java 8 braucht eine unveränderliche Liste drei Methodenaufrufe, eine unveränderliche Map einen statischen Block, und das letzte Element einer Liste kostet eine Indexrechnung. Sieh Dir an, was die neueren Releases dafür mitbringen, und baue die Stammdaten des Shops damit um.

    Arbeitsschritte

    Worum es geht

    Seit Java 9 legen List.of, Set.of und Map.of unveränderliche Sammlungen in einem Aufruf an (JEP 269, LTS-Marke 11). Seit Java 21 haben alle geordneten Sammlungen ein erstes und ein letztes Element: getFirst(), getLast() und reversed() aus dem neuen Interface SequencedCollection (JEP 431, LTS-Marke 21). Wo beides in der Geschichte von Java steht, zeigt die LTS-Evolution.

    Das Release hochstellen

    Öffne im Übungsprojekt das Modul neuerungen/collection-factories. Stell in seiner pom.xml die Property maven.compiler.release an der Stelle mit dem Kommentar „Hier hochstellen.“ von 8 auf 21 – die höhere der beiden LTS-Marken. Baue das Modul danach:

    Kommandozeile

    Baue das Modul im Wurzelordner des Übungsprojekts und lass seine Tests laufen:

    mvn clean verify -pl neuerungen/collection-factories -am
    IntelliJ

    Starte die Run Configuration neuerungen-collection-factories. Sie baut mit clean.

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration neuerungen-collection-factories. Sie baut mit clean.

    Hinweis: Immer mit clean. Ändert sich nur das Release, hält Maven die übersetzten Klassen für aktuell.

    Der Build ist grün: Code im Stil von Java 8 übersetzt auch mit Release 21.

    Ausprobieren

    Im Modul liegt unter beispiel/ das Programm Fabriken.java. Es gehört zu keinem Build, Java startet es direkt aus dem Quelltext:

    Kommandozeile

    Starte das Beispiel im Wurzelordner des Übungsprojekts:

    java neuerungen/collection-factories/beispiel/Fabriken.java
    IntelliJ

    Öffne über View → Tool Windows → Terminal ein Terminal im Wurzelordner des Projekts und starte das Beispiel dort mit dem Befehl aus dem Reiter „Kommandozeile“. Das Beispiel gehört zu keinem Build und hat deshalb keine Run Configuration.

    Eclipse

    Öffne über Window → Show View → Terminal ein Terminal im Wurzelordner des Projekts und starte das Beispiel dort mit dem Befehl aus dem Reiter „Kommandozeile“. Das Beispiel gehört zu keinem Build und hat deshalb keine Run Configuration.

    Lies den Quelltext und die Ausgabe, ändere Werte und starte erneut:

    • In welcher Reihenfolge erscheinen die Länder aus Set.of? Ist sie bei jedem Start gleich?
    • Welche der vier Versuche am Ende scheitern, und mit welcher Ausnahme?
    • Was liefert getFirst() bei einer leeren Liste? Probiere es aus.

    Die Vorlage umbauen

    Die Klasse Stammdaten im selben Modul ist im Stil von Java 8 geschrieben. Baue sie mit den Fabrikmethoden und den Sequenced Collections um. StammdatenTest sichert das Verhalten ab – er bleibt unverändert und muss grün bleiben. Baue danach das Modul erneut.

    Lösungsweg
    • ZAHLARTEN = List.of("Rechnung", "Lastschrift", "Kreditkarte", "PayPal")
    • LIEFERLÄNDER = Set.of("DE", "AT", "CH")
    • ZAHLUNGSZIEL_TAGE = Map.of("Rechnung", 14, "Lastschrift", 3) – der statische Block entfällt.
    • bevorzugteZahlart() liefert ZAHLARTEN.getFirst(), letzteZahlart() ZAHLARTEN.getLast(), zahlartenRückwärts() ZAHLARTEN.reversed().

    Die Importe von ArrayList, Arrays, Collections, HashMap und HashSet fallen weg.

    Bewerten

    Halte für Dich fest, kurz und in Stichworten:

    • Voraussetzungen: Welches Release brauchen alle, die den Code bauen und betreiben?
    • Vorteile: Was wird kürzer, was sicherer?
    • Herausforderungen: Was verhält sich anders als vorher?
    • Betrifft mich das? Wie hoch ist der Nutzen für einen REST-Microservice, ein Batch-Programm und eine Server-Anwendung (Java EE/Jakarta EE) – gering, mittel oder hoch?

    Reflexionsfragen

    • List.of(…).contains(null) wirft eine Ausnahme, Collections.unmodifiableList(…).contains(null) nicht. Wo könnte Dein Bestand darauf angewiesen sein?
    • Ein Test prüft die Ausgabe einer Map, die mit Map.of entstanden ist. Warum kann er auf einem anderen JDK plötzlich rot werden?
    • reversed() liefert eine Ansicht, keine Kopie. Wann ist das ein Vorteil, wann eine Falle?
