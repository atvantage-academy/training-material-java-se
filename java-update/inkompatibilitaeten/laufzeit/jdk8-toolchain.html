    JDK 8 als Toolchain einrichten

    Definition of Done
    • Ein JDK 8 ist installiert, und java -version aus seinem Ordner meldet 1.8.0_….
    • ~/.m2/toolchains.xml führt das JDK 8 mit der Version 1.8.
    • mvn -v meldet weiter Dein aktuelles JDK, nicht das JDK 8.
    • Der Test im Modul inkompatibilitaeten/laufzeit/toolchain ist mit dem Profil jdk8 grün.

    Die Übungen zu den Brüchen zur Laufzeit – Datumsformat, Zeitstempel, JAXB, Reflection, Security Manager, Zeichensatz – starten mit einem roten Test. --release 8 legt nur fest, gegen welche Sprache und API übersetzt wird; laufen tut der Code auf Deinem JDK 21 oder 25. Wie der Test vor dem Umstieg ausging, beschreibt jede Übung. Mit einem zusätzlichen JDK 8 siehst Du es selbst.

    Dafür stellst Du nichts um: Maven läuft weiter auf Deinem aktuellen JDK und übersetzt damit. Nur die Tests laufen über eine Maven-Toolchain auf dem JDK 8. Das übernimmt das Profil jdk8 im Übungsprojekt; es braucht nur zu wissen, wo das JDK 8 liegt. Das trägst Du einmal in ~/.m2/toolchains.xml ein.

    Schritte

    Ein JDK 8 installieren

    Installiere ein JDK 8 neben Deinem aktuellen JDK. Mach es nicht zum Standard: JAVA_HOME und PATH bleiben, wie sie sind.

    IntelliJ

    Unter File → Project Structure… → Platform Settings → SDKs fügst Du mit + → Download JDK… ein JDK hinzu: Version 1.8, Anbieter etwa Azul Zulu oder Amazon Corretto. IntelliJ legt es in Deinem Benutzerordner ab und braucht dafür keine Administratorrechte. Den Ordner zeigt die Liste der SDKs an.

    macOS

    Mit Homebrew installierst Du Azul Zulu 8. Das Paket gibt es für Intel- und Apple-Prozessoren; Homebrew wählt das passende selbst:

    brew install --cask zulu@8

    Ohne Homebrew lädst Du ein JDK 8 als .pkg oder .dmg herunter und installierst es: Azul Zulu 8 oder Amazon Corretto 8, jeweils für Deinen Prozessor.

    Hinweis: Eclipse Temurin gibt es für Java 8 auf dem Mac nur für Intel-Prozessoren, auch als Homebrew-Paket temurin@8. Auf einem Mac mit Apple-Prozessor (M1 und neuer) liefe es nur über Rosetta – nimm dort Zulu oder Corretto.

    Homebrew und die Installer legen das JDK unter /Library/Java/JavaVirtualMachines ab. Dein Standard-JDK ändert sich dadurch nicht: macOS nimmt weiter das neueste.

    Windows

    Mit Chocolatey installierst Du Eclipse Temurin 8. Öffne eine PowerShell als Administrator und installiere nur das JDK selbst – ohne Eintrag in PATH und ohne Verknüpfung der .jar-Dateien, die das Paket sonst mitbringt:

    choco install temurin8 --params="/ADDLOCAL=FeatureMain /INSTALLDIR=$env:ProgramFiles\Eclipse Adoptium\"

    Ohne Chocolatey lädst Du Eclipse Temurin 8 als .msi herunter und installierst es. Lass im Installer die Punkte „Set JAVA_HOME variable“ und „Add to PATH“ abgewählt.

    Prüfe danach in einer neuen Konsole, dass java -version weiter Dein aktuelles JDK meldet.

    Linux

    Installiere das JDK 8 über die Paketverwaltung, unter Debian und Ubuntu etwa:

    sudo apt install openjdk-8-jdk

    Prüfe danach, dass java -version weiter Dein aktuelles JDK meldet. Falls nicht, stellst Du es mit sudo update-alternatives --config java zurück.

    Den Ordner des JDK 8 finden

    Für die Toolchain brauchst Du den Ordner des JDK – den, in dem bin/java liegt.

    macOS

    Lass Dir den Ordner des JDK 8 anzeigen:

    /usr/libexec/java_home -v 1.8

    Typisch ist /Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home, von IntelliJ geladen ~/Library/Java/JavaVirtualMachines/…/Contents/Home.

    Windows

    Typisch ist C:\Program Files\Eclipse Adoptium\jdk-8.0.…-hotspot, von IntelliJ geladen C:\Users\«Du»\.jdks\…. Sieh im Explorer nach, wie der Ordner bei Dir genau heißt.

    Linux

    Lass Dir die installierten JDKs anzeigen:

    ls /usr/lib/jvm

    Typisch ist /usr/lib/jvm/java-8-openjdk-amd64.

    Prüfe den Ordner, indem Du das java darin direkt aufrufst:

    «ordner»/bin/java -version

    Die Ausgabe beginnt mit openjdk version "1.8.0_…".

    Das JDK 8 in toolchains.xml eintragen

    Lege die Datei toolchains.xml im Ordner .m2 Deines Benutzerordners an (~/.m2/toolchains.xml, unter Windows C:\Users\«Du»\.m2\toolchains.xml) und setze bei jdkHome den Ordner aus dem vorigen Schritt ein:

    <?xml version="1.0" encoding="UTF-8"?>
<toolchains>
  <toolchain>
    <type>jdk</type>
    <provides>
      <version>1.8</version>
    </provides>
    <configuration>
      <jdkHome>/Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home</jdkHome>
    </configuration>
  </toolchain>
</toolchains>

    Gibt es die Datei schon, ergänzt Du nur den Abschnitt <toolchain> innerhalb von <toolchains>. Ob dort 1.8 oder 8 als Version steht, ist gleich: Das Profil sucht jede Version ab 1.8 und unter 9.

    Hinweis: IntelliJ IDEA und Eclipse lesen dieselbe Datei. In Eclipse siehst Du unter Window → Preferences → Maven → User Settings (auf dem Mac Eclipse → Settings…) bei User Toolchains, welche Datei es nimmt.

    Die Einrichtung prüfen

    Für diese Prüfung hat das Übungsprojekt ein eigenes Modul, inkompatibilitaeten/laufzeit/toolchain. Es enthält nur einen Test, und der läuft nur mit dem Profil jdk8. Grün ist er nur, wenn er wirklich auf einem JDK 8 läuft.

    Kommandozeile

    Prüfe zuerst, dass Maven weiter auf Deinem aktuellen JDK läuft:

    mvn -v

    Baue dann das Modul im Wurzelordner des Übungsprojekts mit dem Profil jdk8:

    mvn clean verify -pl inkompatibilitaeten/laufzeit/toolchain -am -Pjdk8
    IntelliJ

    Starte die Run Configuration laufzeit-toolchain. Sie baut mit clean und dem Profil jdk8.

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration laufzeit-toolchain. Sie baut mit clean und dem Profil jdk8.

    VS Code

    Starte über Terminal → Run Task… den Task laufzeit-toolchain. Er baut mit clean und dem Profil jdk8.

    In der Ausgabe steht vor dem Test, welches JDK ihn ausführt, und der Test nennt es noch einmal selbst:

    [INFO] Toolchain in maven-surefire-plugin: JDK[/Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home]
Die Tests laufen auf Java 1.8.0_512 (Azul Systems, Inc.) aus /Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home/jre

    Geht etwas schief, sagt Dir die Meldung, wo Du suchen musst:

    • „Requested toolchain specification did not match any configured toolchain“ – Maven findet keinen passenden Eintrag. Prüfe Name und Ort der Datei und die Version in toolchains.xml. Steht davor „Misconfigured toolchain.“, gibt es den Ordner bei jdkHome nicht.
    • „Die Tests laufen nicht auf JDK 8“ – der Eintrag passt, aber jdkHome zeigt auf ein anderes JDK.

    Die Übungen zu den Brüchen zur Laufzeit haben je eine eigene Run Configuration mit -jdk8 am Ende, etwa laufzeit-jaxb-jdk8. Sie nennen sie an der Stelle, an der Du den Stand vorher sehen kannst.
