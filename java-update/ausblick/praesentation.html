Ausblick: von Java 26 bis Java 29

Was nach Java 25 kommt · Java-Update

Der Zug fährt weiter

  • 26 und 27 sind erschienen, die Liste für 28 füllt sich bis Dezember
  • Was bis 29 final wird, trägt die Marke LTS 29 – alles andere frühestens LTS 33

Stand Oktober 2026 – JEP 543, 532, 401, 531, 517, 540

Die JVM wird von selbst besser

  • G1 überall Standard (27, JEP 523): Im Container mit einem Kern und 1 GB wählt 25 noch Serial, 27 den G1 – gemessen
  • Kompakte Objekt-Header Standard (27, JEP 534): weniger Heap, ohne Code zu ändern
  • AOT-Cache mit jedem GC, auch ZGC (26, JEP 516), und mit übersetztem Code (28, JEP 544)
  • ZGC startet schneller und passt den Heap selbst an (28, JEP 545, 546)

Was in der JVM-Einheit Startskript und Dockerfile brauchten, erledigt das JDK zunehmend selbst

Was als Nächstes bricht

$ java spielwiese/FinalesFeld.java              # JDK 26 und 27
WARNING: Final field nummer in class FinalesFeld$Bestellung has been mutated reflectively …
WARNING: Mutating final fields will be blocked in a future release …
Nummer nach der Änderung: B-9999

$ java --illegal-final-field-mutation=deny spielwiese/FinalesFeld.java
Exception in thread "main" java.lang.IllegalAccessException: … not allowed to mutate final fields
  • „Final means final“ (26, JEP 500): heute eine Warnung, künftig ein Verbot – betrifft Bibliotheken, die final-Felder per Reflection setzen
  • Applet-API entfernt (26, JEP 504), macOS auf Intel zur Entfernung vorgesehen (28, JEP 541)
  • Dasselbe Muster wie bei der starken Kapselung: erst warnen, dann verbieten. Wer Warnungen liest, wird nicht überrascht

Valhalla: Objekte ohne Identität

value record Geldbetrag(long cent, String währung) {}

var a = new Geldbetrag(1999, "EUR");
var b = new Geldbetrag(1999, "EUR");
a == b                    // true – gleich ist gleich
synchronized (a) { … }    // scheitert: ein Wert hat keinen Monitor
  • Preview in 28 (JEP 401) – Projekt Valhalla, an dem seit 2014 gearbeitet wird
  • Im Preview-Modus werden Integer, Optional, LocalDate und weitere zu Wertklassen: synchronized auf ihnen scheitert, == vergleicht den Wert
