    Die JVM unter die Lupe nehmen

    Als Entwickler:in, deren Anwendung im Container und unter Last läuft, möchte ich wissen, was die JVM von selbst entscheidet und wie ich ihr beim Starten und Messen helfe, damit ich die Optionen in Startskript und Dockerfile begründen kann.

    Lernziele
    • Du liest ab, welchen Garbage Collector und wie viel Heap die JVM wählt – ohne und mit knappen Ressourcen.
    • Du vergleichst die Garbage Collectors an Pausen und Laufzeit und begründest, welcher zu Deiner Anwendungsart passt.
    • Du erzeugst einen AOT-Cache (JDK 25) bzw. ein CDS-Archiv (JDK 21) und misst den Unterschied beim Start.
    • Du zeichnest einen Lasttest mit Java Flight Recorder auf und wertest ihn mit jfr view aus.
    • Du bewertest, welche JVM-Einstellungen in Eure Startskripte gehören.
    Definition of Done

    Ergonomie und Garbage Collector

    • Du kannst sagen, welchen GC und welche Heap-Größe die JVM mit einem Kern und 1 GB wählt.
    • Du hast mindestens drei Collectors an längster Pause und Laufzeit verglichen und einen für Deine Anwendungsart begründet gewählt.

    Start und Flight Recorder

    • Du hast die Startzeit mit und ohne Archiv bzw. Cache gemessen.
    • Du hast eine JFR-Aufzeichnung mit mindestens zwei Ansichten von jfr view ausgewertet.

    Bewertung

    • Du hast notiert, welche Optionen Ihr in Startskript oder Dockerfile setzen würdet – und welche Ihr streicht.

    Für die ganze Seite

    • Du hast die Kontrollfragen beantwortet

    Du änderst keinen Code – Du startest die REST-Schnittstelle der Bestellabwicklung und zwei kleine Programme mit anderen JVM-Optionen und misst, was sich ändert. Wie die Collectors arbeiten, was die JVM im Container wählt und was CDS und AOT-Cache tun, zeigt die Visualisierung Die Laufzeitumgebung seit Java 8.

    Hinweis: Du brauchst JDK 21 oder 25. Wo ein Schritt nur mit einem der beiden geht, steht es dabei. Alles liegt im Modul schwerpunkte/jvm-fuer-entwickler, mit einer eigenen Kopie der Bestellabwicklung – was Du in anderen Übungen am Projekt geändert hast, spielt hier keine Rolle. Zu jedem Befehl gibt es eine Run Configuration (in VS Code einen Task); sie ruft über Maven genau diesen Befehl auf, mit dem JDK, mit dem Deine IDE Maven startet – in VS Code mit dem, das mvn -v im Terminal nennt.

    Arbeitsschritte

    Das Modul bauen

    Danach liegt die REST-Schnittstelle als startbares JAR in target/jvm-fuer-entwickler.jar; die beiden Programme Speicherlast.java und Angeheftet.java liegen als Quelldateien daneben und starten ohne Übersetzen.

    Kommandozeile

    Wechsle in den Ordner des Moduls und baue es – alle weiteren Befehle laufen in diesem Ordner:

    cd schwerpunkte/jvm-fuer-entwickler && mvn clean verify
    IntelliJ

    Starte die Run Configuration schwerpunkte-jvm-fuer-entwickler.

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration schwerpunkte-jvm-fuer-entwickler.

    VS Code

    Starte über Terminal → Run Task… den Task schwerpunkte-jvm-fuer-entwickler.

    Was wählt die JVM?

    Lass die JVM zeigen, wie sie sich eingerichtet hat, und stell danach einen kleinen Container nach, mit einem Kern und 1 GB:

    Kommandozeile

    Zeig, was die JVM auf Deinem Rechner wählt:

    java -Xlog:gc,gc+init -version

    Stell den kleinen Container nach:

    java -XX:ActiveProcessorCount=1 -XX:MaxRAM=1g -Xlog:gc,gc+init -version
    IntelliJ

    Starte nacheinander die Run Configurations:

    • schwerpunkte-jvm-fuer-entwickler-ergonomie – zeigt, was die JVM auf Deinem Rechner wählt.
    • schwerpunkte-jvm-fuer-entwickler-ergonomie-klein – stellt den kleinen Container nach, mit einem Kern und 1 GB.
    Eclipse

    Starte unter Run → Run Configurations… → Maven Build nacheinander die Konfigurationen:

    • schwerpunkte-jvm-fuer-entwickler-ergonomie – zeigt, was die JVM auf Deinem Rechner wählt.
    • schwerpunkte-jvm-fuer-entwickler-ergonomie-klein – stellt den kleinen Container nach, mit einem Kern und 1 GB.
    VS Code

    Starte über Terminal → Run Task… nacheinander die Tasks:

    • schwerpunkte-jvm-fuer-entwickler-ergonomie – zeigt, was die JVM auf Deinem Rechner wählt.
    • schwerpunkte-jvm-fuer-entwickler-ergonomie-klein – stellt den kleinen Container nach, mit einem Kern und 1 GB.

    Lies ab: Welcher GC? Wie viele Prozessoren? Wie groß darf der Heap werden – und welcher Anteil Deines Arbeitsspeichers ist das? Was hat sich im kleinen Container geändert, und warum?

    Hinweis: Wer Docker hat, probiert es im echten Container: docker run --rm --cpus 1 -m 1g eclipse-temurin:25 java -Xlog:gc,gc+init -version. Mit eclipse-temurin:27 sieht das Ergebnis anders aus.

    Die Garbage Collectors vergleichen

    Speicherlast.java hält drei Millionen Bestellpositionen im Speicher und erzeugt daneben viele kurzlebige – Arbeit für den Garbage Collector. Starte sie mit G1, zeichne den Lauf mit dem Flight Recorder auf und sieh Dir die Pausen an:

    Kommandozeile

    Starte die Speicherlast mit G1 und zeichne auf:

    java -XX:+UseG1GC -Xmx1g -XX:StartFlightRecording=filename=gc.jfr Speicherlast.java

    Sieh Dir die Pausen an:

    jfr view gc-pauses gc.jfr

    Wiederhole beides mit -XX:+UseSerialGC, -XX:+UseParallelGC und -XX:+UseZGC anstelle von -XX:+UseG1GC.

    IntelliJ

    Starte nacheinander die Run Configurations:

    • schwerpunkte-jvm-fuer-entwickler-gc-g1 – startet die Speicherlast mit G1, zeichnet sie in gc.jfr auf und zeigt danach die Pausen (jfr view gc-pauses).
    • schwerpunkte-jvm-fuer-entwickler-gc-serial – dasselbe mit dem Serial GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-parallel – dasselbe mit dem Parallel GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-z – dasselbe mit ZGC.
    Eclipse

    Starte unter Run → Run Configurations… → Maven Build nacheinander die Konfigurationen:

    • schwerpunkte-jvm-fuer-entwickler-gc-g1 – startet die Speicherlast mit G1, zeichnet sie in gc.jfr auf und zeigt danach die Pausen (jfr view gc-pauses).
    • schwerpunkte-jvm-fuer-entwickler-gc-serial – dasselbe mit dem Serial GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-parallel – dasselbe mit dem Parallel GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-z – dasselbe mit ZGC.
    VS Code

    Starte über Terminal → Run Task… nacheinander die Tasks:

    • schwerpunkte-jvm-fuer-entwickler-gc-g1 – startet die Speicherlast mit G1, zeichnet sie in gc.jfr auf und zeigt danach die Pausen (jfr view gc-pauses).
    • schwerpunkte-jvm-fuer-entwickler-gc-serial – dasselbe mit dem Serial GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-parallel – dasselbe mit dem Parallel GC.
    • schwerpunkte-jvm-fuer-entwickler-gc-z – dasselbe mit ZGC.

    Halte je Collector die Laufzeit, die Zahl der Pausen und die längste Pause fest.

    Recherchiere dann in der Visualisierung und im Garbage Collection Tuning Guide (unter den Ressourcen): Wie arbeitet jeder Collector, was kostet er, wann ist er sinnvoll? Welchen würdest Du für Eure Anwendung wählen?

    Hinweis: jfr liegt im bin-Ordner Deines JDK. Shenandoah fehlt in den Builds von Oracle; mit Temurin kannst Du ihn mit -XX:+UseShenandoahGC dazunehmen (Run Configuration schwerpunkte-jvm-fuer-entwickler-gc-shenandoah).

    Den Start verkürzen

    Als Messlatte dient der Lasttest mit einer Bestellung – er startet die REST-Schnittstelle, schickt eine Anfrage und endet. 100 ms davon wartet die Anfrage aufs Lager. In der letzten Zeile nennt er, wie lange die JVM vom Start bis zum Ende lief.

    Kommandozeile

    Miss den Start ohne eigenes Archiv:

    java -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1

    Mit JDK 25 lässt Du einen Trainingslauf einen AOT-Cache schreiben:

    java -XX:AOTCacheOutput=rest.aot -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1

    Starte dann mit dem Cache und miss wieder:

    java -XX:AOTCache=rest.aot -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1

    Mit JDK 21 schreibt der erste Lauf ein CDS-Archiv:

    java -XX:ArchiveClassesAtExit=rest.jsa -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1

    Starte dann mit dem Archiv und miss wieder:

    java -XX:SharedArchiveFile=rest.jsa -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1
    IntelliJ

    Starte nacheinander die Run Configurations:

    • schwerpunkte-jvm-fuer-entwickler-start – misst den Start ohne eigenes Archiv.
    • schwerpunkte-jvm-fuer-entwickler-start-aot-training (JDK 25) – lässt einen Trainingslauf den AOT-Cache rest.aot schreiben.
    • schwerpunkte-jvm-fuer-entwickler-start-aot (JDK 25) – startet mit dem AOT-Cache und misst wieder.
    • schwerpunkte-jvm-fuer-entwickler-start-cds-training (JDK 21) – lässt den ersten Lauf das CDS-Archiv rest.jsa schreiben.
    • schwerpunkte-jvm-fuer-entwickler-start-cds (JDK 21) – startet mit dem CDS-Archiv und misst wieder.
    Eclipse

    Starte unter Run → Run Configurations… → Maven Build nacheinander die Konfigurationen:

    • schwerpunkte-jvm-fuer-entwickler-start – misst den Start ohne eigenes Archiv.
    • schwerpunkte-jvm-fuer-entwickler-start-aot-training (JDK 25) – lässt einen Trainingslauf den AOT-Cache rest.aot schreiben.
    • schwerpunkte-jvm-fuer-entwickler-start-aot (JDK 25) – startet mit dem AOT-Cache und misst wieder.
    • schwerpunkte-jvm-fuer-entwickler-start-cds-training (JDK 21) – lässt den ersten Lauf das CDS-Archiv rest.jsa schreiben.
    • schwerpunkte-jvm-fuer-entwickler-start-cds (JDK 21) – startet mit dem CDS-Archiv und misst wieder.
    VS Code

    Starte über Terminal → Run Task… nacheinander die Tasks:

    • schwerpunkte-jvm-fuer-entwickler-start – misst den Start ohne eigenes Archiv.
    • schwerpunkte-jvm-fuer-entwickler-start-aot-training (JDK 25) – lässt einen Trainingslauf den AOT-Cache rest.aot schreiben.

    Wie viel schneller ist der Start? Und was müsste geschehen, damit Eure Anwendung beim Kunden mit genau diesem Cache startet?

    Hinweis: Miss jeden Fall mehrmals; der erste Lauf nach dem Bauen ist immer langsamer. Bau das Modul zwischen Trainingslauf und Messung nicht neu – zu einem neu gebauten JAR passt der Cache nicht mehr.

    Mit dem Flight Recorder messen

    Zeichne einen größeren Lasttest auf – er dauert gut zehn Sekunden – und sieh nach, wo die Rechenzeit hingeht und welche Klassen den meisten Speicher anlegen:

    Kommandozeile

    Zeichne den Lasttest auf:

    java -XX:StartFlightRecording=filename=last.jfr,settings=profile -cp target/jvm-fuer-entwickler.jar bestellung.rest.Lasttest 1000

    Sieh nach, wo die Rechenzeit hingeht:

    jfr view hot-methods last.jfr

    Sieh nach, welche Klassen den meisten Speicher anlegen:

    jfr view allocation-by-class last.jfr
    IntelliJ

    Starte die Run Configuration schwerpunkte-jvm-fuer-entwickler-flight-recorder. Damit zeichnest Du den Lasttest in last.jfr auf und siehst danach, wo die Rechenzeit hingeht (jfr view hot-methods) und welche Klassen den meisten Speicher anlegen (jfr view allocation-by-class).

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration schwerpunkte-jvm-fuer-entwickler-flight-recorder. Damit zeichnest Du den Lasttest in last.jfr auf und siehst danach, wo die Rechenzeit hingeht (jfr view hot-methods) und welche Klassen den meisten Speicher anlegen (jfr view allocation-by-class).

    VS Code

    Starte über Terminal → Run Task… den Task schwerpunkte-jvm-fuer-entwickler-flight-recorder. Damit zeichnest Du den Lasttest in last.jfr auf und siehst danach, wo die Rechenzeit hingeht (jfr view hot-methods) und welche Klassen den meisten Speicher anlegen (jfr view allocation-by-class).

    Was überrascht Dich?

    Optional: jfr help view listet alle Ansichten – probiere auf der Kommandozeile eine weitere, etwa jfr view thread-count last.jfr.

    Kür: kompakte Objekt-Header (JDK 25)

    Starte die Speicherlast mit und ohne kompakte Header und vergleiche, wie viel Speicher der Bestand belegt (letzte Zeile der Ausgabe):

    Kommandozeile

    Starte sie mit kompakten Headern:

    java -XX:+UseCompactObjectHeaders -Xmx1g Speicherlast.java

    Starte sie zum Vergleich ohne:

    java -XX:-UseCompactObjectHeaders -Xmx1g Speicherlast.java
    IntelliJ

    Starte nacheinander die Run Configurations:

    • schwerpunkte-jvm-fuer-entwickler-header-kompakt – startet die Speicherlast mit kompakten Headern.
    • schwerpunkte-jvm-fuer-entwickler-header-klassisch – startet sie zum Vergleich ohne.
    Eclipse

    • schwerpunkte-jvm-fuer-entwickler-header-kompakt – startet die Speicherlast mit kompakten Headern.

    Kür: Pinning nachweisen (JDK 21 und 25)

    Angeheftet.java lässt 200 virtuelle Threads in einem synchronized-Block warten – wie die Fremdsysteme der Bestellabwicklung. Zeichne den Lauf auf und sieh nach, welche virtuellen Threads ihren Träger festgehalten haben:

    Kommandozeile

    Zeichne den Lauf auf:

    java -XX:StartFlightRecording=filename=angeheftet.jfr Angeheftet.java

    Sieh Dir die angehefteten Threads an:

    jfr view pinned-threads angeheftet.jfr
    IntelliJ

    Starte die Run Configuration schwerpunkte-jvm-fuer-entwickler-pinning. Damit zeichnest Du den Lauf in angeheftet.jfr auf und siehst danach die angehefteten Threads (jfr view pinned-threads).

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration schwerpunkte-jvm-fuer-entwickler-pinning. Damit zeichnest Du den Lauf in angeheftet.jfr auf und siehst danach die angehefteten Threads (jfr view pinned-threads).

    VS Code

    Starte über Terminal → Run Task… den Task schwerpunkte-jvm-fuer-entwickler-pinning. Damit zeichnest Du den Lauf in angeheftet.jfr auf und siehst danach die angehefteten Threads (jfr view pinned-threads).

    Bewerten

    Halte in Stichworten fest:

    • Ergonomie: Was wählt die JVM in Eurem Container – und würdet Ihr das so lassen?
    • Garbage Collector: Welchen nehmt Ihr für einen REST-Microservice, ein Batch-Programm, eine Server-Anwendung?
    • Start: Lohnt ein AOT-Cache bzw. ein CDS-Archiv bei Euch, und wo entstünde er?
    • Startskripte: Welche Optionen würdet Ihr setzen – und welche streichen?

    Reflexionsfragen

    • Eure Anwendung läuft im Container mit einem Kern und 1 GB. Was wählt die JVM – und ist das gut?
    • Warum nehmt Ihr nicht immer ZGC?
    • Wann lohnt ein AOT-Cache, und wo gehört der Trainingslauf hin?
