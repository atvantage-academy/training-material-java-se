    Start/Java-Update/Kursbeschreibung

    Kursbeschreibung

    Zielgruppe

    Java-Entwickler:innen, deren Wissen auf dem Stand von Java 8 ist – Lambdas, Streams, Optional und java.time sind vertraut – und deren Projekte auf ein aktuelles LTS-Release umziehen sollen oder schon umgezogen sind. Der Kurs spricht Teams an, die REST-Microservices (z. B. mit Quarkus), Batch-Programme oder Server-Anwendungen auf Java-EE-/Jakarta-EE-Basis entwickeln.

    Überblick

    Zwischen Java 8 und Java 25 liegen vier LTS-Releases und mehrere hundert Änderungen. Manches davon ist bloße Bequemlichkeit, manches verändert, wie man Daten modelliert oder Nebenläufigkeit schreibt – und einiges bricht Code, der jahrelang lief. In zwei Tagen hebst Du eine Java-8-Anwendung Schritt für Schritt auf ein aktuelles Release: Du lernst die Neuerungen kennen, probierst sie am Code aus und entscheidest jeweils, ob sie sich für Deine Art von Anwendung lohnen. Am Ende steht keine Feature-Liste, sondern eine begründete Empfehlung für die Migration.

    Lernziele

    Die Lernenden…

    • ordnen Sprach-, API- und Laufzeit-Neuerungen ihrem LTS-Release zu und unterscheiden finale Features von Preview- und Incubator-Features.
    • heben Code über LTS-Grenzen hinweg an, beheben typische Kompatibilitätsbrüche an ihrer Ursache und schätzen deren Risiko für die eigene Anwendung ein.
    • probieren Neuerungen in Syntax und API am Code aus und bewerten sie nach Voraussetzungen, Vorteilen und Herausforderungen.
    • modellieren Daten mit Records, versiegelten Typen und Pattern Matching und begründen, wann klassische Polymorphie die bessere Wahl bleibt.
    • deklarieren Teile einer Anwendung als Module und beurteilen, wo das Modulsystem im Bestand Probleme macht und wo es sich lohnt.
    • stellen blockierenden Code auf Virtual Threads um, messen den Effekt und grenzen den Ansatz gegen reaktive Programmierung ab.
    • leiten für REST-Microservices, Batch-Programme und Server-Anwendungen eine begründete Empfehlung ab, welche Neuerungen sich lohnen und wo Risiken liegen.

    Agenda (2 Tage)

    Inkompatibilitäten und Neuerungen sind kurze, voneinander unabhängige Einheiten: Der Trainer wählt sie passend zu den Anwendungen der Gruppe aus und verteilt sie zwischen die Schwerpunkte. Die als optional gekennzeichneten Schwerpunkte kommen je nach Gruppe hinzu.

    Überblick: Wie Java heute entsteht

    • Warum es alle sechs Monate ein neues Java gibt – und welche Version man davon wirklich einsetzt (LTS)
    • Woran man erkennt, ob ein Feature fertig ist oder sich noch ändern darf – am Beispiel der zurückgezogenen String-Interpolation (JEP, Preview, Incubator)
    • Wie man denselben Code gezielt für ein älteres Release übersetzt (--release)

    Inkompatibilitäten: Was beim Umstieg bricht

    • Warum Code, der mit Java 8 lief, auf einem neuen JDK nicht mehr übersetzt oder sich anders verhält
    • Was aus Bibliotheken wurde, die früher im JDK steckten (JAXB, JAX-WS)
    • Warum Reflection auf JDK-Interna plötzlich verboten ist – und was man stattdessen tut (starke Kapselung)
    • Wie sich Tests verhalten, wenn sich Zeichensatz, Datumsformate oder Zeitstempel-Genauigkeit ändern
    • Wo neue Sprachmittel und Methoden mit eigenem Code kollidieren (_, yield, Sequenced Collections) und was vom Security Manager bleibt
    • Wie hoch das Risiko eines Bruchs für die eigene Anwendung ist

    Neuerungen in Syntax und API

    • Welche Hilfsmethoden man nicht mehr selbst schreiben muss (Collection Factories, Sequenced Collections, String, Stream, HTTP-Client)
    • Wo Typangaben, Fallunterscheidungen und Zeichenketten über mehrere Zeilen den Code unnötig aufblähen (var, Switch Expressions, Text-Blöcke)
    • Wie man unveränderliche Datenträger ohne Boilerplate schreibt und der Compiler prüft, dass jeder Fall behandelt ist (Records, Sealed Classes, Pattern Matching)
    • Was Java 25 neu mitbringt (LTS 25: kompakte Quelldateien, Markdown in Javadoc, Scoped Values, flexible Konstruktoren)
    • Was ein Feature voraussetzt, was es bringt und wo es schwierig wird

    Schwerpunkt: Das Modulsystem

    • Welche Probleme des Classpath das Modulsystem löst – und warum es trotzdem freiwillig blieb
    • Wie man Module deklariert, Abhängigkeiten und Schnittstellen festlegt und eine eigene Laufzeitumgebung baut (module-info.java, jlink)
    • Ob sich Module für Quarkus-Anwendungen oder auf einem Jakarta-EE-Server lohnen

    Schwerpunkt: Nebenläufigkeit ohne Thread-Pool-Arithmetik

    • Warum ein Server mit einem Thread je Anfrage bisher an seine Grenzen kam
    • Wie sich blockierender Code skalieren lässt, ohne ihn reaktiv umzuschreiben (Virtual Threads)
    • Ob reaktive Programmierung damit überflüssig wird

    Schwerpunkt: Die JVM unter der Haube (optional)

    • Welcher Garbage Collector zu welcher Anwendung passt
    • Wie eine Anwendung im Container ihre Ressourcen richtig erkennt
    • Wie man die Startzeit eines Service verkürzt (CDS, AOT-Cache) und den Speicherbedarf senkt (Compact Object Headers)
    • Wie man in Produktion nachsieht, was die JVM tut (Java Flight Recorder)

    Schwerpunkt: Werte ohne Identität (optional)

    • Warum Java Objekte ohne Identität bekommen soll – für Speicher, Performance und eine genauere Abbildung der Domäne (Project Valhalla, Value Classes)
    • Was man davon schon heute beachten muss (wertbasierte Klassen) und was darauf wartet (Vector API)

    Abschluss: Die Migration bewerten

    • Was sich für REST-Microservices, Batch-Programme und Server-Anwendungen jeweils lohnt – und wo die Risiken liegen
    • Was mit den nächsten Releases bis zum LTS-Release Java 29 kommt

    Technische Voraussetzungen

    • JDK 21 oder JDK 25 auf jedem Arbeitsgerät – JDK 25 empfohlen. Wer nur JDK 21 hat, kann alle Kernübungen bearbeiten; die Teile zu Java 22–25 zeigt dann der Trainer. Ein JDK lässt sich auch ohne Administratorrechte im Benutzerverzeichnis installieren (z. B. über die IDE).
    • Eine Java-IDE (IntelliJ IDEA, Eclipse oder VS Code mit Java-Erweiterungen).
    • Maven 3.9 oder neuer, installiert und auf der Kommandozeile aufrufbar (mvn -v).
    • Internetzugang zu Maven Central und Lesezugriff auf GitHub für das Übungsrepository.
    • Für die Online-Durchführung: Kamera, Mikrofon und die Möglichkeit, den Bildschirm zu teilen.
