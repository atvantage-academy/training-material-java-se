Scoped Values

Ein Scoped Value hält einen Wert für die Dauer eines Aufrufs: Wer ihn bindet, ruft eine Aufgabe auf, und überall darin lässt er sich lesen – danach ist er wieder weg. Kein Setzen, kein Aufräumen.

seit Java 25 LTS 25 JEP 506 Preview in 21 bis 24

1 · Der Anwendungsfall

Manche Werte braucht jede Schicht einer Anfrage, ohne dass sie fachlich dazugehören: die Kennung der Anfrage für das Protokoll, der angemeldete Benutzer, der Mandant. Als Parameter müssten sie durch jede Methode wandern. Bisher hielt man sie deshalb in einer ThreadLocal:

static final ThreadLocal<String> ANFRAGE = new ThreadLocal<>();

static <T> T bearbeite(String anfrage, Callable<T> aufgabe) throws Exception {
    String vorher = ANFRAGE.get();
    ANFRAGE.set(anfrage);                // setzen
    try {
        return aufgabe.call();           // irgendwo darin: ANFRAGE.get()
    } finally {
        if (vorher == null) {
            ANFRAGE.remove();            // aufräumen – sonst sieht die nächste Anfrage den alten Wert
        } else {
            ANFRAGE.set(vorher);         // geschachtelte Anfrage: den äußeren Wert wiederherstellen
        }
    }
}

Das funktioniert, verlangt aber Disziplin – und lässt jedem die Möglichkeit, den Wert unterwegs zu ändern. Im Vergleich:

ThreadLocalScopedValue
Wert setzenset(…), jederzeit, auch mitten in der Anfragenur durch eine Bindung für einen Aufruf: where(…).run(…)
Wert ändernjeder, der die ThreadLocal siehtniemand – nur eine neue, geschachtelte Bindung verdeckt ihn
Aufräumenvon Hand mit remove(), sonst sieht die nächste Anfrage auf demselben Thread den alten Wertentfällt: Die Bindung endet mit dem Aufruf, auch nach einer Ausnahme
Viele Threadsjede Kopie kostet Speicher, auch bei virtuellen Threadsleicht, für virtuelle Threads gemacht
