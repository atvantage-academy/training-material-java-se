    Switch Expressions

    Als Entwickler:in, die eine Java-8-Anwendung auf ein aktuelles Release heben soll, möchte ich Fallunterscheidungen als Ausdruck schreiben, damit kein vergessenes break und kein vergessener Fall mehr unbemerkt bleibt.

    Lernziele

    • Du schreibst switch als Ausdruck mit Pfeilen, mehreren Marken je Fall und yield.
    • Du nutzt, dass der Compiler einen switch-Ausdruck über ein enum auf Vollständigkeit prüft.
    • Du unterscheidest, wann ein default nötig ist und wann er eine Prüfung verschenkt.
    • Du bewertest, wo sich der Umbau in Deinem Bestand lohnt.

    Definition of Done

    • Das Modul neuerungen/syntax/switch-expressions baut mit Release 17, und ZahlartregelnTest ist unverändert grün.
    • Alle drei Methoden von Zahlartregeln nutzen switch-Ausdrücke ohne break; der switch über Zahlart kommt ohne default aus.
    • Du hast die Kontrollfragen beantwortet

    Mit Java 8 ist switch eine Anweisung: Jeder Fall braucht sein break, ein Ergebnis entsteht über eine Variable, und fehlt ein Fall, merkt es niemand. Sieh Dir an, was neuere Releases daraus machen, und baue die Regeln je Zahlart damit um.

    Arbeitsschritte

    Worum es geht

    Seit Java 14 ist switch auch ein Ausdruck, der einen Wert liefert (JEP 361, LTS-Marke 17). Mit Pfeilen (case A, B ->) fällt nichts mehr durch, yield liefert den Wert eines Falls mit mehreren Anweisungen, und über ein enum prüft der Compiler, dass jeder Wert einen Fall hat.

    Das Release hochstellen

    Öffne im Übungsprojekt das Modul neuerungen/syntax/switch-expressions. Stell in seiner pom.xml die Property maven.compiler.release an der Stelle mit dem Kommentar „Hier hochstellen.“ von 8 auf 17. Baue das Modul danach:

    Kommandozeile

    Baue das Modul im Wurzelordner des Übungsprojekts und lass seine Tests laufen:

    mvn clean verify -pl neuerungen/syntax/switch-expressions -am
    IntelliJ

    Starte die Run Configuration syntax-switch-expressions. Sie baut mit clean.

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration syntax-switch-expressions. Sie baut mit clean.

    Hinweis: Immer mit clean. Ändert sich nur das Release, hält Maven die übersetzten Klassen für aktuell.

    Der Build ist grün: Code im Stil von Java 8 übersetzt auch mit Release 17.

    Die Vorlage umbauen

    Sieh Dir zuerst die Visualisierung Switch Expressions an: Sie zeigt Stufe um Stufe, wie aus der alten Form ein switch-Ausdruck wird.

    Prüfe dann in der Klasse Zahlartregeln im selben Modul, welche Stellen Du durch switch-Ausdrücke ersetzen kannst, und baue sie um. Baue das Modul danach erneut, wie oben: ZahlartregelnTest bleibt unverändert und zeigt Dir, ob sich die Anwendung weiterhin korrekt verhält.

    Reflexionsfragen

    • switch-Ausdrücke eignen sich gut für Mapper, etwa wenn ein enum der Domäne als JSON oder XML übertragen wird. Warum ist es ratsam, dafür einen switch-Ausdruck zu verwenden, statt mit Enum.name() und Enum.valueOf(…) zu mappen?
