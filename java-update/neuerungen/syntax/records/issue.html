    Records

    Als Entwickler:in, die eine Java-8-Anwendung auf ein aktuelles Release heben soll, möchte ich Wertklassen ohne handgeschriebenes equals, hashCode und toString ausdrücken, damit nur die Fachlichkeit im Code steht.

    Lernziele

    • Du schreibst einen Record mit kompaktem Konstruktor für die Prüfungen.
    • Du benennst, was der Compiler für einen Record erzeugt.
    • Du erkennst, wo das erzeugte toString schadet, und schreibst es dort selbst.
    • Du begründest, warum eine Klasse mit Identität und veränderlichem Zustand kein Record wird.

    Definition of Done

    • Das Modul neuerungen/syntax/records baut mit Release 17, und WertklassenTest ist unverändert grün.
    • Position, Kunde und Kreditkarte sind Records; Bestellung ist eine Klasse geblieben.
    • Du hast die Kontrollfragen beantwortet

    Mit Java 8 schreibt man eine Wertklasse mit vier Feldern in siebzig Zeilen: Konstruktor, Getter, equals, hashCode, toString. Fachlich ist davon kaum etwas. Sieh Dir an, was neuere Releases dafür mitbringen, und bau solche Klassen damit um.

    Arbeitsschritte

    Worum es geht

    Ein Record ist ein Datenträger mit festgelegten Komponenten: record Position(String artikelnummer, int menge, …). Konstruktor, Zugriffsmethoden, equals, hashCode und toString erzeugt der Compiler. Records sind seit Java 16 final (JEP 395, nach Previews in 14 und 15) und tragen die LTS-Marke 17.

    Das Release hochstellen

    Öffne im Übungsprojekt das Modul neuerungen/syntax/records. Stell in seiner pom.xml die Property maven.compiler.release an der Stelle mit dem Kommentar „Hier hochstellen.“ von 8 auf 17. Baue das Modul danach:

    Kommandozeile

    Baue das Modul im Wurzelordner des Übungsprojekts und lass seine Tests laufen:

    mvn clean verify -pl neuerungen/syntax/records -am
    IntelliJ

    Starte die Run Configuration syntax-records. Sie baut mit clean.

    Eclipse

    Starte unter Run → Run Configurations… → Maven Build die Konfiguration syntax-records. Sie baut mit clean.

    VS Code

    Starte über Terminal → Run Task… den Task syntax-records. Er baut mit clean.

    Hinweis: Immer mit clean. Ändert sich nur das Release, hält Maven die übersetzten Klassen für aktuell.

    Der Build ist grün: Code im Stil von Java 8 übersetzt auch mit Release 17.

    Die Vorlage umbauen

    Sieh Dir zuerst die Visualisierung Records an: Sie zeigt, was der Compiler für einen Record erzeugt – und was er bewusst weglässt.

    Mach dann aus den Wertklassen im selben Modul Records. Die Stellen sind in der Vorlage mit // Umbauen: markiert. Baue das Modul danach erneut, wie oben: WertklassenTest bleibt unverändert und muss grün bleiben. Wird dabei ein Test rot, lies seine Meldung: Was macht der Record von sich aus anders als die alte Klasse?

    Reflexionsfragen

    • Welche Typen in der Vorlage können zu Records werden, und welche nicht?
    • Ein Record erzeugt equals und hashCode aus all seinen Feldern. Kann zum Beispiel der Record Kunde die logische Gleichheit allein über die Kundennummer umsetzen?
    • Was sind Vorteile und Herausforderungen von Records?
