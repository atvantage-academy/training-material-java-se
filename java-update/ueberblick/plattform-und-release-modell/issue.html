    Das Übungsprojekt kennenlernen

    Als Entwickler:in, die eine Java-8-Anwendung auf ein aktuelles Release heben soll, möchte ich das Übungsprojekt einmal gebaut und durchgesehen haben, damit ich in den folgenden Übungen weiß, wo ich was finde.

    Lernziele

    • Du öffnest das Übungsprojekt in Deiner IDE und baust es mit Maven auf Deinem JDK.
    • Du findest, für welche Java-Version übersetzt wird und wo Du das je Modul änderst.
    • Du ordnest die Ordner des Projekts den Teilen des Kurses zu.
    • Du startest ein Java-Programm direkt aus dem Quelltext, ohne es vorher zu übersetzen.

    Definition of Done

    • Das Übungsprojekt ist in Deiner IDE geöffnet, alle Module sind importiert.
    • Das ganze Projekt ist einmal gebaut; Du weißt, welche Module dabei rote Tests haben und warum das so gewollt ist.
    • Du hast die Stelle gefunden, an der ein Übungsmodul sein Release festlegt.
    • Du hast spielwiese/Versionsinfo.java ohne javac gestartet und seine Ausgabe gelesen.
    • Du hast die Kontrollfragen beantwortet

    Alle Übungen dieses Kurses arbeiten am selben Übungsprojekt: einer Bestellabwicklung, wie sie mit Java 8 geschrieben wurde, und je Übung einem eigenen kleinen Modul. Bevor Du etwas daran änderst, holst Du es Dir, baust es einmal und siehst Dich darin um.

    Arbeitsschritte

    Das Projekt holen und öffnen

    Klone das Übungsprojekt (siehe Ressourcen) und bleib auf dem Branch main. Öffne es in Deiner IDE:

    Kommandozeile

    Klone das Projekt und wechsle in seinen Wurzelordner:

    git clone https://github.com/atvantage-academy/code-template-java-se-java-update.git && cd code-template-java-se-java-update
    IntelliJ

    Öffne die pom.xml im Wurzelordner über File → Open und wähle Open as Project. IntelliJ importiert alle Module und findet die Run Configurations des Projekts von selbst.

    Eclipse

    Importiere das Projekt über File → Import → Existing Maven Projects und wähle den Wurzelordner. Lass alle Projekte ausgewählt, auch das Wurzelprojekt java-update – dort liegen die Run Configurations.

    Alles einmal bauen

    Baue das ganze Projekt und lass alle Tests laufen. Brich dabei nicht beim ersten Testfehler ab:

    Kommandozeile

    Baue im Wurzelordner des Übungsprojekts:

    mvn clean verify -fae -Dmaven.test.failure.ignore=true
    IntelliJ

    Wähle oben rechts in der Auswahl neben dem Startknopf die Run Configuration java-update und starte sie.

    Eclipse

    Öffne Run → Run Configurations… und starte unter Maven Build die Konfiguration java-update.

    Der Build läuft durch – aber in einigen Modulen sind Tests rot. Welche Module sind das? Sieh in der Ausgabe nach den Zeilen mit FAILURE oder ERROR.

    Hinweis: Die roten Tests sind Absicht. Das Projekt ist für Java 8 geschrieben, und einige Module verhalten sich auf einem neuen JDK anders. Um genau diese Stellen geht es in den Übungen zu den Inkompatibilitäten.

    Den Aufbau sichten

    Sieh Dir die Ordner im Wurzelverzeichnis an und ordne sie zu:

    Ordner Inhalt
    altbestand/ die Bestellabwicklung auf Java 8 – Domäne, REST-Schnittstelle, Batch-Import
    ueberblick/ Werkzeuge, die vor dem Umstieg zeigen, was bricht
    inkompatibilitaeten/ je Stelle, an der der Umstieg bricht, ein Modul – unter bauzeit/ und laufzeit/
    neuerungen/ je Neuerung ein Modul – unter syntax/ und api/
    spielwiese/ einzelne Programme zum Ausprobieren, ohne Build

    Öffne die pom.xml im Wurzelordner und such die Property maven.compiler.release. Für welche Java-Version wird übersetzt? Öffne dann die pom.xml eines Moduls unter neuerungen/syntax/ oder inkompatibilitaeten/laufzeit/: Dort steht dieselbe Property noch einmal, mit dem Kommentar „Hier hochstellen.“ An dieser Stelle stellst Du in den Übungen das Release eines einzelnen Moduls um.

    Ein Programm ohne Übersetzen starten

    Seit Java 11 startet java ein Programm auch direkt aus einer Quelldatei: Es übersetzt sie im Speicher und führt sie aus, ohne dass Du vorher javac aufrufst (JEP 330).

    Starte im Wurzelordner das Programm Versionsinfo:

    java spielwiese/Versionsinfo.java

    Lies die Ausgabe: Auf welchem Java läuft das Programm, und von welchem Hersteller stammt Dein JDK? Öffne dann spielwiese/Versionsinfo.java, ändere eine der Ausgaben und starte das Programm noch einmal. Wo ist die übersetzte Klasse geblieben?

    Hinweis: In der IDE startest Du dasselbe Programm einfach über den Startknopf neben der main-Methode. Der Unterschied zeigt sich nur auf der Kommandozeile: Dort brauchst Du weder javac noch einen Ausgabeordner.

    Reflexionsfragen

    • Der Altbestand ist mit Deinem JDK gebaut und seine Tests sind grün. Ist er damit auf Java 21?
    • Das Projekt wird für Java 8 übersetzt. Was würde passieren, wenn diese Klassen auf einem Server mit Java 8 liefen – und verhalten sie sich auf Deinem JDK genauso wie dort?
    • Wofür ist java Datei.java im Alltag nützlich, und wofür nimmst Du weiter Maven?
